# Product

## Register

product

## Users

SigrikaGo serves logged-in players who want a readable, responsive strategy-game flow across lobby, matchmaking, live rooms, replay, social, shop, warehouse, profile, and announcement surfaces. It also serves administrators who maintain game content, users, characters, shop items, system settings, mailbox, announcements, and operational views from a dense admin console.

## Product Purpose

SigrikaGo is an authenticated online board-game app built around 13-line Go-inspired play, character skills, real-time rooms, spectators, replays, progression, commerce, and admin operations. Success means players can understand the current game state and act quickly without UI ambiguity, while admins can manage live content safely without disturbing the player experience.

## Brand Personality

Playful, tactical, and precise. The player UI should feel like a Bright School notebook world with anime character energy, but the product controls should remain familiar, dependable, and task-focused.

## Anti-references

Avoid generic dark sci-fi HUD styling bleeding into the Bright School theme, marketing-page hero layouts inside app surfaces, decorative motion that does not communicate state, overbuilt card stacks, vague AI-tool aesthetics, unreadable low-contrast paper tints, mobile overflow, and modal flows that replace context when a separate detail window is expected.

## Design Principles

- Make game state legible before making it decorative.
- Preserve the Bright School paper-and-campus identity without inventing nonstandard controls.
- Keep desktop and mobile workflows equivalent, with mobile receiving explicit layout treatment instead of being a later shrink pass.
- Use semantic feedback for loading, errors, unread state, disabled state, selected state, and dangerous actions.
- Keep admin surfaces quieter and denser than player surfaces so content operations stay efficient.

## Accessibility & Inclusion

Target WCAG AA contrast for text and controls. Keep keyboard focus visible, respect reduced-motion preferences, preserve 44px minimum mobile touch targets where practical, avoid color-only state communication, and prevent horizontal overflow on phone and narrow tablet layouts.
