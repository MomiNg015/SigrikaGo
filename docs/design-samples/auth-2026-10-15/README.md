# 登录 / 注册界面审查与三套样板

预览：开发服务启动时打开 `/docs/design-samples/auth-2026-10-15/index.html`。

## 审查结论

- 保留原手绘角色、纸张背景、深棕描边与粉色主操作，它们已经建立了明确的围棋部身份。
- 现有登录／注册页签、输入框、提交按钮均有较强描边，视觉重量接近。建议降低次级控件重量，让主操作更突出。
- 当前英文标识及版本号使用装饰字体，实际画面中字符辨识偏弱。样板使用清楚的英文标识，将版本号降到表单末尾。
- 当前注册规则与字段名同排，小屏会压缩字段标题。样板将简短规则置于输入框下方，并与错误反馈使用同一位置；不增加额外说明段落。
- 已有密码显隐、逐字段校验、提交锁和会话冲突确认应保留。本轮只审查和探索视觉，不改变认证服务。

## 方案

| 方案 | 设计重点 | 取舍 |
| --- | --- | --- |
| 1 社团签到纸（推荐） | 保留角色探出纸面的关系，纸面干净，页签与主操作拉开重量 | 最接近现有界面，变化较克制 |
| 2 左右迎新页 | 原角色完整放大，桌面左右分区，手机转为插画页眉 | 桌面更宽，角色存在感更强 |
| 3 入部登记册 | 页角角色、目录页签与横线输入，纸页装订感 | 表单感更强，角色更小 |

## 实现边界

独立 React 样板；只导入正式 AuthScreen 的校验和文案函数，不挂载正式认证组件，不调用 API，不写账号或会话缓存。提交仅等待 900ms 后展示本地演示提示。使用原始 `/assets/login-sigrika-mascot.webp`，不重绘、不拉伸或替换手绘图。Vite 开发服务用于 JSX 转换，不能直接以 file URL 打开。

## 验证

- 三版在 1440px 桌面及 390/320px 手机宽度共九组注册布局中，页面 scrollWidth 与 clientWidth 相等，图片加载成功；短屏可滚动到提交按钮。
- 检查登录／注册切换、用户名保留与密码清空、空表单错误和首个错误焦点、密码显隐、提交时禁用及本地完成反馈。
- 修正窄屏 Grid 的固有最小宽度导致的溢出，以及 register 模式类名与方案样式的冲突。
- 使用项目维护文件的 ESLint 配置通过 stdin 检查样板 JSX；默认 ESLint 不扫描该 docs 目录。
- `npm test -- src/auth/AuthScreen.test.js`：17 项通过。最初直接调用 Vitest 扫到了临时旧副本，改用项目 npm test 的既有排除规则后通过。
- `npm run docs:system-design` 已生成入口 HTML；生产源码和认证接口未修改。

## 设计检测器复核

检测器提示的圆角／颜色取值是本次三方向探索中的局部纸张、中性线条和状态色，不作为全站 token 变更。ClubTitle 是项目现有 LXGWMarkerGothic 字体的样板别名，不是新增字体资源。粗下边线是角色下方的独立分隔线，并非卡片侧边强调；控制栏重复间距用于同级切换按钮，表单本身具有字段、区块和主操作间距层次。因此这些提示在该隔离样板中属有意设计或上下文误报，未添加任何检测豁免。正式接入时需收敛为项目的语义 token 和样式所有者。
