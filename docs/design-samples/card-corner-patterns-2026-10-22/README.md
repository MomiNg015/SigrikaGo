[打开交互比较页](./index.html) · [三版总览](./overview.png)

本轮审查以玩家端各类内容卡片的组件与最终样式为依据。履历与详细信息做了实际浏览器对照，其它窗口属于源码与设计适用性审查，不代表逐窗口视觉回归。正式界面未替换，样板直接加载当前 `ResumeModal` / `UserProfileCard` 和完整主题。

## 设计判断

纯色本身可以保留；当前重复感来自大面积同色纸面配相似的边框、圆角和阴影。给大卡片一处有方向的角部构图，比给所有表面平铺纹理更适合现有外层方格纸。项目的暖纸、棕墨、浅蓝、薄荷和 Q 版角色继续承担主视觉。

以下图形是基于「星炬学院围棋部」语境的原创抽象设计，不是官方院徽或设定符号：

| 方案 | 角部构成 | 适合场景 | 取舍 |
| --- | --- | --- | --- |
| A 星轨切片 | 大圆弧、不同间距轨道、少量星点 | 履历、身份、人物资料 | 最轻柔，与校园纸面兼容；辨识度较含蓄 |
| B 光束折面 | 有限的斜切色面、错位轮廓、小菱形 | 仓库详情、成就、重点资料 | 更醒目、更有方向感；密集列表中不宜重复 |
| C 棋阵坐标 | 裁切菱框、局部棋盘交点、两颗抽象棋子 | 战绩、挑战、记录摘要 | 与玩法关联直接；大面积使用会偏工具感 |

推荐先以 A 作为普通资料卡默认方向。若采用混合系统，也应按内容用途选择，避免同一窗口每张卡都换一套语言。

## 卡片体系审查

| 内容族 | 当前证据 / 样式所有者 | 建议 |
| --- | --- | --- |
| 履历与用户详情身份卡 | `ProfileResumeView.jsx`、`profile-paper-cards.css`、`profile-dossier/card-surfaces.css`：大面积实色身份区 | 首批适用；右上放一处大图形，姓名和头像区域保持清楚 |
| 段位、战绩、挑战卡 | 同一组件中的 `.profile-summary-item`、`.profile-record-card` 与 `ProfilePlayRecords.jsx` | 中小纹理；段位右下、战绩右上，保留星级、胜负语义色和回放控件 |
| 角色战绩列表 | `.profile-character-section`、原生表格行 | 只装饰整个容器一角；每条记录不重复叠图，避免与角色色和表格数字竞争 |
| 手册角色详情 | `mobile-adaptive/handbook-detail-cards.css`：技能标题已有声痕，简介已有黑白棋装饰，派生技能叠卡 | 已有专属符号，应保留；若扩展新纹理，只选无符号的长正文尾角，不能压过声痕或重复图案 |
| 好友 | `friends-companion.css`、`friends-companion-feedback.css`：名单纸卡、独立伙伴操作区 | 优先伙伴详情的大留白；名单中选中态比装饰重要，不给每个人重复大图 |
| 仓库 | `warehouse-field-guide-detail.css`：详情纸卡与物品圆形底台 | 详情尾角可用 B；圆形底台已有结构，不再叠第二套中心图案 |
| 观战 | `watch-ledger-paper.css`：每行纸卡，已结束状态灰底 | 小角标量级即可；灰色结束状态继续优先，不将纹理当状态编码 |
| 排行榜 | `leaderboard-podium-winners.css`、`leaderboard-podium.css`：领奖台色块、下方密集名单 | 只考虑前三名领奖台的大留白；普通名单不加纹理 |
| 成就与个性化 | `achievement-modal.css`：解锁与未解锁背景、徽章陈列 | 分组或说明卡角部可用；已有徽章图案与解锁状态要优先 |
| 公告、邮箱 | `announcement/detail.css`、`mailbox/detail.css` / `list.css`：阅读面板、状态消息、附件操作 | 长文内容尾角弱化使用；表单、消息状态与附件操作不装饰 |
| 设置、反馈 | `settings-panels.css` 与 `MessageBoardModal.jsx`：已有方格纸设置区、输入区 | 设置继续保留外层纸面；输入框与滑块不加角部纹理 |
| 商店、角色选卡、对局、演出 | 商店专用窗口与商品美术、选角印章、对局状态和演出各有独立语义 | 不通过通配卡片选择器批量覆盖；后续按专属美术评估 |
| 后台 | `admin/shell-layout.css`：白底工作面板和状态色 | 管理工作区保留安静、密集的内容呈现，不纳入学院纹理主题 |

审查结论是分层应用，而非所有纯色表面都添加图案。近期结果条、表格单元格、按钮、输入框和徽章背板在本样板中均保留原样。

## 样板实现

- `orbit.svg`、`facets.svg`、`coordinate.svg` 是有限几何构图；`*-lower.svg` 为垂直翻转的下角版本。没有 SVG pattern、平铺或动态效果。
- `corners.css` 仅指定自定义变量与背景绘制属性；`background-repeat: no-repeat`，不改边框、阴影、文字、尺寸、间距、定位和滚动。
- 桌面身份卡背景画布 360×240，手机 240×160；段位 150×100；战绩桌面 180×120、手机 150×100；表格容器 170×113，手机 150×100。SVG 自带透明留白，实际图形仅占画布右侧。
- 上方九张卡片是跨尺寸视觉研究，下方 iframe 是当前真实窗口；两者明确区分。
- 样板内复制独立本地 fixture，账号接口在页面内模拟，未知账号接口也在本地失败；不写账号数据，不导入此前未提交的配色样板。
- 原版对照、纹理开关、本人／他人、正常／空战绩／长名字、桌面／390／320px 均可切换。原有回放打开本地空列表，成就等不可用状态沿用当前正式组件。

## 运行与验证

运行 `npm run dev:client -- --host 127.0.0.1`，访问 `/docs/design-samples/card-corner-patterns-2026-10-22/index.html`。它依赖 Vite 解析 JSX，不能直接以 file URL 打开真实组件预览。

- 18 组：3 纹理 × 本人／他人 × 1440×1000、390×844、320×568。
- 与原版逐项比较身份卡、摘要卡、结果条、角色区域、战绩字段及玩法按钮的边界和文本，完全一致。
- 6 组 320px 空战绩／长名字检查，末条角色记录可滚动到达，页面无横向溢出。
- 纹理计算样式均为单次绘制；关闭纹理和原版对照有效。
- 检查方案、窗口、尺寸切换，吃子挑战、回放开关、关闭后重开；无浏览器运行时错误。
- 样板 JS/JSX 按项目规则 lint 通过。此次只新增设计样板，未重复运行无关的全项目业务测试。
- [机器可读验证记录](./verification.json)。截图文件名为 `方案-self/social-desktop/mobile.png`。
