# 履历与详细资料 · 按参考图重新设计

2026-10-19。此目录是用户否定第一轮后，直接依据用户提供的两张截图重做的三个交互样板。正式窗口尚未替换。

打开[三版比较页](./index.html)，可切换方案、桌面、390px 手机和 320px 窄屏；“对照原图”展开用户提供的两张截图。各版也可独立打开：[方舟档案](./arknights.html)、[终末地名片](./endfield.html)、[融合档案](./hybrid.html)。使用项目 Vite 开发服务器访问，不能以 file:// 直接打开 ES module。

## 参考图里的构图和材质

本轮直接视觉依据是 [明日方舟参考图](./references/arknights.png) 与 [终末地参考图](./references/endfield.png)。两张图片由用户提供，仅用于本地方案对照。第一轮查阅的 [PRTS 个人名片目录](https://prts.wiki/w/个人名片一览)、[终末地名片实机资料](https://gamewith.net/akendfield/72406) 为补充背景；本轮以用户截图为准，不用网页或项目默认主题替换其要求。

**第一张图的核心是“大立绘与右侧资料墙”。** 人物从画面上沿贯穿到底，元信息在左侧叠印，右侧依次出现身份、签名、助战、收藏。大数字与小标签形成明显尺度差，青色只标记少数信息点，黑灰连续底面把不同内容连成一个窗口。黑色模块本身承担分区，不需要暖色卡纸、厚描边或大量阴影。

**第二张图的核心是“横向明暗分界与左右不对称”。** 左侧头像与身份信息较小，进度与收藏数向下展开；右侧浅色成就板、深色角色陈列、窄条记录形成稳定次序。灰色地形浮雕留在背景，黄色短标记和细线负责引导，圆角只用在右侧独立模块。大面积灰白下半部是真正的构图变化，不是给所有卡片换一个浅色。

本轮保留项目自身的角色美术、围棋战绩与玩法结构。资源必须沿用正式项目：通过 `resolveCharacterPortrait` 解析当前 `handbook-chibi-sprites` 全身图和完整头部 `-avatar.webp`。曾误用仍留在仓库的废弃 `handbook-sprites`，用户指出后已全量替换；参考图只指导构图、尺度层次和材质，不授权回退角色资源。未复制其它游戏的 logo、账号养成字段或品牌文案。成就板的四枚几何徽章为版式占位，弹层使用项目实际成就名牌，并明确是示例陈列。

## 三版的区别

| 方案 | 对参考的对应 | 桌面 | 手机竖屏 |
| --- | --- | --- | --- |
| 方舟档案 | 最接近参考 1 | 左侧近半幅立绘、青色标签和大数字；右侧黑色身份、签名、玩法、角色横排 | 立绘 → 玩家身份 → 签名 → 玩法 → 战绩 → 两列角色记录 |
| 终末地名片 | 最接近参考 2 | 左侧头像、段位与浅色统计；右上浅色成就、右中深色角色、下方最近十盘；保留上深下浅 | 先展示身份和战绩，再展示成就及角色；明暗分界仍可见 |
| 融合档案 | 两张图的构图结合 | 左侧大立绘跨入浅色区，右侧身份、成就、角色依次叠放；战绩留在左下浅色区 | 立绘和身份先出现，成就板衔接浅色战绩区，下接深色角色记录 |

第一版适合强调角色与个人档案；第二版最接近用户终末地截图，也最容易容纳完整履历；第三版同时保留大角色与成就陈列，手机滚动距离更长。三版是可比较的候选方案，最终方向由用户视觉确认。

## 左侧标签选项卡

三版保留现有“星炬／标准／其它”，直接加载生产的 `window-bookmark-shells.css`、`window-bookmark-paper.css`、`window-bookmark-mobile.css`，使用 `WindowBookmarkTabs` 相同的 SVG 路径和 class。保留纸书签轮廓、三种纸色、选中位移与标题字体。桌面横写，手机仍在左侧竖写；没有改成顶部导航。样板用本地 DOM 状态实现点击、Up/Down/Home/End、aria-selected 和 roving tabindex，未修改生产组件。

## 内容、交互与接入边界

- 玩法仍为星炬／标准／其它。星炬下保留常规匹配、吃子挑战赛、队际赛；挑战使用个人最佳与排名，标准及其它不显示角色技能统计。
- 常规统计包括段位、星数、总对局、胜负和、胜率、最近十盘、角色出场与角色详情。队际赛使用独立出场数，不把角色出场相加当作总局数。
- 我的履历提供成就与展示角色选择；他人详情提供点赞、申请好友、黑名单确认、举报表单。回放是列表排版预览，没有播放真实棋谱。
- 用户名、UID、入社日、签名、战绩及徽章均为示例；不请求账号 API，不写账号、持久缓存或社交数据。
- 使用本地人物资源和字体。灰度地形为一次性 Canvas 装饰，没有动画循环；没有新增依赖、生产样式覆盖或路由。
- 手机按自然页面滚动，主内容为单列，四角色改为两列，左侧书签始终占用独立横向空间。后续正式接入时需沿用现有窗口的滚动容器及浮层层级。

### 设计检查的处理

此次深灰、灰白、青色、黄色及几何徽章材质属于用户截图要求的隔离探索，不能为了匹配默认暖纸色盘把它们改回第一轮。检测器对这些颜色及明暗渐变的提示按本轮明确参考分类为有意设计；没有增加规则忽略项或更改 DESIGN.md。黑灰层级、头像裁切与圆角也按参考图使用。

纸书签与主体的材质差异是用户明确要求保留现有标签的结果。三方案 01/02/03 用于反馈定位；数字采用项目已有字体栈中的 Arial，优先保证段位和胜率辨认。装饰微字仅作纹理层，中文主要信息、数字与操作名称独立可读。

实际修复了不必要的 iframe 宽度过渡、未使用的旧粉彩数据、手机玩家身份排列过晚、手机明暗交界穿过数字、狭窄的段位说明触点，以及最重要的废弃角色资源误用。现已直接导入正式资源解析器，完整头部头像使用 contain，全身图按现用 Q 版比例重新布局。正式接入仍需要把选定方案颜色收敛成 theme token，并按真实装备立绘、真实名字和游戏滚动容器再测；这不属于本轮三个独立样板的交付。
