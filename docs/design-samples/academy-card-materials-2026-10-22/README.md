# 学院卡片材质 · 三版跨窗口样板

[打开交互比较页](./index.html) · [三版对照图](./overview.png) · [验证记录](./verification.json)

用户已认可并要求实装功能 C，现已正式接入：[七种功能丝印与正式效果](./screenprint.html) · [实装记录](./production-integration.md)。段位按后续要求左右镜像并放到左下，成就保留右下。下方保留原三版记录。

上一轮星轨、折线、棋阵角纹被用户否定。本轮依据用户指定的《明日方舟》《终末地》视觉方向重做，并把样板扩展到八类真实窗口。比较页中的卡片截图直接裁自正式组件预览；下方可以操作完整窗口。当前仍是独立样板，未替换正式主题。

## 三版取舍

| 方案 | 图形和材质 | 适合的位置 | 需要控制的地方 |
| --- | --- | --- | --- |
| A 学院徽印 | 现有星炬学院图形超大裁切，配一块低对比实心斜面 | 身份卡、好友详情、档案容器 | 徽记是身份信息，大卡更合适；小卡仅露出一部分 |
| B 工业浮雕 | 原创透明材质图，哑光浅灰与暖白的实体切面 | 仓库说明、人物资料、较大的正文卡 | 体积感最强；正文区降低对比，小卡缩小尺寸 |
| C 战术丝印 | 宽斜面、局部有限网点和少量实心短块 | 观战、记录、名单和说明卡 | 更平面、更利落；网点只聚集在角部，不能铺满 |

三版都采用单次背景绘制。A 的图形来自项目已有 `public/assets/factions/startorch.webp`；B 为此次生成的原创素材，见[提示词与来源](./generation-prompt.md)；C 为有限 SVG 几何构图，没有 SVG pattern 或平铺渐变。没有复制参考游戏的标志。

## 已呈现的八类窗口

每一种材质都可以切换到以下八类窗口。大面板与小卡片使用不同尺寸；同一窗口中保留原有浅绿选中态、灰色结束态及角色专色。

| 窗口 | 实际组件 / 背景目标 | 构图处理 |
| --- | --- | --- |
| 我的履历 | `ResumeModal`；身份、摘要、挑战与角色记录容器 | 身份右侧大裁切；摘要与挑战小角纹；表格只装饰外层 |
| 他人详情 | `UserProfileCard`；相同资料卡族 | 保留右下社交操作，背景从边缘退入 |
| 好友 | `FriendsModal`；`.fc-person`、`.fc-detail` | 名单小角纹，伙伴操作区较大；保留左侧书签 |
| 仓库 | `WarehouseModal`；`.wg-entry`、`.wg-inspector` | 小物品卡与大详情有明显尺度差；物品圆形展示台保留 |
| 观战 | `WatchModal`；`.wl-row::before` | 每场对局右下小构图；结束状态继续灰底 |
| 角色详情 | `CharacterDetailDialog`；技能正文和简介 | 背景收在正文尾角，保留现有声痕、棋子装饰、立绘和角色徽记 |
| 成就 | `AchievementModal`；成就内容行 | 紧凑尾角；状态、徽章和奖励优先 |
| 公告 | `AnnouncementModal`；列表与阅读详情 | 列表更轻，阅读区尾角较大；正文可正常滚动 |

## 全项目卡片审查的其余处理

前轮[源码审查表](../card-corner-patterns-2026-10-22/README.md#卡片体系审查)仍可用于定位各卡片所有者，前轮图形方案已经作废。本轮新增上述八类实际浏览器预览；以下是应用建议，尚未制作逐窗预览：

- 排行榜：A 可用于前三名领奖台的大留白；密集排名行维持纯色，避免数字与图形竞争。
- 邮箱：沿用公告的阅读区尾角策略；附件、消息状态和领取操作保持清楚。
- 个性化：A 用于说明容器；已有名牌、称号、徽章展示区不叠加相同徽记。
- 设置、反馈：只有说明卡适合轻量 C；表单、滑块及输入面不增加底纹。
- 商店、招募、角色选卡：已有商品或角色专属美术，需按各自构图决定留白中的纹理，不采用全局卡片通配覆盖。
- 对局与演出、后台：此次不改变这些独立视觉体系。

## 参考与视觉边界

直接参考是项目保存的用户截图：[明日方舟](../profile-reference-v2-2026-10-19/references/arknights.png)、[终末地](../profile-reference-v2-2026-10-19/references/endfield.png)。本轮提取的是大尺度裁切、块面层次、哑光材质与局部印刷感。官方来源：[明日方舟官网](https://ak.hypergryph.com/)、[终末地官网](https://endfield.gryphline.com/zh-tw)。

所有产品预览继续加载现有完整主题、字体、边框、阴影和布局。比较页外壳的灰绿配色，以及 B 的中性材质色，是用户指定参考方向下的独立探索；不写入生产 `DESIGN.md` 或共享主题。`studio.css` 的 Campus 字体别名仍指向项目现有霞鹜漫黑文件，不是新增字体。设计检查中的外壳色盘偏离和字体别名提示据此归类为明确的样板差异。

## 实现和运行

- `sample.jsx` 直接导入八类生产组件；角色资料复用已提交的部员手册公开快照。
- `materials.css` 只覆盖明确白名单的背景属性和背景变量，使用 `no-repeat`；桌面大卡约 360–460px，小卡约 140–240px，手机另行缩小。页面根标记覆盖 portal 渲染的角色详情，正式页面没有该标记。
- `fixtures.js` 在页面内模拟所有 `/api/` 请求；未知接口在本地返回 501。选择、示例道具操作及社交操作不会连接真实账号或持久保存。其它静态资源按原路径加载。
- 长内容状态覆盖名字、道具说明、观战名字、技能正文、成就说明与公告正文；空数据覆盖列表和战绩，角色详情保持当前选中的角色。
- 运行 `npm run dev:client -- --host 127.0.0.1`，访问 `/docs/design-samples/academy-card-materials-2026-10-22/index.html`。真实组件依赖 Vite，不能直接以 file URL 打开。

## 验证

- 24 组桌面预览：3 材质 × 8 窗口，1440×1000。
- 48 组手机预览：3 材质 × 8 窗口 × 390×844 / 320×568，无页面横向溢出、图片加载失败或运行时错误。
- 48 组原版几何对照：1440 / 320px，三版八窗口目标卡片的矩形位置、宽高一致。这不代表逐像素截图相同。
- B 方案在 320px 检查八窗口的空数据 / 长内容，共 16 组，无横向溢出。
- 已操作好友选择、仓库选择、观战搜索、履历挑战模式、成就筛选、公告切换与手机返回；比较页方案、窗口、原版、尺寸及数据切换有效。
- 12 张真实卡片裁图组成对照板；保存桌面和手机截图并检查视觉结果。样板 JS/JSX/MJS 的项目 lint 通过；系统设计入口同步并重新生成 HTML。

此次未建立新的生产组件契约。接入时需要根据用户选定方向保留明确的窗口白名单，并重新验证实际主题、状态和资源加载。
