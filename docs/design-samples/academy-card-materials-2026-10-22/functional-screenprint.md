# C 方案深化：按卡片功能分配纹理

[打开功能丝印样板](./screenprint.html) · [七类总览](./roles-overview.png) · [浏览器验证](./roles-verification.json)

用户认可 C 的实心几何与局部网点，但要求增加样式并按卡片功能分配。本轮保留这一视觉语言，设计七个有限构图；采用固定的功能映射，不按数组序号随机换图。仍是独立设计样板，未接入正式界面。

| 功能 | 纹理 | 已分配到的实际卡片 | 角落与尺度 |
| --- | --- | --- | --- |
| 身份 | 档案切角 | 履历、他人详情的身份卡 | 右上；桌面 390px，手机 260px |
| 记录 | 棋局矩阵 | 升降级战绩、吃子挑战、最近十盘、角色战绩容器 | 左下；140–280px，表格只装饰外容器 |
| 社交 | 交叠联结 | 好友名单、伙伴详情 | 右侧偏下；名单 160px，详情桌面 430px / 手机 270px |
| 物品 | 封装折带 | 仓库列表、物品详情 | 右下；保留用户选中 C 的原图，列表 160px，详情 420px / 270px |
| 战术 | 对向楔阵 | 观战对局、角色普通技能与派生技能正文 | 右下；170–250px，手机 155–200px |
| 阅读 | 页角印层 | 角色简介、公告列表与阅读正文 | 右下；150–350px，图形对比比其它功能更轻 |
| 荣誉 | 授章菱片 | 段位卡、成就内容行 | 右下；160–170px，印章不表示已解锁或实时进度 |

因此，一张履历同时出现身份、荣誉与记录三种纹理；角色详情的技能正文和简介使用不同构图。同功能的名单条目继续保持一致，通过大小与留白区分列表和详情。网点只存在于角部有限区域，所有背景均为 `no-repeat`，不添加细线轨道或全卡铺底。

## 实现边界

- `build-role-motifs.mjs` 生成七个 `role-*.svg`，其中物品纹理直接复制原 `screenprint.svg`，保留已认可的图形。
- `screenprint-roles.css` 在样板根标记 `data-material="screenprint-roles"` 下按明确语义类分配图案，只改背景；Portal 中的角色详情共用文档根标记。
- 继续复用八个正式窗口和现有本地 fixture。旧 A/B/C 保持原样，新增入口可以切换功能分配、原 C 同纹与纯色原版。
- 保留状态色、学院徽记、技能标题声痕、简介棋子装饰、现有字体和操作。没有新增依赖、生产组件或账号写入。
- 检查工具提示的 `role-studio.css` 灰绿色字面值及既有 `harness.css` 底色，是前轮比较页外壳的沿用色，不进入生产主题；属本地设计展示上下文的有意差异，未加入全局忽略规则。正文与说明使用深色，装饰图形使用低透明度。

## 验证

- 八窗口 × 1440×1000 / 390×844 / 320×568，共 24 组。目标卡片的矩形与文字和纯色原版逐项一致；计算样式确认每个目标都拿到相应 `role-*.svg`，且为单次绘制。
- 页面无横向溢出、图片加载错误及运行时异常。保存 8 张桌面、8 张手机截图及 3 张真实履历裁图，查看了履历、好友与角色详情的视觉结果。
- 320px 下验证八窗口的正常、空数据和长内容；空 / 长状态共 16 组，角色详情空状态保持当前选择。
- 六项比较页控制通过：纹理跳转、原 C 对照、纯色对照、窗口说明联动、320px 预览与长内容切换。比较页在 390 / 320px 无页面横向溢出。
- 新增及修改的 JS / JSX / MJS 按项目规则 lint 通过，系统设计入口重新生成 HTML。此次不改变生产行为，未新增复制实现的单元测试。

当前未建立新的生产样式契约。确认接入时应把这张语义映射表作为白名单，并继续按真实卡片尺寸控制留白。
