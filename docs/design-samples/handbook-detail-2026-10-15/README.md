# 部员手册：角色详情与衣柜三版样板

入口：[交互比较页](./index.html)。通过项目 Vite 服务访问，不能双击文件离线运行。

推荐先看 **2 · 立绘展台**。三版均包含角色详情与衣柜，支持达妮娅、西格莉卡、桌面、390px 与 320px 竖屏；也提供现有正式组件的独立窗口对照。

## 现状审查

依据：`src/modals/house/HouseNestedDialogs.jsx`、`src/modals/house/CharacterCostumeDialog.jsx`、`src/styles/modals/character-opening/costume-wardrobe*.css`、`src/styles/mobile-adaptive/handbook-detail-figure.css`，以及本目录 `current-*.png` 的实际组件截图。

1. **详情页缺少清晰的阅读分组。** 姓名、CV 和音乐播放器共用标题行；技能、获得途径与可点击对白紧接排列。短技能时尚可，长说明和派生技会增加同一区域的阅读负担。建议固定身份层，把技能、声音与人物信息分出层级；保留当前完整立绘和正文独立滚动的优点。
2. **衣柜入口不够直观。** 目前是立绘角落的衣服图标，读屏标签完整，但视觉上没有“衣柜”文字。样板加入文字入口或书签，减少首次使用时的猜测。
3. **看详情与换装分散。** 卡片主体打开服装详情；独立的小衣服按钮直接换装。查看介绍之后还需回到列表操作。建议选中即在原窗口预览，介绍、画师署名和确认按钮与试穿状态保持一致。
4. **状态主要依赖颜色。** 当前穿戴外框变绿，未拥有服装变灰；按钮都是衣服图标。样板同时用文字、选中边框和图标说明“正在穿戴 / 已拥有 / 未拥有”，未拥有仍可看原色大图，但确认按钮禁用。
5. **未来服装增多时需要控制层级。** 当前链路是角色详情、衣柜、服装详情三个独立浮层。样板将服装预览内嵌，减少关闭与返回步骤；手机保留底部确认，滚动只发生在内容区。

以上为设计判断，不把样板对照环境中的叠层行为推断为线上故障。现有窗口对照分别挂载正式组件以观察外观，不复刻整个 App 的窗口堆栈。

## 三版取舍

| 方案 | 详情 | 衣柜 | 适合与代价 |
| --- | --- | --- | --- |
| 1 夹页档案 | 左人物、右技能与人物信息；电脑一眼读全 | 同一窗口切页，选服装后集中确认 | 阅读和操作均衡，接近现有结构；立绘表现力较克制 |
| 2 立绘展台 | 宽幅角色舞台、右侧窄纸页；手机上下重排 | 放大试穿图、右侧缩略图与固定确认 | 最能体现现有 Q 版立绘与换装差异；长技能会更早滚动 |
| 3 随身手账 | 技能、人物、衣柜三枚章节书签 | 服装小卡像相册，介绍接在下方 | 手机内容分组清楚；读完资料需要多一次切换，立绘更小 |

推荐 **2** 作为角色收藏与换装的方向。如果优先考虑技能查阅，选 **1**；如果后续人物资料会明显扩充，选 **3**。

## 边界与素材

- 仅本目录新增样板与文档，不替换正式窗口、不变更后端或账号。
- `catalog.json` 是从已提交 `server/adminDefaultSnapshot.js` 提取的达妮娅、西格莉卡和对应服装。默认装扮由正式 `orderCostumeCards` / `defaultCostumeCard` 生成，默认立绘仍经手册解析器选用新版 Q 版。
- `PortraitShowcase` 沿用可见像素边界，卡片使用共同展示比例，人物保持完整。新增服装艺术素材数量为零。
- 两名角色均假定已拥有；默认装扮与第一套额外服装为已拥有示例，达妮娅第三套展示锁定状态。换装只修改 React 状态，刷新恢复。比较页始终标注示例数据。
- 语音与音乐仅在点击后播放项目本地文件，暂停/关闭清理。样板音乐为默认曲目的循环段试听；不实现多曲目选择或持久化。正式组件对照保留原播放器。
- 技能正文、特性释义与派生技解析复用正式组件/函数。释义目录预先用本地默认数据初始化，避免访问账号或后台接口。
- 手机以竖屏为主；书签可用左右键、Home、End 切换。窗口复用 `ModalDialog` 的键盘约束；Escape 在衣柜返回详情，再次 Escape 关闭。

## 视觉规范检查

- 修正字体别名，使用设计系统的 `Sigrika Window Title`，实际资源为项目 LXGWMarkerGothic 字体。
- 纸色、正文墨色、弱化墨色及主确认的校园粉对齐 `DESIGN.md`。三版的差别来自布局、阅读分组和图像占比。
- 检查器报告的其余纸面中间色、细线、半透明背景及非标准圆角，是独立设计样板中的有意材料探索；不是生产主题新增 token。语录细竖线是引用标记，手账左侧厚边是实体书脊，按语境归类为误报，不修改全局检测规则。
- 共享 `skill-description.css` 的提示来自导入的既有样式，本次没有编辑该文件。

## 验证

运行：`node docs/design-samples/handbook-detail-2026-10-15/verify.mjs`，需项目开发服务在 5173，浏览器使用本机 Edge。

- 三方案 × 两角色 × 三尺寸（1440×900 / 390×844 / 320×568），共 18 组详情及衣柜流程。
- 检查图片、文档及内容区横向溢出、确认按钮可达；试穿、换装、已穿戴禁用、未拥有禁用、返回后立绘同步。
- 检查技能特性释义位置、章节切换、Escape、Tab、关闭/重新打开与比较页切换。
- 检查真实本地音频的播放、暂停、关闭停止；无账户 API 请求。
- 使用项目现有 ESLint 规则显式检查样板（普通 lint 的维护文件清单不包含设计样板）。
- 浏览器结果保存于 `verification.json`；截图覆盖三版详情与衣柜的电脑、手机，以及现有组件对照。
