# 好友窗口：审查与三版样例

日期：2026-10-22。初始范围为好友／黑名单窗口的视觉审查和三版比较。用户随后选择第三版，要求保留现有左侧标签，并增加符合主界面风格的硬阴影、悬停和按下反馈，现已接入正式窗口。下文原始三版保留为历史比较，比较页「现有窗口」表示本轮改造前的组件基准。

正式实现保留原接口及真实关系操作：桌面左右分栏，手机名单在上、操作在下；好友／黑名单仍为原左侧书签。名单卡片使用 3px／4px 硬阴影，细指针悬停轻抬，按下下沉；禁用按钮静止，减少动态效果时取消过渡。完整实现契约见 `.trellis/spec/frontend/friends-companion-contract.md`。

正式效果：[桌面](./production-1440x900.png) · [390px 手机](./production-390x844.png) · [320px 手机](./production-320x740.png)。浏览器回归：`npx playwright test --config tests/e2e/window-surfaces.config.js friends-companion.spec.js`。

正式实现验证：7 项浏览器回归通过；全量 ESLint、立绘及可视边界检查、构建、产物 CSS 契约和部署配置检查通过。全量单测初次为 3308 通过／3 失败：系统设计 HTML 重新生成后，其 4 项测试通过；开发代理启动用例受默认 5 秒上限影响，独立复测仍有 1 项超时，将本次运行上限设为 15 秒后 4 项全通过，未修改测试默认配置。`check:admin-snapshot` 仍报告本地 `siteSettings`、`characters` 与已提交默认快照不同，本任务未导出或覆盖后台配置。因此不能将本次 `npm run check` 记录为整体通过。

## 审查结论

现有窗口的校园纸张、标题贴纸、Q 版角色已经有辨识度，应保留。最值得调整的是信息组织与重复装饰的重量。

| 现象 | 当前依据 | 改进方向 |
| --- | --- | --- |
| 状态、头像、名字、齿轮横向分成四列，身份信息被拆开 | `src/modals/friends/FriendsList.jsx`；`src/styles/commerce/social-profile/friends-list-status.css` | 把头像、名字、状态作为一个阅读组，让名字成为视觉重点 |
| 每行粗边框、硬阴影与齿轮按钮共同争夺注意力 | 当前组件预览及完整主题实际渲染 | 主窗口保留纸张轮廓，名单改细分隔线或减轻名片边框 |
| 手机头像只有 32px，左侧书签又占用横向空间 | `src/styles/themes/bright-school/mobile/lists-settings/friends-rows.css`；窗口书签规则 | 移动端改内置横向标签，头像提高到 42–68px，长用户名允许换行 |
| 资料与对局入口藏在齿轮中，展开后与解除好友并列 | `FriendActionPanel` | 常用操作提前，解除操作放在次级位置，并保留确认 |

这是设计判断，未作真人可用性测试。`current-*.png` 来自本次当前组件渲染，使用相同虚构数据，不是线上用户截图。

## 三个方向

| 方案 | 核心变化 | 优势 | 代价 |
| --- | --- | --- | --- |
| 清爽名册 | 单列名单、细分隔线、姓名下方显示状态、对局直接可见 | 扫读快，桌面手机一致，接入成本相对低 | 角色展示较克制 |
| 社团名片 | 桌面两列、手机单列；大头像、独立操作栏 | 角色存在感更强，身份和操作边界清楚 | 手机每屏显示的好友更少 |
| 伙伴侧栏 | 桌面名单＋固定伙伴操作区；手机改为名单＋底部操作区 | 选中对象明确，大角色形象更有游戏感 | 多一步选择，移动端操作区占用名单高度 |

建议以清爽名册作为日常使用的基础；若希望更突出游戏角色，可选社团名片。伙伴侧栏适合特别看重选中好友展示的方向。

## 交互与边界

- 用户名、关系和状态都是明确标注的示例。所有操作仅修改当前页面内存；刷新或重置恢复，不请求 `/api/`。
- 搜索仍是全局用户名查找，不悄悄改成好友名单筛选。可尝试「小满」「晚风」「长离」，长离不在初始好友名单中。
- 在线可申请对局；离线、对局中使用真实 disabled 按钮。对局选项直接读取现有 `modeOrderedEntries()`。
- 资料入口为局部演示对话框；正式接入时继续使用现有 `UserProfileCard`，不替换履历、铭牌、徽章、称号和资料规则。
- 黑名单、解除取消／确认、空状态、关闭／重开、更多操作可交互。原生 dialog 处理焦点限制、Esc 关闭与焦点恢复。
- 三版默认字号、粗细、线条和色彩均限于独立样例；没有把新样例样式导入生产入口。
