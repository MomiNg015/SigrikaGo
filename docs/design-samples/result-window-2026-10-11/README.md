## 已选方案 1：正式接入

正式组件入口为 `production.html`，它加载完整项目主题与 `ResultModal`，并使用真实的 `useOverlayActions` 验证关窗和回大厅。选择方案 1 后已移除用户名、垂直居中人物、同排放置返回棋盘与退出房间，并显示实际升降星／段／九段积分。特殊决战保持原继续行为。

`verify-production.mjs` 检查 24 组正式组件状态（4 个视口 × 胜负 × 星／段／积分），中心误差不超过 1px，两个按钮同排且高度至少 44px，无越界；同时检查两种导航区别。显式 ESLint、184 项相关测试、构建和构建 CSS 检查通过。全局 CSS inventory 仍存在本轮前的 822 字节超额及 `match-mode-title-layout.css` 的 360px 断点未登记；本轮预算仅增加自己的 4817 字节，不吸收其他工作。设计钩子在 styleContract 测试中报告的色值是未修改的旧断言，不是新增界面色值。

通过运行中的 Vite 打开 `/docs/design-samples/result-window-2026-10-11/index.html`。顶部可切换方案、角色、胜负、玩法与手机竖屏；窗口按钮关闭预览结果，可重新打开。数据均为本地示例。

## 现状审查

- `ResultModal.jsx` 在立绘下额外展示 `UserIdentity`，增加不必要的身份信息。
- Bright School 的 `result-room-popovers.css` 强制 50vw × 40vh，窗口尺寸跟随视口而不是内容，立绘却限制在 152px。
- 同一主题规则设置 `overflow: hidden`，限制人物和天气向窗外展示；手机又有后置规则覆盖，正式接入需同时处理双方的所有者样式。
- 样板拆开纸面与立绘，不把 overflow、固定高度和小立绘限制带入新布局。保留结果、胜负原因、段位、金币、玩法说明和返回操作。

## 复用与边界

直接使用生产 `ResultCharacterPortrait` 和 `resultCharacterPortraits`，胜利跳动来自生产 `result-modal.css`，乌云使用原 `result-defeat-rain.gif`。减少动态效果时呈现静态云。九名默认表情角色可切换，未复制图片或新增人物资源。

这是供选择的独立样板，尚未改动生产 `ResultModal`。音效、账号、奖励结算、队员揭示和特殊对决均不连接真实业务；队际、挑战、陪练用于检查不同内容量，不能据此认为完整业务已接入。

## 验证

运行 `node docs/design-samples/result-window-2026-10-11/verify.mjs`，需要本机 Chrome 和 5173 端口 Vite。

- 36 个组合：3 个方向 × 胜／负／和 × 1440×900、390×844、360×640、320×568。
- 检查立绘、天气、窗口、操作按钮位于视口内，无横向溢出，图片加载成功；分别检查跳动和静态状态。
- 每个组合执行关闭、重开、Escape；额外检查四种玩法在最短竖屏的按钮边界。
- 检查方案、角色、结果、手机预览、重新展示，以及减少动态效果。
- 使用项目 ESLint 配置显式覆盖本目录 JSX（默认维护列表不自动包含新样板）；检查通过。
- `verification.json` 记录 36 个组合及错误结果；desktop/mobile PNG 为三套胜负截图。未运行整个项目的后端与全量测试，因为这轮没有更改生产行为。
