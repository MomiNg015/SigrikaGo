# 履历／详细资料：三个设计方向

## 打开样板

在仓库根目录运行 `py -3 -m http.server 5196 --bind 127.0.0.1`，访问 [对比入口](http://127.0.0.1:5196/docs/design-samples/profile-directions-2026-10-10/index.html)。也可直接打开本目录的 HTML 文件；图片、字体、脚本均来自本地，无外部 CDN。

| 方向 | 主要变化 | 适用与代价 |
| --- | --- | --- |
| [社团档案夹](./folder.html) | 独立身份纸页、文件夹模式标签、右侧连贯战绩表 | 最贴近校园档案气质；手机身份区较高 |
| [对弈成绩单](./scoresheet.html) | 顶部紧凑身份、段位和五项战绩并列、表格连续对齐 | 查战绩最快、内容密度适中；角色展示较克制 |
| [部员收藏册](./collection.html) | 完整 Q 版立绘、总览／角色战绩分叶、角色记录行卡 | 角色氛围最强，手机易分段阅读；查看角色战绩需要多一次切换 |

顶部可切换本人／他人及桌面竖屏预览，底部可预览空战绩、加载中、加载失败、长用户名、九段积分。数字键 1/2/3 切换方案，分类和玩法按钮支持方向键，子窗口支持 Escape。三套使用相同且内部一致的虚构数据。

## 分类与统计口径修正

初版错误地沿用旧履历的“星炬／标准／五子棋”三个平级标签，漏查了当前首页玩法、结算和回放的完整链路。用户指出后，三套统一改为：

- **星炬对弈**：常规匹配、吃子挑战赛、队际赛。
- **标准对弈**：常规匹配。
- **玩些别的**：五子棋。

常规匹配展示升降级战绩、段位、最近十盘和角色记录；回放列表区分升降级／友谊对局。吃子挑战展示最高提子、当前排名和最佳成绩使用角色。队际赛展示对局结果、手数、双方出场阵容和回放入口，不展示段位或个人胜率。准时宝陪练不持久化普通战绩，因此没有编造陪练历史。

现有资料接口只汇总 rated:true 的模式记录，不能直接提供完整新窗口。队际赛可使用现有 mode=team 回放查询；常规星炬回放当前混合了队际赛，要拆分必须在服务器分页前筛选。吃子挑战摘要需明确接入已有挑战数据。这里展示的是正确口径的设计方案，尚未修改正式接口。

成就、个性化和回放演示其入口及上下层关系，不重做这些独立系统。点赞、好友、举报、黑名单仅更新页面内演示状态，不发请求。刷新恢复样板数据。

## 项目审查结论

初轮完成的是项目结构与界面规范抽查，不能称为完整项目审查。修订时补充核对 HomeScreen 的完整分类、social.js 统计查询、roomResultPersistence 结算分支、captureChallenge 成绩存储及 replayPagination 筛选边界；并未逐行审计全仓库。详细证据见 [review.md](../../../.trellis/tasks/10-10-profile-three-design-directions/research/review.md)。

1. **界面可拓展性**：已有 `ProfileResumeView` 统一本人和他人记录区域；后续应在此共享层接入布局，避免两份展示逐渐分叉。Bright School 的纸面、深棕墨线、标题贴纸和 Q 版资产是统一基础。
2. **功能可拓展性**：身份操作与模式战绩是两组不同责任。样板保留现有字段，独立容纳本人管理与他人关系操作，没有臆造赛季、战力、排名或成长曲线。
3. **使用流畅性**：主要改进是操作显性化、危险操作降级、数字对齐以及手机的自然纵向阅读。三个方向分别让用户比较校园感、查阅效率和角色表现。
4. **对局与数据稳定性边界**：重设计不应修改资料缓存、竞态防护、模式切换保留旧数据、回放权限或角色外观解析。本轮均以无请求的独立样板验证，不据此声称正式对局稳定性通过。

正式接入还应覆盖装备铭牌／成就称号组合、主题变体、真实关系权限、服装及特殊效果、回放权限和模式请求竞态；这轮样板没有替代这些生产验证。

## 验证

执行 `node docs/design-samples/profile-directions-2026-10-10/verify.mjs`（需要本地 5196 服务），使用项目已有 Playwright 和本机 Chrome。

- 三套设计 × 本人／他人 × 1440、390、360 宽度，共18组。
- 每组覆盖五个玩法入口；断言挑战／队际赛不出现段位、个人胜率和角色胜场，并验证对应空状态、排名／回放入口、出场阵容。另检查字体和图片解码、横向溢出、长姓名、角色列表末行可达、点赞去重、好友状态、举报校验、改名、重试、加载、九段积分、关闭重开及键盘切换。
- 截图关闭瞬时动画再采样，避免捕获淡入中间帧。结果记录在 `verification.json`。
- 独立 JS 与检查脚本通过 scoped ESLint；更新系统设计入口并生成 HTML。未运行全项目测试，本轮不修改正式源码。

## 设计检查反馈

比较控件中的 01/02/03 是与快捷键对应的三个样板编号，不是产品窗口内新增的装饰标题，保留。墨线框配轻圆角是 DESIGN.md 的纸面窗体合同；选中分叶的底线是状态指示，不是装饰性卡片边条。浅灰棕纸材、网格、分隔线及胜负底色是局部纸张／语义色调，属于本轮明确的材质探索，不写入共享主题。未添加任何钩子忽略配置。
