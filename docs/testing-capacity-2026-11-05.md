# 2026-11-05 本机容量压测

## 结论

当前可作为本机参考的已通过组合是 **500 人在线、50 盘普通围棋同时对局**：100 名对局玩家、100 名观战者、300 名闲置用户，连续 3 分钟完成 2,950 次真实落子及 100 次重连，客户端和持久化均零错误。落子 ACK p95 12.01ms / p99 16.67ms，服务 RSS 峰值 468.71 MiB，事件循环 p95 峰值 35.75ms，最终持久化待写房间为 0。

2 核 2GB 正式部署可先以 **300 人在线、最多 50 盘**作为保守规划起点，给真实 API 操作、技能、系统和网络留余量；这是规划建议，不是已经测出的云主机上限。500 在线 / 50 盘是本机短测通过档位，100 盘因持久化错误不通过；1,000 纯在线虽维持成功，但事件循环略超门槛。此次没有测出绝对最大容量，也没有修改生产配置。

公网带宽需单独核对：本次是回环网络，没有大批图片/音声下载；实时房间快照随历史增长，不能从 CPU/RAM 指标直接推导低带宽云主机人数。技能对局、服务端人机、数据库已有大量历史记录和数小时持续运行也需要另测。

## 测试范围与环境

目标是给 2 核 2GB 部署提供参考，区分在线连接与同时对局。测试基于 `8fb8420d` 工作区的服务代码；已有未提交改动保留。本次只修改压测工具与文档，没有调整游戏服务、生产容量阈值或数据库模型。

主机是 Windows、AMD Ryzen 9 7945HX、32 逻辑处理器、约 15.18 GiB 物理内存、Node v24.15.0。服务限制在逻辑 CPU 24/26，发压端在 CPU 28/30，两者均为 below-normal 优先级；MuMu 进程不做任何设置变更。服务 Job Object committed-memory 硬上限为 1536 MiB，预留约 512 MiB 作为 2GB 部署中系统及其它进程的预算假设。系统可用物理内存低于 1024 MiB 时，监控只终止本次服务及其子进程。

**这不是完整的 2GB Linux 云主机模拟。** Job Object 限制的是 committed memory；Windows 本身、页缓存和发压端仍使用主机其它资源，磁盘和网络均为本机条件。具体语义见 [Microsoft Job Object 内存文档](https://learn.microsoft.com/en-us/windows/win32/api/winnt/ns-winnt-jobobject_extended_limit_information)。云主机 CPU 型号、共享算力、Linux、磁盘、Nginx/HTTPS、带宽和真实网络会改变结果。

每轮使用随机端口、独立临时 SQLite 和容量测试账号，停止服务后才清理数据库。没有访问开发或生产数据库；远程智子 AI 禁用。复用现有 `dist`，前端渲染性能与大量图片/音声下载不在此次服务压测范围内。

## 方法

- 实际建立认证 WebSocket，每个账号对应一个连接。
- 使用普通围棋 `standard` 模式，通过真实匹配、预加载确认和开局进入 playing。双方轮流发送合法 `game:action` 落子；复用游戏规则在发压端选择合法点，服务器仍按正式流程校验、广播、保存房间。
- 除最小诊断档外，各盘错开落子；每盘的间隔见结果表。每轮主动重连 20% 连接，包含玩家、观战者和闲置用户；记录错误与恢复延迟。
- 账号注册属于准备阶段。常规在线容量轮使用并发 1，且准备后重启隔离服务再连接，避免 bcrypt 注册开销污染整个进程生命周期的事件循环直方图。它不等同于负载中的服务重启恢复。
- 通过线为落子 ACK p95 < 200ms、p99 < 500ms、事件循环 p95 < 50ms、服务 RSS < 1.2GiB、无动作/重连/持久化错误，并核对服务端最终在线与房间数。纯在线测试不适用落子延迟门槛。
- 这是短时参考测试。没有覆盖所有角色技能、服务端 GNU Go 人机、长时间反复结算/奖励、数据库大规模历史数据、所有人同时登录、完整资源冷启动或数小时内存泄漏。

## 结果

以下时长是账号与房间准备后的负载阶段，不含准备耗时。RSS 为服务进程采样峰值，不含发压端；单位 MiB。原始报告存于 `artifacts/capacity/2026-11-05/`。

落子间隔是配置目标，发压端等待应答、重连和指标采样会降低实际吞吐；100 盘档实测 8,700 / 300 = 29 次落子/秒，每盘约 87 手，不能按配置写成完成了 10,000 手。

| --- | --- | ---: | ---: | ---: | ---: | --- |
| 20 / 5 / 5 | 30 秒 / 3 秒（同时动作） | 50 | 45.52ms | 196.89 | 38.83ms | 通过 |
| 100 / 20 / 40 | 60 秒 / 7.5 秒 | 160 | 11.39ms | 297.27 | 111.87ms | 未通过，含账号准备耗时 |
| 200 / 50 / 100 | 90 秒 / 7.5 秒 | 600 | 11.03ms | 404.00 | 31.44ms | 通过 |
| 500 / 100 / 200 | 300 秒 / 3 秒 | 8,700 | 12.90ms | 632.89 | 33.51ms | 未通过，23 次持久化错误 |
| 1,000 / 0 / 0 | 60 秒 / 不适用 | 0 | 不适用 | 267.70 | 51.28ms | 未通过，略超 50ms 观察线 |
| 500 / 50 / 100 | 180 秒 / 3 秒 | 2,950 | 12.01ms | 468.71 | 35.75ms | 通过 |

500 人 / 100 盘的动作 ACK p99 为 21.98ms，100 次重连 p95 为 2.15 秒，全部客户端动作与重连成功。但房间持久化计数在正式动作开始前已有 13 次错误，负载阶段增加 10 次，累计 23 次；因此不能宣称 100 盘可靠通过。按房间串行的持久化队列允许不同房间并发写 SQLite，是后续调查入口，当前未取得这一轮具体数据库错误码，不能将推测当成已定位根因。

1,000 纯在线账号维持成功，服务端最终计数确为 1,000，200 次重连 p95 为 236.09ms，零客户端错误、零持久化错误；其 51.28ms 事件循环峰值略超门槛，报告仍判失败，未放宽门槛。它代表已建立连接的维持能力，不代表同时注册、加载资源或发起对局的容量。

已确认的额外问题：100 账号、并发 8 的注册准备出现 SQLite `P1008` 查询超时（尚未进入对局负载）。串行注册成功。100 人/20 房未分离准备阶段的一轮落子 p95 为 11.39ms、零错误，但累计事件循环 p95 峰值 111.87ms 导致整轮不通过；同轮末尾已降至 25.41ms。保留失败，不将它改写成成功。

所有完成轮次的 Windows 限额监控均未触发系统内存停止线，记录到的最小系统可用内存为 1112.67 MiB；100 盘轮服务 Job committed-memory 峰值为 841.92 MiB，低于 1536 MiB 上限。MuMu 的三项可读取核心进程 PID、正常优先级和全 CPU 亲和性在测试前后保持一致，检查时均仍在响应。未修改模拟器设置，也没有测量其内部帧率，不能由进程状态推断帧率完全不变。

## 复跑

Windows 本机先确认指定逻辑 CPU 存在且系统内存有余量。下面仅作用于本次子进程，不能复制 CPU 掩码到处理器数量不同的机器。

```powershell
$env:CAPACITY_WINDOWS_LIMITS='1'
$env:CAPACITY_SERVER_AFFINITY='0x05000000'
$env:CAPACITY_DRIVER_AFFINITY='0x50000000'
$env:CAPACITY_SERVER_MEMORY_MIB='1536'
$env:CAPACITY_MIN_FREE_MIB='1024'
$env:CAPACITY_REPORT_DIR='artifacts/capacity/2026-11-05'
node --max-old-space-size=256 scripts/verify-capacity.mjs --profile target --sockets 500 --rooms 50 --spectators-per-room 2 --duration 180 --action-interval 3 --action-mode move --registration-concurrency 1 --stagger-actions --restart-after-setup --skip-build --skip-restart
```

`--skip-build` 仅在已有 `dist/index.html` 时使用；本次服务端代码直接从工作区加载。纯在线可用 `--rooms 0 --spectators-per-room 0`。默认动作仍是 `layout` 合成诊断，评估真实落子必须显式传 `--action-mode move`。

目标云需在独立测试实例用相同代码重跑；不要使用正式生产数据库。Linux 无需设置 Windows 限额变量，使用云主机/容器自身资源限制，发压端最好独立部署，并补做带宽、真实登录突发、技能/人机、持久化结算及长时间稳定性验证。
