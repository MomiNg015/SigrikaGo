## 测试发现与修复

封禁账号原先只改变数据库状态，已有 Socket 仍在线，可继续经过不刷新认证的房间入口。现改为封禁和审计事务提交后立即断开该账号全部连接；失败/输入无效不踢出。新增真实连接测试及路由事务回归。

原 E2E 前端沿用开发 Vite 代理，可能访问 3001 而测试后台运行在另一端口。现为测试专用代理，统一 API、上传、WebSocket 到隔离后端，默认 5317/3317 并严格占用指定端口。缓存、上传、数据库、限流命名空间和构建输出也已隔离。陪练 ready 等待 API 初始化，统一子进程失败和清理顺序。

静态 fixture 显式禁用开发代理；API 启动前探测端口占用，数据库清理拒绝活跃 API PID。Vite 测试进程单独启用 CI 模式，禁用其默认 stdin EOF 退出行为，并用真实进程验证标准输入关闭后仍可访问。

若干旧浏览器断言仍依据已拆分 CSS、历史书签/按钮或网格立绘。按现行合同修正测试并保留尺寸、状态、图片、灰显、保密、滚动和实际业务断言；没有为满足旧测试更改现行界面设计。

全应用复跑发现新糖果测试忽略达妮娅 35% 拒绝且不消耗的规则。消耗验证改用固定接受的西格莉卡，并核对接受结果、效果与库存；达妮娅接受/拒绝仍由注入随机值的单元测试覆盖。没有修改产品概率。

## 异常与开发数据库风险

旧稳定性入口默认命令曾因 3001 已占用而退出。它允许继承开发 PORT/DATABASE_URL，且服务在检测端口冲突前已执行 schema、seed、历史清理和房间恢复路径。因此这次启动可能触及开发库，不能以启动失败推断无副作用。只读查询确认失败时间段没有新建 fx 前缀测试账号；没有前后数据库快照，无法确认具体初始化数据变化。未回滚真实库或停止开发服务。

现已让稳定性入口仅使用 STABILITY_PORT（默认 4173）、强制新测试库及独立上传/origin、禁用远端，端口预检先于数据库准备和服务初始化。真实进程重启测试改为直接启动 server/index.js、显式复用其自行准备的测试库。

另外保留一次完整应用测试服务中途退出和测试进程 IPC 中断的日志。原提前退出未记录来源，无法确认是否是 stdin EOF；完整应用随后 27/27 通过。已补退出码/信号诊断及 stdin EOF 保护，不能将未知来源写成已定位的产品缺陷。
