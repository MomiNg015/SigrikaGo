# 资源、音频与启动预加载

本文记录图片、音乐、音效、语音、WebP 资产、启动预加载和资源扩展约束。新增角色资源、音乐语音、特效素材、预加载策略或资源路径时优先更新本分篇。

## 当前结论

- 运行期图片优先引用 WebP；PNG/JPG/GIF 多作为源素材或兼容文件保留。

Frontend and backend should read titles, rule copy, board size, komi, skill enablement, time controls, mode family, and mode ordering from `src/shared/gameModes.js` instead of hard-coding mode facts.

These PNGs are stable runtime resources but are not part of the startup preload manifests.
- Matchmaking, friend duels, room snapshots, persisted rooms, replay records, watch lists, leaderboards, and profile/history surfaces carry a `mode` field. Match queues are isolated by mode, lobby stats expose per-mode waiting counts, friend duel requests include the requested mode, and old/missing record modes normalize to `spark` for legacy data.
- No-skill room UI keeps player cosmetics such as selected character portraits and stone decorations, but directly removes skill gameplay affordances: no action-bar skill button, no player skill chips, no skill name display, no removal/overclock counters, and no overclock terms in scoring breakdowns. Gomoku also hides pass/counting/dead-stone controls plus capture/removal/overclock chips, and the rules layer rejects pass, active skill, and passive-skill execution in gomoku mode.
- Room board coordinates and action validation are size-aware. The backend validates move/scoring `pointId` values against the active room game's `size`, and the board coordinate labels use the same `--size` grid as the rendered intersections so 13-line and 19-line boards stay aligned.
- Spark skill presentation uses a hybrid board renderer: `Board` keeps the React DOM/SVG grid, buttons, coordinates, stones, scoring marks, and click handling as the source of interaction truth, while `BoardSkillEffects` mounts a `pointer-events: none` PixiJS canvas overlay for character skill animations and `BoardAmbientEffects` renders ongoing passive ambience. Skill-enabled boards schedule an idle `pixi.js` prewarm through `src/room/pixiPrewarm.js`, and the eventual skill animation reuses the same module promise; strict CSP builds load `pixi.js/unsafe-eval` before `pixi.js` so the renderer can initialize without runtime eval failures, and standard no-skill boards skip this prewarm. When a pending Pixi board effect is present, `BoardSkillEffects` starts Pixi app initialization and blocking Pixi-drawn sprite asset loading during the banner window, then mounts the transparent `.board-effects-canvas` and exposes the playable runtime only after both `app.init()` and those blocking `Assets.load()` calls have completed. This keeps PixiJS v8 image sprites on the cache-backed path expected by `Sprite.from()` and avoids a visible blank/white frame when a renderer reads a texture before decode; assets used only by resolved DOM markers remain non-blocking preloads. If Pixi init, WebGL, texture loading, renderer dispatch, or ticker callbacks fail, `BoardSkillEffects` catches the failure, marks the layer with `data-effect-failed` / `data-effect-error`, clears sound timers, and cleans up the canvas instead of letting the skill animation blank the page. There is no visible DOM/CSS replacement animation for a failed skill effect; a production-like test must observe a real `.board-effects-canvas` for the skill to pass. Concrete Pixi animation implementations live behind `src/room/boardSkillEffectRegistry.js`, with shared board geometry in `src/room/boardSkillEffectGeometry.js`; registry playback catches renderer errors through an `onError` hook. Cleanup detaches `.board-effects-canvas` from its host before destroying the Pixi/WebGL app, so context teardown cannot paint a frame while the canvas is still composited. Skill preview metadata comes from the already-resolved backend skill action (`effectType`, `targetId`, affected/marked points, removal counts, and `resolvesAt`), so the animation layer never recomputes or changes game rules. The shared `src/shared/skillPresentation.js` presentation contract keeps the 2s skill banner first, then starts the board effect, normalizes per-effect Pixi/DOM layer capabilities, exposes the 180ms cleanup grace, and exposes the global all-effects-off switch used by `BoardSkillEffects` before prewarm, overlay rendering, and SFX scheduling; reduced-motion users receive a short static hit effect. Full-motion effects are staged as anticipation, impact, and afterglow/residue phases so visual polish stays in the presentation layer without changing board state timing. Aemeath `hidden-hand` uses a 1500ms full-board Pixi circuit-board takeover: a green electronic flow ignites at board center without a center green circle, travels outward along the board's horizontal and vertical grid lines with sparse diagonal circuit links, briefly draws only a light circuit outline membrane without a dark full-board fill, then dissolves uniformly without focusing the hidden target. Its procedural SFX uses a low startup tone, high electronic data stream, and short takeover pulse through the existing `sfx` channel. Sigrika `erase-point` keeps the resolved invalid intersection as a point-local DOM marker using transparent WebP `/assets/effects/sigrika-erased-field-marker.webp`, and the pending meteor cast reuses that point-local marker with a delayed impact reveal while the Pixi impact crater uses a dark-gray core during impact and then fades out before cleanup, so no opaque crater is hard-cut at the tail and no full-board gray fallback is used. ChangLi `double-move` uses transparent SVG `/assets/effects/changli-fire-phoenix.svg` and `/assets/effects/changli-flame-sprite.svg` sprites for a red phoenix fly-in plus an irregular-edged full-board fire cast phase, Lynae `spray-stone` sends every transformed point through pending `affectedPointIds`; the Pixi spray cast paints the selected target and resolved random target together, the original stones stay visible while an internal borderless cyan/purple/pink/yellow irregular `.spray-transform-pending` spray-paint cover blooms above them, then switch visually to `/assets/stones/spray-stone.webp` only after that cover has stayed opaque through most of the post-banner effect window, and generated spray neutral stones use the same WebP as their only stone artwork, without a CSS/SVG fallback stone, plus a point-bound colorful underside glow. Pending spray stones reuse the final `spray` offset while the paint cover hides the original stone, preventing a visible snap when resolution swaps the stone type. Nabomo `color-illusion-passive` uses a pointer-transparent CSS center-out activation wave plus a `.board-wrap.color-illusion-board-surface::before` texture reveal into `/assets/boards/nabomo-color-illusion-board.webp`, resolves at the 2s banner end so the gray/white board transition starts without a post-banner gap, then keeps that board background for the duration of the active passive; it intentionally avoids persistent Pixi smoke/ticker ambience and clipped rectangular fog edges on desktop and mobile. Board skill SFX are scheduled from the same frontend timeline through `src/room/boardSkillEffectSoundScheduler.js` and the existing `sfx` audio channel; they are cleaned up with the overlay and are suppressed for reduced-motion board effects.
- 仇远的 `row-slash` 技能使用 `/assets/characters/portraits/qiuyuan.webp` 作为内置立绘；棋盘技能演出不依赖独立刀光纹理，而是通过 `BoardSkillEffects` 注册一个 full-board Pixi Graphics cast：技能横幅结束后先在棋盘内依次扫过两道竖向贯穿预兆刀光：第一道自上向下斜竖砍落，第二道自下向上竖劈，角度在 -30 到 30 度间确定性随机，扫完后留存到主刀收势并一起淡出；随后从目标行左侧聚出青白墨锋，并用约 1.8 格高度的主刀光从左到右刷过整行。预兆和主刀光去掉浅蓝透明厚波纹，保留白色直刃线，直刃边缘使用低透明青白渐变光效增厚，并通过 Pixi Graphics 多段深青墨、灰蓝墨、飞白短划制造水墨涂抹边缘。前端点位通过 `row-slash-cut-pending` 和 `--row-slash-cut-delay` 让该行棋子在主刀扫到时快速消失；`BoardRowSlashOverlay` 仍然负责持久 `.board-row-slash`，但 pending casting 刀痕会按 `boardEffectDurationMs * 0.19` 延迟和 `* 0.22` 时长与 Pixi 主刀同步从左向右裁切展开，并通过轻微下移起点让刀痕中点贴合目标行中线。结算后的持久棋盘标记保存在 `game.rowEffects`，会同步给观战、回放和实时客户端，并通过 `clearAfterColor` 在对手下一次行动（普通落子、弃手或消耗回合技能）后清除。
- 莫宁的 `protocol-takeover` 技能使用 `/assets/characters/portraits/mornye.webp` 作为内置立绘。技能横幅后先通过 Pixi 播放淡紫与冰蓝数据流光束从棋盘上方向目标点落下的目标点演出；结算后的协议禁入标记直接渲染为棋盘点按钮内的 `.protocol-ban-mark` DOM/CSS 子层，保持 `pointer-events: none`，以便该标记对双方、观战和回放可见，同时不改变落子、触控确认、数子标记或技能目标命中。
- Chisa `liberty-purge` uses `/assets/characters/portraits/chisa.webp` as its builtin portrait. After the 2s skill banner, `Board` first displays the pending placement on `targetId` with the player's selected stone decoration, a delayed drop-in, and the same `liberty-purge-stone` eerie red glow used by surviving resolved placements. The targeted `BoardSkillEffects` Pixi canvas then reads the already-resolved `removalMarkIds` and draws several saturated red scissor slashes in sequence over those removal points only, excluding the newly placed target stone even though `affectedPointIds` still carries both the target and removals for metadata consumers. `skillBoardEffectDurationMs()` extends the board-effect window from `removalMarkIds.length`, so the server keeps `resolvesAt` open until every removal slash has had time to play; the slashes fade out and the real result appears without an extra post-effect gap. Resolved removal history still renders through `.liberty-purge-removal-mark` red crosses as pointer-transparent point children independent from protocol bans, blast residue, scoring marks, and dead-stone marks.
- Development GIF previews for role skill animations are generated by `scripts/export-skill-gifs.mjs` through `npm run export:skill-gifs`. The script starts a local Vite capture harness, renders the existing `BoardSkillEffects` Pixi path over the current `.board-wrap` board texture for canvas effect-only captures and the full `Board` path for DOM/CSS effects such as `row-slash`, captures frames with Playwright virtual time, then uses ffmpeg to encode looping GIFs in `outputs/skill-gifs/<character-or-effect>/`. The harness lets the real effect path finish Pixi/canvas preparation before the cast starts, then advances the browser clock by one frame for each screenshot so capture I/O cost does not make the encoded GIF play faster than the in-room animation. Board-context Voyage Star captures also flip their mock `Board` to the resolved crater/removal state after `bannerDurationMs + 52%` of the board-effect window, while the active Pixi cover continues running above it, so exported GIFs can verify that the crater is revealed by dissolve instead of popping in. This workflow is intentionally local and muted; GIFs are preview artifacts and are not registered in runtime preload manifests.
- Generated preview outputs, including `outputs/skill-gifs/`, Playwright screenshots, contact sheets, and `.codex-dev*.log`, are ignored local artifacts rather than source assets. ## Music Display Name Management

- Current effective preload contract: login preload blocks home entry only on the selected character portrait, home-shell images, interaction audio, and currently reachable home BGM. Other owned character portraits, shop/recruitment/inventory/equipment/decorations, battle/skill tracks, result sounds, and character voices remain in the same manifest but load in the bounded background queue after home entry. Unpurchased music products still do not preload full audio. Battle preload is scoped to the current room and current user's music selections: it loads both player portraits, only the selected battle track, one resolved track per relevant base/derived skill slot, required voice candidates, and mode-specific effect images. No-skill modes such as `standard` and `gomoku` skip skill BGM, skill voices, and skill effect images. A refreshed or reconnected player that resumes a room still in `GAME_PHASES.preloading` must return to the battle preload route and emit `room:preload-ready` after local assets finish, instead of entering active room state from that snapshot; this report is retried until the server acknowledges it.
- Client-side playable-ready prewarm sits before the current effective preload contract. It can warm module/Pixi caches while the user is on the home or match-selection surfaces, but the app still shows `match-preloading` and waits for the same room-scoped battle asset manifest plus server ready acknowledgements before exposing the interactive room.
- Current effective cache contract: production gives hashed Vite build outputs `Cache-Control: public, max-age=31536000, immutable`; named `/assets/**` runtime resources and the SPA shell use `no-cache`. Nginx and Express fallback templates share these values, so stable-name WebP/SVG/BGM/voice replacements revalidate through ETag/Last-Modified instead of serving a stale visual for another release window. Hash or version filenames remain recommended for truly immutable high-traffic resources.
- Local stability verification uses `LOCAL_PROD_STATIC=1` to exercise this same cache contract against the production build without setting `NODE_ENV=production`. This keeps local socket/auth/test-action behavior usable while still catching stale-cache regressions before a cloud deploy. `npm run verify:stability` now also covers desktop/mobile room recovery, real Pixi `.board-effects-canvas` playback for Sigrika and Aemeath `hidden-hand` / `voyage-star`, finished-room exit plus reload without reopening the result modal, and opponent reconnect without showing the local player a rate-limit toast.

- `voyage-star` is a full-board Pixi skill effect backed by `/assets/effects/voyage-star-crater.webp`, a transparent WebP converted from the supplied heart/star artwork. `src/room/boardSkillEffectRegistry.js` draws the white/ice-blue knight greatsword, target omen, impact glow, visual-only quake layer, yellow-white soft-edged explosion cover, and removal particles from pending preview geometry while leaving the crater artwork to the resolved board overlay. The greatsword drops from above with a short trail and stays visible through impact; the impact window adds concentric earthquake ellipses, 2-3 decaying shake pulses on the Pixi layer only, and deterministic dust sparks without moving the DOM board or hit areas. The explosion cover layer is added after the other Pixi layers so it can fully mask the impact frame; it expands from the skill center with a solid warm-white core whose radius is at least 2.2 board cells, covering the roughly four-cell crater footprint, then blends outward through low-alpha white and warm-yellow discs whose feathered outer edge fades to zero alpha.
