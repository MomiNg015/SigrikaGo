## 原电脑离开前

每次切换都执行以下流程，可以直接使用文末的“离开前”提示词交给 Codex：

1. 用 `git status --short --branch`、`git worktree list` 核对分支、工作目录及改动，确认本次提交范围，保留其他并行或未知工作。
2. 更新本页最新交接摘要、相关任务和开发日志，同步系统设计并生成 HTML；记录已完成、明确待办、验证和本地数据移交状态。
3. 按改动完成适当检查，将确认过的文件提交到 `master` 并执行 `git push origin master`。若另一台已有新提交，先保护本地工作，再安全解决冲突和完成检查；不使用 `reset --hard`、`clean` 或强制推送。
4. 确认推送成功，再用 `git rev-parse HEAD` 与 `git ls-remote origin refs/heads/master` 核对本地提交和远端分支头一致。其他 worktree 或尚未提交的文件不包含在这次交接中。
5. 如需延续本地数据，停止写入服务后备份数据库和缺失上传资源；只需同步代码时无需每次搬库。浏览器中未保存的剧情／Excel 草稿先保存或导出，选人缓存、草稿和登录状态不会随 Git 迁移。

两台电脑不要同时修改同一份待交接工作；完成旧机推送后，再到另一台开始。

### 本地数据的交接方式

两台电脑各自维护 `.env` 中的本机路径，不把凭据或数据库提交到 Git。需要延续本地账号、后台配置或上传等数据时，确认实际 `DATABASE_URL`、`UPLOAD_DIR` 是否指向项目外，停止旧机写入数据库的开发服务和后台任务后，再备份数据库及所需上传文件。目标电脑也先停服务并备份原库，再恢复这次副本；不直接合并两台独立开发库。上传目录中已提交的文件走 Git，其余需要保留的文件单独迁移。

需要分别处理的内容：

| 内容 | 获取方式 |
| --- | --- |
| 已提交源码、资源、文档、迁移与测试 | 随对应分支 clone / pull |
| `AGENTS.md`、`.trellis/`、`.agents/`、项目 `.codex/` | 已有文件由 Git 跟踪；新增任务及规范仍要实际纳入提交 |
| `.env` | Git 忽略，两台各自维护；首次可私下复制并调整本机路径，文档与提交中不写入其内容 |
| SQLite 开发库 | Git 忽略；当前项目有 `prisma/dev.db`，以实际 `DATABASE_URL` 为准，单独备份复制 |
| 上传目录 | 默认 `public/uploads/`；该目录没有整体忽略，但仅纳入提交的文件会随 Git 获取，剩余资源另行复制 |
| 本机 GNU Go 引擎 | 若安装在项目外，单独复制或安装；核对 `.env` 的 `PRACTICE_ENGINE_PATH`，以及外置引擎依赖是否齐全 |
| `.trellis/.developer`、`.current-task`、`.runtime/` | 属于本机忽略状态；新电脑重新初始化身份并选择需要继续的任务 |
| `node_modules/`、`dist/`、`.tmp/` 等 | 依赖和产物在新电脑重新生成，测试原始日志与截图如需保留则另行备份 |

个人目录中的技能、记忆和美术源文件也不属于项目 Git。需要继续使用时，单独迁移当前用户目录下的 `.codex\skills`、`.agents\skills`、`.codex\memories` 及所需的 `.codex\visualizations` 素材；PowerShell 的 `$env:USERPROFILE` 指向对应用户目录。新电脑用户名不同时放到新用户目录，并检查配置里的旧绝对路径；插件及外部服务连接按新电脑环境重新配置。


如果新电脑已有该仓库，先确认没有需要保留的本地改动，再获取同一分支：

```powershell

git fetch origin
git switch master
git pull --ff-only origin master
```

如有本地改动或分支分歧，先核对并保留，不用 `reset --hard`、`clean` 或覆盖目录来强行同步。

将原电脑的 `.env`、数据库和缺失上传资源放回正确位置，另行迁移或安装项目外 GNU Go，并更新本机引擎路径。公开陪练使用仓库中的浏览器 WASM；本机 GNU Go 仍用于专属决战回退和历史服务端房间。没有旧数据时，依据 [README](../README.md) 和 [部署手册](./deployment.md) 配置新开发环境，不能把新空库误作原电脑数据库的完整副本。

然后安装依赖并启动：

```powershell
npm ci
npm run dev
```

依赖安装和开发服务入口会生成 Prisma Client。复制现有可运行开发库，不因换电脑而无条件执行 `prisma db push`、`prisma migrate resolve` 或重建数据库。若另有版本迁移需求，先备份，核查迁移历史，再按部署手册处理；当前没有名为 `prisma:migrate:deploy` 的 npm 脚本，正式 Prisma 命令是 `npx prisma migrate deploy`，也不能直接用于未经基线核验的所有旧库。

服务启动会运行已有 schema guard 和数据初始化；尚未完成星数迁移的旧库可能在首次启动时迁到三段 2 星，已完成的库通过数据库内回执跳过重跑。因此应在首次启动前保留数据库副本，不能仅以“服务能打开”判断旧数据完全一致。

Trellis 的本地开发者身份若不存在，初始化后读取上下文：

```powershell
py -3 ./.trellis/scripts/init_developer.py Moming
py -3 ./.trellis/scripts/get_context.py
```

仓库里有多项历史 `in_progress` 任务；它们不等于全部都需要立即恢复。由用户指定接续范围，再阅读对应 PRD、最新追加需求和验证记录，不批量启动或归档旧任务。

## 开发约定和验证入口

先阅读 [AGENTS.md](../AGENTS.md)、[Trellis 工作流](../.trellis/workflow.md)、[系统设计入口](./system-design.md)以及对应后端/前端规范。用户最新指令决定本次范围。

- 保护已有未提交工作，修改只围绕当前请求；新建分支、回滚、提交等操作先核对实际 Git 状态。
- 架构、行为、接口、数据模型、资源、主题、部署或技术债变化同步对应设计事实；系统设计入口保持同步，运行 `npm run docs:system-design` 生成 HTML。局部调整不强行扩写无关架构。
