# 星炬人机练习模式

## Goal

实现服务端权威的轻量星炬人机练习模式，对手固定为无技能 NPC「准时宝」，让入门用户可以稳定练习，也让开发者可以沿用正式房间链路验证技能。该模式不依赖大模型、GPU、外部 AI 服务或新数据库模型。

## Requirements

- 仅支持 `spark` 星炬模式，沿用正式的 5 分钟主时限和 30 秒 3 次读秒。
- 在对弈模式弹窗的星炬卡片右下角提供独立的“准时宝对弈”按钮，不能形成嵌套交互元素。
- 开局设置支持 `beginner` / `basic` 两档难度，以及玩家执黑、执白或随机。
- 玩家沿用当前出战角色；准时宝使用稳定资源 ID `zhunshibao`、中性立绘占位和无技能状态。
- 新增 `practice:start` Socket 协议，继续复用 `match:found`、预加载、开局、房间更新、动作 ack、计时、数子、结果和恢复协议。
- 人机房使用 `rated: false`、`matchSource: "practice"`、`recordPolicy: "none"`；不进入匹配队列、匹配人数或公开观战列表，但计入活跃房间容量。
- 准时宝预加载自动 ready；房间运行快照必须保存练习配置并支持刷新、断线与服务重启恢复。
- 决策只能使用准时宝颜色对应的公开棋盘视图，不得读取玩家隐藏手或颜色幻象的真实状态。
- 每回合最多评价 48 个候选点；使用局部吃子、逃叫吃、制造叫吃、连接、气数、位置、自紧气和填眼的一层启发式评分。
- 入门档 25% 从全部合法候选随机选择，否则从评分前 8 名随机；延迟 1.2-1.8 秒。
- 基础档从评分前 3 名随机；延迟 0.6-1.0 秒。
- 无合法落子或终局候选全部是低价值自填时弃手；连续弃手不会自动触发数子。
- 准时宝不根据模糊全局胜率认输。玩家普通提子累计达到阈值时，准时宝在下一次行动前认输：入门 11 子，基础 22 子。
- 认输阈值只读取 `game.captures[humanColor]`，不包含 `skillRemovals`；该练习认输不能被早期无效对局规则改写。
- 玩家申请数子后，准时宝保守判断自己的明显死子；玩家可修正双方死子，准时宝不得覆盖修正，只负责重新确认和接受结果。
- 玩家申请和棋时准时宝延迟同意。
- 技能严格沿用真人房规则；准时宝无技能，因此要求对手先发动技能的前置条件不会被练习模式绕过。
- 结果界面显示“人机练习、不计成长、不保存棋谱”，不展示积分或金币奖励。
- 准时宝不能成为好友、拉黑、资料或其他真人社交操作的目标。

## Acceptance Criteria

- [ ] `practice:start` 严格校验难度与执色，重复开局、容量满或维护排空时返回稳定 ack 错误。
- [ ] 黑、白、随机三种执色均能创建仅含一名真人和准时宝的星炬房间。
- [ ] 准时宝只提交正式规则判定为合法的落子或弃手，候选评价数不超过 48。
- [ ] 固定随机源时两档算法可复现，且入门与基础选择范围符合要求。
- [ ] 隐藏手和颜色幻象场景证明决策器使用准时宝视图而非权威隐藏状态。
- [ ] 普通提子达到 11/22 子时准时宝立即认输；技能除子不触发阈值。
- [ ] 玩家断线时准时宝不继续行动；重连或服务重启恢复后，在轮到准时宝时只调度一次。
- [ ] 数子时准时宝先尝试标记死子，玩家能修正双方标记，修正不会被机器人重新覆盖。
- [ ] 人机房不创建 `GameRecord`，不更新金币、积分、段位、胜负、成就、任务或进度账本。
- [ ] 人机房不出现在匹配计数或观战列表，准时宝没有社交动作。
- [ ] 桌面与竖屏移动端均能无障碍打开入口、选择设置并进入房间。
- [ ] 相关单元、Socket 集成、恢复与稳定性测试通过；`npm run check`、`npm run verify:capacity` 通过。

## Definition of Done

- 服务器房间、决策调度、前端入口、结果/社交边界和恢复路径均实现并有回归测试。
- 系统设计入口及对应前端、实时房间、领域/性能分篇同步更新。
- `npm run docs:system-design` 重新生成 `docs/system-design.html`。
- 不引入数据库迁移、新依赖或外部服务。
- 现有与彩虹移动效果相关的未提交 WIP 保持原样，不进入本功能提交。

## Technical Approach

- 在现有房间工厂/创建生命周期上增加明确的人机房创建路径，而不是复制一套客户端棋局。
- 将准时宝建模为房间内的虚拟玩家：运行时 actor ID 与真人用户隔离，对外暴露 `isBot` 和安全的 bot profile；客户端将其视为在线对手，但房间在线人数和社交系统不把它当真人。
- 新建纯决策模块，接收 bot-view 游戏状态、难度和可注入随机源，输出 `{ type: "move", pointId }` 或 `{ type: "pass" }`。
- 新建房间自动化调度器，在权威状态广播、开局完成、技能演出完成、恢复和重连后幂等检查机器人动作、数子/和棋响应和认输阈值。
- 使用房间计时器注册表管理机器人延迟，关闭、断线和恢复时沿用现有清理机制。
- 人机数子扩展只在 `matchSource === "practice"` 时允许真人修改双方死子；真人房行为保持不变。
- `recordPolicy: "none"` 在结果保存入口短路并标记处理完成；运行快照仍正常持久化以支持恢复。

## Decision (ADR-lite)

**Context**: 客户端教学棋盘已有共享规则复用，但缺少正式计时、完整数子和可靠恢复；技能测试必须代表真实在线房间行为。

**Decision**: 使用服务端权威的人机房，并以受候选数上限保护的一层启发式决策器驱动准时宝。

**Consequences**: 技能、计时、恢复和结果路径与真人房一致；人机房会占用一个活跃房间，但不会增加外部算力依赖。准时宝棋力定位为入门/基础陪练，不承诺复杂死活或全局胜率判断。

## Out of Scope

- 标准 19 路与五子棋人机模式。
- 多个机器人角色、机器人技能或可上传准时宝正式立绘。
- 深层搜索、蒙特卡洛树搜索、神经网络、外部推理服务。
- 人机棋谱、奖励、成就、任务或排行榜统计。
- 人机房公开观战、好友或资料页。
