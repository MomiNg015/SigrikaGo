# 修复新手加载条闪满与观战模式房间数样式

## Goal

修复新手引导加载页在新一轮加载首帧短暂沿用上一轮 100% 进度的问题，并改善桌面端观战模式选项卡中模式标题与房间数徽标的间距和形状。

## Requirements

- 新手引导每次进入加载状态时，第一帧必须从 0% 显示，不得短暂显示上一轮已完成的 100%。
- 保留现有三秒计时进度、加载文案、角色和加载条动效。
- 所有共享加载页都不得显示猪小仙（`baconbits`）的角色立绘或角色专属加载台词；随机角色与显式固定角色路径都必须遵守该排除规则。
- 当加载页收到猪小仙作为固定角色时，改用其他具有立绘的可用角色；角色在对局、图鉴、商店、语音等非加载场景中的行为保持不变。
- 桌面端观战模式选项卡的模式小标题与房间数之间保持明确的 `1em` 间距。
- 房间数背景必须是等宽高的圆形徽标，不得因数字内容或内边距变成椭圆。
- 保留观战模式选项卡现有配色、选中态、字号和移动端布局。

## Acceptance Criteria

- [ ] 同一个 `TutorialBattleScreen` 实例连续触发两次不同 `loading.id` 时，第二次加载的首次渲染进度为 0%。
- [ ] 加载进度仍从 0% 平滑增长到 100%，且不改变现有最短加载时长。
- [ ] 随机加载角色候选中包含猪小仙时，选择结果永远不会返回 `baconbits`。
- [ ] 加载页显式收到猪小仙角色及后台配置的猪小仙加载台词时，最终 HTML 不包含猪小仙名称、立绘地址或该台词，并显示其他可用角色。
- [ ] 桌面端观战模式按钮中标题与房间数的布局间距为 `1em`。
- [ ] 房间数徽标具有相等的宽高和 `border-radius: 50%`，单个数字时视觉为圆形。
- [ ] 相关组件与样式合同测试通过。
- [ ] `npm run docs:system-design` 成功生成最新系统设计 HTML。

## Definition of Done

- 增加或更新针对加载进度重置与观战房间数徽标的回归测试。
- 运行相关测试、构建或项目质量门禁。
- 同步更新 `docs/system-design.md` 与受影响的 UI 分篇事实。

## Technical Approach

- 将教程计时进度状态与当前 `loading.id` 绑定；在新 id 的首次渲染阶段直接返回 0，而不是等待 effect 归零，避免提交旧的 100% 状态。
- 在 `AssetPreloadScreen` 的共享角色选择边界维护加载页排除 ID，并让随机候选与固定角色解析复用同一规则；被排除的固定角色回退到其他安全候选。
- 在观战列表自己的样式 owner 中明确设置按钮内容间距，以及房间数徽标的固定等宽高、无扩张内边距、圆形半径和居中布局。
- 用现有教程组件测试和 `WatchModal` 样式合同测试锁定回归行为。

## Decision (ADR-lite)

**Context**: React effect 在浏览器绘制后才同步新一轮加载状态，导致复用组件时出现旧进度首帧；房间数徽标只设置最小宽度与内边距，无法保证圆形。

**Decision**: 在渲染阶段按加载标识隔离陈旧进度，并在观战局部样式中建立明确的圆形尺寸合同。

**Consequences**: 改动保持局部，不改变共享加载视觉或其他模式选项卡；多位数房间数仍在固定圆形内显示，极端超大数值不在本次范围内。

## Out of Scope

- 重做共享加载条视觉或时长。
- 分别重写普通登录、匹配、路由预加载页面；排除行为统一由共享加载组件负责。
- 删除或禁用猪小仙角色、技能、语音、商店或对局数据。
- 重设计观战弹窗、房间列表或移动端选项卡。
- 为三位及以上房间数设计新的缩写或扩容策略。

## Technical Notes

- 教程加载进度位于 `src/tutorial/TutorialBattleScreen.jsx` 的 `useTimedLoadingProgress`。
- 观战模式结构位于 `src/modals/WatchModal.jsx`，局部样式 owner 为 `src/styles/lobby/watch-list.css`。
- 相关系统设计事实位于 `docs/system-design/06-ui-theme-mobile.md`。
