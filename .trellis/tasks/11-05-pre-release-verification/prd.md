# 上线前综合验证与持久化修复

## Goal
按用户授权完成一轮相对完备、可复跑的本机上线前验收；修复实测暴露的可靠性缺陷，保留失败与修复后的证据，明确云环境/真机/长时间运行的证据边界。

## Requirements
- 优先复现并定位容量档出现的房间持久化错误，最小范围修复并增加真实数据库回归。
- 串行运行代码/资源/构建检查、完整浏览器流程、稳定性/权限/经济并发/对局结算/恢复、迁移和备份恢复。
- 补充分级容量复测、突发/重连/负载下重启和有界较长稳态测试；压力流量应覆盖完整对局生命周期，避免把填满一张棋盘当长稳。
- 每阶段记录命令、代码/环境、结果、失败原因、原始产物路径；可自动复跑，区分真实接口与 mock fixture。
- 不触碰正式或开发数据库。保留已有 WIP。不改生产容量阈值，不执行发布/生产流量操作。
- 保护 MuMu：不更改它的进程、CPU、优先级；仅测试树低优先级/限核，浏览器单 worker，内存不足停止本次测试，不杀其它应用。
- 云服务器/公网带宽、真实手机与 Safari、真实第三方服务不在本机冒充完成。

## Acceptance Criteria
- [ ] 持久化错误复现、根因证据、修复和回归。
- [ ] 可用本机自动门禁执行；失败有修复或明确阻断报告。
- [ ] 压测包含真实动作、数据正确性、重连与重启，记录持续时间和资源保护。
- [ ] 测试报告、系统设计和相关规格同步，生成 HTML。
- [ ] 仅提交本轮与同聊天前置压测的可分离文件，保留其它 WIP。

## Scope Decision
用户直接授权“按建议做套相对完备的测试”，沿用已确认本机验证及 MuMu 保护约束；无需再次确认流程。资源不足时优先保护模拟器，仍完成不依赖额外内存的验证，并如实标记受限环节。
