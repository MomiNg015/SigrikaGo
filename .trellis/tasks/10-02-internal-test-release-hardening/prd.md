# 修复内测发布前八项风险

## Goal
完成 2026-10-02 审查中用户已批准的八项修复，使当前单实例 Node.js + SQLite 项目可以进入云端小规模内测验收。

## Requirements
1. 升级存在安全公告的运行依赖，保留现有功能和依赖主版本兼容性；逐项评估仍需主版本调整的传递依赖。
2. 对局结算以数据库唯一回执保证幂等，成功提交后才公布已保存状态；普通、队际、特殊有效终局在过期恢复时先重试结算。
3. 所有匹配模式与建房入口统一拒绝同账号同时参加进行中对局，并防范异步检查后的竞争。
4. 生产检查及正式更新脚本明确要求 NODE_ENV=production。
5. 启动网络错误保留会话并提供重试，非关键目录可降级；实时连接中断有明确反馈，普通匹配检查连接、处理 ACK 失败和超时。
6. 管理员重置密码复用认证密码规则，在事务内撤销全部会话，并通知/断开在线 Socket。
7. 棋钟保留亚秒余量，正确处理回合、暂停与恢复；GNU Go/KataGo 共用内部子到引擎目的转换。
8. readiness 加入有界数据库健康检测及持续持久化失败信号；正式更新保存完整旧发布目录，停服后补迁移前备份，失败时避免自动启动代码/数据库不一致的版本。

9. 玩家空状态仅显示“暂无＋对应卡片或内容名称”，不加说明或引导；日常代码测试默认单 worker。

## Acceptance Criteria
- 每项问题有针对触发条件的回归测试，包含结算事务失败、提交后重复恢复、过期终局、异步匹配竞争、网络 503、重置后的旧会话、棋钟抖动和部署失败路径。
- npm run check 通过；核对并修复审查时已有的过时测试断言，不通过删除测试或放宽关键合同掩盖问题。
- 隔离数据库迁移、备份恢复、浏览器稳定性、容量 smoke、本地陪练 WASM 验证通过；本地环境障碍与目标云未验证项如实记录。
- 更新 docs/system-design.md 入口及对应分篇，并生成 docs/system-design.html。
- 新增持久化合同同步到 .trellis/spec，代码无非必要视觉/功能扩充。

## Decisions
用户已批准此前明确列出的八项，需求无需再次确认。沿用现有单实例架构、界面风格、模式和奖励规则；扩展已有注入依赖、恢复和会话机制。

## Out of Scope
部署到真实云主机、操作真实生产数据、发布/推送/提交；首页美化、预加载体积重构、办公室 IP 限流、上传大小调整及其余审查建议。

## Technical Notes
审查基线为干净的 codex/battle-paper-panels。原始单元测试 11 失败，多数是旧替身/文本/CSS/换行断言；稳定性 4 失败涉及缓存预期和已 portaled 的页签。Windows 正在运行的服务占用 Prisma DLL，完整验证需协调本地开发服务生命周期，不修改真实用户数据库。

## Additional full-project validation

2026-10-02 用户要求全量测试所有可测试环节。补跑四套专用浏览器配置和真实认证；新增隔离 HTTP/SQLite/Socket 的后台、社交、商城、仓库、邮件、公告、招募、扭蛋、多模式对局/观战/回放烟测。记录实际成功、失败、fixture 覆盖与本机不可验证的云端环节；保持重测试串行单 worker。测试入口端口必须转发到本次隔离服务，不可写入用户开发数据库。
