# 黑化西格莉卡决战观战与全服单局限制

## Goal

让智子云只能稳定支持一盘共享 KataGo 对局的约束成为服务端权威规则：黑化西格莉卡决战允许观战、采用明确的 30 分钟无读秒用时，并且整个服务器任一时刻最多存在一盘未结束的黑化西格莉卡决战；当槽位被占用时，引导其他处于黑化阶段的用户先去观战。

## What I already know

* 用户要求黑化西格莉卡决战可观战。
* 决战双方都采用 30 分钟包干：真人与西格莉卡？各自从 30:00 递减，耗尽立即超时判负；智子每手最多 5 秒的搜索限制保持不变。
* 空闲态点击红色“与西格莉卡？决战”后，必须先显示确认弹窗，文案精确为 `本对局为高难度对局，用时为30分钟包干制，确定参与吗？`；确认后才进入原有创建/预加载流程。
* 整个服务器只能同时进行一盘黑化西格莉卡决战。
* 有别人的决战正在进行时，模式选择窗口内原“与西格莉卡？决战”按钮改为浅黄色背景，文案精确为 `西格莉卡？正在对局中。。。`；点击该按钮直接观战当前唯一特殊房，不再显示原忙碌 toast。
* 黑化主页现有“观战”工具按钮继续锁定；特殊决战不进入通用观战窗口，模式选择窗口的状态按钮是唯一新增观战入口。
* 特殊决战观战资格仅向当前处于黑化篇章（`sigrikaCandyArc.corrupted === true`）的已登录用户开放，普通阶段账号不得发现或直接加入。
* 当前特殊决战由 `server/roomFactory.js` 设置为 `unlimitedTime=true`，双方棋钟都投影为不限时。
* 当前 `server/roomQueries.js` 主动从观战列表排除特殊决战，`server/roomConnectionLifecycle.js` 也禁止非房主加入带 `sigrikaCandyDuel` 的房间。
* 当前黑化主页通过 `HomeStage` 向整个 `HomeUtilityDock` 传递 `disabled=true`；新决定要求保留该整组锁定，不拆出通用观战按钮。
* 当前观战 UI 只有 `spark`、`standard`、`gomoku` 三个模式分页，特殊决战继续不进入这些分页。
* 当前特殊决战已通过 `PersistedRoom` 恢复，服务端拥有房间级权威状态；智子客户端进程内只有一个共享远程会话槽，但决战创建入口尚未把“全服一盘”作为独立准入条件。

## Assumptions (temporary)

* “整个服务器”按当前单实例 Node 服务及其恢复后的 `PersistedRoom` 权威状态解释，不只检查当前智子连接是否繁忙。
* “正在决战”指从特殊房创建成功起，到房间正式结束或按既有房间清理规则作废为止，包含预加载、开场演出和玩家断线等待恢复阶段；这些阶段均允许符合资格的用户进入观战。
* 已经拥有当前特殊房的房主始终可以恢复自己的房间，不会被全服单局限制误拦截。
* 观战者只获得现有安全 `roomView`，不会看到智子凭据、隐藏吻合度审计或服务端内部演出阶段。

## Requirements

* 服务端权威保证任一时刻最多一盘未结束的黑化西格莉卡决战；并发点击也不能创建两间房。
* 房主恢复现有特殊房的优先级高于新建准入判断。
* 服务端向处于黑化篇章的大厅/模式选择界面提供当前特殊决战是否被别人占用的权威状态；窗口保持打开时状态也能收敛更新。
* 特殊房从创建成功起即占用全服槽位并开放专属观战，包括资源预加载、开场演出、正式落子和房主断线等待恢复；结束或按既有规则清理后才释放。
* 没有别人决战时，按钮保持原红色“与西格莉卡？决战”；当前账号拥有未结束特殊房时，保持原红色“继续与西格莉卡？决战”，优先恢复房主身份。
* 有别人的特殊决战时，按钮使用浅黄色背景和精确文案 `西格莉卡？正在对局中。。。`，点击后关闭模式选择窗口并直接进入当前特殊房观战，不打开通用观战窗口，也不经过普通匹配等待弹窗。
* 决战按钮触发的服务端操作必须原子保证全服单局约束，并保留点击时意图，绝不能因权威状态变化自动把“挑战”改成“观战”或把“观战”改成“创建”。
* 点击红色挑战按钮后若被别人抢先，服务端不创建第二间房也不自动送入观战；客户端退出匹配等待态、把按钮刷新为浅黄色，并 toast `西格莉卡？已经开始和别人对局了。`，由用户再次点击决定是否观战。
* 点击浅黄色观战按钮后若目标房刚结束或清理，服务端不创建新决战；客户端把按钮恢复为红色，并 toast `这盘决战已经结束了。`，由用户再次点击决定是否挑战。
* 特殊决战继续从 HTTP 通用观战列表中过滤；服务端在专属观战加入路径校验黑化篇章资格，普通阶段账号即使知道房间号也不能绕过。
* 观战投影继续遵守特殊决战的隐藏数据边界。
* 特殊决战观战人数沿用现有 `MAX_SPECTATORS_PER_ROOM` 单房软上限和原观战者重连豁免，不另设无限席位。
* 特殊决战继续禁用玩家与观战者聊天输入；观战者可看到现有安全系统记录和当前演出，但不补播加入前已经结束的弹窗演出。
* 特殊决战结算必须区分房主与观战者：只有房主的“继续”可以启动恢复剧情；观战者绝不能调用房主专属恢复接口。观战者确认结算后离开房间并直接返回保持打开状态的模式选择窗口，此时按钮已恢复为红色“与西格莉卡？决战”。
* 黑化主页现有通用观战按钮和其它已锁定工具按钮全部继续锁定。
* 空闲态点击红色挑战按钮先打开高难度确认弹窗；取消只关闭确认层并保留模式选择窗，确认锁定本次“挑战”意图后才进入原有决战创建流程。本人“继续”与浅黄色“观战”不显示该确认。
* 特殊决战为真人与西格莉卡？分别配置 30 分钟主时间，不配置读秒；任一方主时间耗尽立即超时判负，智子单手搜索仍沿用最多 5 秒的既有边界。
* 桌面黑化棋钟的“主时间”、倒计时数字必须使用黑化主题高对比文字 token，不能被 Bright School 后置深色文字规则覆盖。
* 竖屏移动端黑化棋钟按“主时间/读秒标签、时间数字、弹性进度条”单行排列；标签左对齐，数字紧随其后，进度条填满剩余水平空间。
* 竖屏黑化对局的回放手数、右上折叠菜单文字、系统记录数量角标、提子/除子/超频小标题、观战视角标记和点按说明浮层必须使用黑化语义 token，不能被 Bright School 后置子元素颜色覆盖。
* 移动端“系统记录”弹层通过 Portal 离开特殊房 room root 后仍必须保持红黑主题；弹层外壳、标题、关闭按钮、记录正文、技能记录、滚动条和只读输入均不得回落到普通纸张样式。
* 特殊决战结束、清理或服务恢复后，单局槽位状态必须与权威房间状态一致，不能永久占槽或错误放行。

## Acceptance Criteria

* [ ] 两个符合开局阶段的用户近乎同时点击决战，最终至多创建一间特殊房；另一人退出等待态、看到浅黄色按钮和 `西格莉卡？已经开始和别人对局了。`，不会被自动送入观战。
* [ ] 当前特殊房房主刷新、断线重连或服务重启后，仍恢复原房，不被忙碌判断拦截。
* [ ] 当别人占用决战槽位时，模式选择窗口按钮变为浅黄色 `西格莉卡？正在对局中。。。`；点击后直接进入观战且不出现忙碌 toast、通用观战窗口或匹配等待弹窗。
* [ ] 特殊房处于预加载、开场演出或房主断线等待恢复时，同样显示占用状态并允许进入当前安全观战视图。
* [ ] 槽位空闲时显示原红色“与西格莉卡？决战”；当前房主显示原红色“继续与西格莉卡？决战”。
* [ ] 黑化主页通用观战按钮仍不可点击，特殊决战也不出现在通用观战列表。
* [ ] 处于黑化篇章的已登录用户可以通过忙碌按钮加入当前特殊决战，退出和重连沿用安全观战链路。
* [ ] 普通阶段账号无法取得特殊决战状态或通过已知房间号直接加入。
* [ ] 观战者无法落子、触发技能、请求数子/和棋或看到隐藏智子审计数据。
* [ ] 观战人数达到现有单房上限时拒绝新观战者，但已在席观战者可重连；特殊房聊天输入保持禁用。
* [ ] 浅黄色按钮点击时若目标房已结束，按钮恢复红色并显示 `这盘决战已经结束了。`，且本次点击不会创建新决战。
* [ ] 观战者看到特殊决战结算时不会触发 `/sigrika/recovery/start` 或改变自己的黑化篇章阶段。
* [ ] 观战者确认结算后离开已结束房间并直接返回模式选择窗口，窗口显示红色“与西格莉卡？决战”，可以由用户再次点击发起自己的决战。
* [ ] 空闲态点击红色挑战按钮只打开含精确风险文案的确认弹窗；取消不离开模式窗，确认后才开始原有流程；本人继续与浅黄色观战不弹确认。
* [ ] 真人玩家与西格莉卡？的棋钟都从 30:00 正确递减，任一方耗尽立即超时判负，不进入读秒，也不出现读秒次数和读秒语音。
* [ ] 桌面黑化棋钟标题和数字清晰高对比；竖屏移动端以“标签、时间、进度条”横排，进度条占满剩余宽度。

* [ ] 移动端系统记录弹层使用完整红黑视觉且所有正文/控制可读；普通房与剧情教学记录继续使用原样式。
* [ ] 特殊房结束或按既有规则清理后，下一位用户可以创建新决战。
* [ ] 服务端、前端、恢复与并发回归测试覆盖上述行为。

## Scope Convergence

* Future evolution：本轮只建立一个黑化西格莉卡决战槽位，不抽象为通用 Boss 房池，也不预留第二个智子会话。
* Related scenarios：通用观战窗口、普通匹配、约战、准时宝练习和普通阶段账号保持原行为；只在黑化模式选择窗口增加专属观战入口。
* Failure and edge cases：MVP 已包含并发抢占、按钮状态竞态、服务重启恢复、预加载/演出/断线占槽、观战席上限、观战重连、结算分流和槽位释放；不追加管理后台强制抢占或人工排队系统。

## Technical Approach

* 由服务端房间权威状态派生唯一未结束特殊房，并通过同步的创建临界区保证“检查并创建”不可并发穿透；恢复的未结束 `PersistedRoom` 同样占用槽位。
* 向符合黑化篇章资格的客户端发布不含隐藏数据的特殊房占用状态；模式选择窗口据此在红色挑战/继续按钮与浅黄色观战按钮之间实时切换。
* 挑战与观战使用可区分的明确意图和稳定 ack 结果：服务端绝不根据最新状态偷偷改变意图，只返回占用/已结束信息供客户端更新按钮和 toast。
* 专属观战入口复用现有房间成员、容量、presence patch、按 viewer 投影、退出与重连基础设施，同时收窄特殊房隐私例外到“已登录且处于黑化篇章”的观战者；通用观战列表继续排除特殊房。
* 特殊房为真人与 NPC 分别配置 `30 * 60` 秒主时间和零读秒；时钟 UI 使用显式总主时间基数，不复用普通五分钟固定分母。
* 模式选择窗复用 `ConfirmModal` 承载空闲挑战的高难度提示；确认回调携带明确 `start` 意图，不能因弹窗停留期间的状态轮询改成观战。
* 黑化房间最终 `room-timers.css` owner 显式覆盖棋钟标签与数字颜色；竖屏 owner 恢复被通用移动规则隐藏的标签，并用三列 grid 让进度条弹性占满余量。
* 黑化房间最终 `room-mobile-readability.css` 只接管留在 room root 内的移动文本与临时表面；`ChatBox` 依据 `room.sigrikaCandyDuel` 为弹层追加 `.sigrika-duel-system-log`，让独立 `room-system-log.css` 在 Portal 目标处继续接管主题。
* 结算组件按当前账号是否为特殊房真人玩家分流：房主继续恢复剧情，观战者普通确认后离房并回到打开的模式选择窗口。

## Decision Log

### 计时口径（已由后续确认更新）

**Decision**: 真人玩家与西格莉卡？各自采用 30 分钟主时间且没有读秒，任一方耗尽立即判负；智子搜索仍保持每手最多 5 秒。

**Consequences**: 服务端必须让两名玩家都进入普通棋钟递减路径，并在持久化/恢复中保留各自剩余主时间；30 分钟是双方各自的思考时间，不是整盘墙钟上限。

### 高难度确认与棋钟呈现

**Decision**: 仅空闲态“与西格莉卡？决战”先显示精确高难度提示，确认后才发起挑战；移动端棋钟固定为“标签、时间、进度条”单行，桌面与移动端文字均使用黑化主题高对比 token。

**Consequences**: 本人继续与他人对局观战保持一次点击；确认期间状态变化也不能改变已选择的挑战意图。最终黑化 CSS owner 必须覆盖通用 Bright School 文字颜色和移动端隐藏标签规则。

### 观战资格与入口

**Decision**: 特殊决战只向当前处于黑化篇章的已登录用户开放观战，但不开放黑化主页通用观战按钮，也不进入通用观战列表。有别人正在决战时，模式选择窗口的决战按钮改为浅黄色 `西格莉卡？正在对局中。。。`，点击直接进入当前特殊房观战；当前房主仍看到并使用“继续与西格莉卡？决战”。

**Consequences**: 观战入口与剧情进度强绑定，避免通用观战窗口提前剧透；服务端仍必须校验账号阶段并原子决定“恢复、观战或创建”，客户端按钮状态只负责呈现，不能作为全服单局互斥的权威。

### 槽位占用生命周期

**Decision**: 特殊房从创建成功到正式结束或按既有规则清理的全生命周期都算“正在对局中”，包括预加载、开场演出和房主断线等待恢复；符合资格的用户在这些阶段均可进入观战。

**Consequences**: 按钮状态与全服智子槽位保持一致，不会在尚未首手或暂时断线时错误开放第二盘；观战 UI 必须能够安全显示尚未进入正式落子的房间状态。

### 按钮状态竞态

**Decision**: 保留用户点击时意图。红色挑战请求若刚被别人抢先，只刷新为浅黄色并提示 `西格莉卡？已经开始和别人对局了。`；浅黄色观战请求若目标刚结束，只恢复红色并提示 `这盘决战已经结束了。`。两种情况都要求用户再次点击，不自动切换行为。

**Consequences**: 极端竞态下会多一次明确点击，但高难决战不会意外变成观战，观战也不会意外创建新决战；服务端需要返回稳定的“已被占用”和“目标已结束”结果供客户端刷新状态。

### 观战结算返回

**Decision**: 观战者确认特殊决战结算后离开房间，并直接回到保持打开状态的模式选择窗口；槽位已释放，按钮显示红色“与西格莉卡？决战”。

**Consequences**: 观战者可以明确决定是否马上开始自己的高难对局，同时必须把房主恢复剧情动作与观战者普通确认动作彻底分离。

### 移动端文字与 Portal 弹层所有权

**Decision**: 黑化对局内的低对比文字由最终移动可读性 owner 直接绑定语义 token；系统记录弹层使用显式 `.sigrika-duel-system-log` 类在 Portal 后重新建立主题边界，不依赖 `.sigrika-candy-duel-room` 祖先。

**Consequences**: 后续新增 Portal 到 app shell 的特殊房浮层必须携带同类语义状态，不能只在房间后代选择器中补色；视觉验收以构建后的生产 CSS 与实际移动视口计算样式为准。
