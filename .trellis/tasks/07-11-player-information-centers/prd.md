# 玩家公告与邮箱信息中心结构优化

## Goal

在保留公告与邮箱两个独立大厅入口、现有业务规则和 Bright School 纸张/手帐视觉语言的前提下，统一玩家信息阅读模型：桌面使用稳定的左侧列表/右侧阅读区，移动端使用列表进入详情并明确返回，提升层级、可读性、响应式表现和可访问性。

## Requirements

* 仅调整玩家公告中心与邮箱，不调整后台管理界面、服务端接口、数据模型或响应类型。
* 新增内部共享信息中心布局，负责标题栏、列表槽、阅读区、移动端列表/详情状态、返回与关闭；公告和邮箱保留各自业务状态与动作。
* 桌面端统一为约 960–1040px 宽、最高约 80dvh 的双栏主从布局，左栏约 288–320px，正文阅读宽度不超过约 68ch。
* 移动端使用安全区内近全屏布局，列表和详情单页切换，不产生页面级横向滚动。
* 公告移除嵌入式详情遮罩；标签与列表位于左栏，详情位于右栏。桌面端公告与更新日志加载或切换完成后自动打开列表第一条，并沿用打开即标记已读规则；移动端继续从列表开始。
* 桌面邮箱首次打开列表第一封邮件并沿用打开即标记已读规则；移动端继续从列表开始。删除当前邮件后，桌面若仍有邮件则选择新的第一封，否则显示空态。
* 保留公告分页、分类、置顶、未读和已读刷新规则；保留邮箱领取、删除、忙碌态与用户刷新规则。
* 纸张网格用于外壳、暖白阅读纸用于正文、粉色用于选择与主要操作；状态使用小标签、圆点或侧边标记，不再整卡大面积染色。
* 领取动作位于阅读区底部操作栏；删除是次级危险操作，交互目标至少 44×44px。
* 选择、前进和返回使用约 260ms 的 transform/opacity 平滑减速动效；移动端标题栏始终预留返回控件槽位，避免进入详情时标题与关闭按钮瞬间错位，并支持 prefers-reduced-motion。
* 外层为正确命名的 dialog；列表使用 li > button；公告标签支持方向键切换；焦点进入、返回、关闭与恢复路径清晰；加载、错误和结果通过独立 live region 通知。
* 更新旧公告任务中关于嵌入式详情层和禁止双栏详情的旧决策。
* 同步更新系统设计入口、前端架构与主题/移动端分篇，并重新生成系统设计 HTML。

## Acceptance Criteria

* [ ] 桌面公告与邮箱首次打开自动选中并展示列表第一条；移动端保持列表优先。
* [ ] 移动端点击条目进入详情并可返回原列表，返回后保持公告标签和列表上下文。
* [ ] 桌面公告默认打开第一条、移动端公告显式点击条目后标记已读，分页、重试与空态继续工作。
* [ ] 桌面邮箱默认打开第一封、移动端邮箱显式选择后标记已读；领取与删除状态正确，删除后桌面推进到剩余第一封、移动端回到列表。
* [ ] 窄屏无页面级横向滚动，关闭、返回、删除和领取均可触达且点击区域不小于 44px。
* [ ] dialog、列表按钮、tab、焦点和 live region 语义通过组件测试。
* [ ] 动效只使用 transform/opacity，并在 prefers-reduced-motion 下关闭或显著缩短。
* [ ] 390×844、768px 边界和桌面宽屏完成实机视觉检查。
* [ ] 相关测试、npm run check、npm run docs:system-design 通过。

## Definition of Done

* 玩家公告与邮箱组件、共享布局、CSS 和测试完成。
* 旧公告 PRD 与系统设计文档反映新结构。
* docs/system-design.html 已重新生成。
* 不包含当前工作区其它未提交修改。

## Technical Approach

新增小型内部信息中心布局组件，通过 list/detail 插槽和 mobileView 状态复用结构，不抽象公告/邮箱业务逻辑。组件始终渲染桌面双栏所需的列表和详情区域，移动端通过状态类切换可见区域并提供返回按钮。公告与邮箱先建立中性选择状态，再由共享窄屏判断决定桌面加载后打开第一条、移动端保持列表优先。CSS 继续由现有 modals 域入口和 Bright School 显式选择器拥有视觉，移除嵌入式公告详情和移动邮箱横向卡带合同。

## Decision (ADR-lite)

**Context**: 公告使用列表加嵌入式详情遮罩，邮箱桌面双栏、移动端横向卡带加详情，同类信息阅读形成两套心智模型。

**Decision**: 桌面统一双栏主从结构，移动端统一列表到详情的单页切换；保留两个入口和各自业务语义。

**Consequences**: 玩家获得一致导航与更清晰阅读层级；公告旧详情层 CSS/测试和邮箱移动横向列表合同需要替换，系统设计事实需要同步更新。

## Out of Scope

* 合并公告和邮箱入口。
* 后台公告/邮箱管理界面改版。
* API、数据库、未读算法、领取资产逻辑变更。
* 新图片资产、第三方动效依赖或全局弹窗体系重构。
* 清理其它主题、弹窗或 CSS 技术债。
