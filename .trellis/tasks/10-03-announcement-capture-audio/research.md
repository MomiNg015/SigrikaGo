# Investigation

## Capture challenge audio (implemented)
- Confirmed cause: `ResultModal` returned early from both result effects whenever `isChallenge` was true. Normal completed challenges also have null winner color, so removing those guards alone would produce a draw voice/no effect sound.
- Added shared completion predicate requiring finished phase, exactly 100 moves, completion reason, no invalid result and authoritative `practice.result`. Both audio resolvers celebrate participating players independently of ordinary winner color; existing playback settings and per-channel duplicate guards stay in place.
- Focused DOM coverage includes settlement pending -> complete, both channels, settings, rerenders, invalid/incomplete/stale result and spectator silence.

## Announcement first-open error (controlled local reproduction and fix)
- All four announcement routes catch domain errors and respond with JSON. Startup awaits schema initialization before admitting traffic; domain payloads use serializable primitives/dates.
- Client format error is emitted when response Content-Type does not include `application/json`; server request parsing uses a distinct `请求 JSON 格式错误` message. The user quote may be approximate.
- Verified bodyless POST with application/json header using real Express JSON parser, production JSON syntax error middleware and actual fetch: first and second request both return HTTP 200 application/json with empty body parsed as `{}`. This does not reproduce the reported failure.
- Parent verified unauthenticated live development list request returns the expected HTTP 401 application/json.
- User clarified the issue occurs locally and the approximate message concerns the interface failing to return JSON. The local backend process changed while the frontend stayed running, consistent with development restart windows; the original failed request trace was not captured.
- User further clarified other windows work normally and announcements fail frequently. This reduces confidence that a broad restart window explains every occurrence. The controlled outage proves a concrete proxy/recovery defect, but does not establish the original announcement-only root cause; exact first-response tracing remains a limitation. Announcement route handlers use the same initialized database and JSON error handling, with no per-list schema initialization found.
- Confirmed controlled reproduction with actual Vite proxy and isolated ephemeral HTTP backend: backend initially unavailable -> HTTP 500, Content-Type text/plain, empty body; backend starts -> second announcement GET returns HTTP 200 JSON. This reproduces the same symptom without claiming the original user request was observed. A first-request socket reset has the same proxy failure path.
- Fixed the API proxy to return JSON 503 with `dev_backend_unavailable` for connection refusal/reset. Announcement list/detail/summary explicitly opt into bounded safe GET recovery (250/500/1000 ms, three retries). No POST replay or retry of unrelated failures; persistent outage displays the service message and preserves manual retry. Caller abort cancels the recovery wait.
- Real HTTP regression coverage includes default cold proxy symptom, fixed JSON error, first authenticated read through backend startup, subsequent normal open and first-request reset recovery. API tests cover retry bounds, unrelated errors, writes, malformed response and cancellation; modal coverage verifies list/detail opt in while read POST remains unchanged.
- Real-client DOM tests combine the announcement modal and concurrent summary hook against mocked HTTP responses: stable first-open/reopen and separate transient failures in list, detail and summary all recover. This is frontend HTTP fixture coverage, not a live authenticated browser observation.
- Development-only diagnostics on unexpected opt-in announcement responses record request path, HTTP status and Content-Type, excluding token/body/content. Malformed responses retain their errors without retry; this enables identifying the exact failed route if the announcement-only issue persists.
