# 后台管理-剧情教学编辑器改版

## Goal

把后台「新手引导」升级并改名为「剧情教学」，在不改变底层 `StoryScript` 数据结构和运行时播放器合同的前提下，重做后台编辑体验。新界面应面向长期维护脚本的桌面生产工具，提供脚本卡片库、自动流程图、当前步骤专用表单、实时问题面板和预览，继续支持旧脚本在新界面中编辑。

## Requirements

### Scope and compatibility

- 后台入口文案从「新手引导」改为「剧情教学」。
- 不修改底层数据模型，继续使用现有 `StoryScript`、`nodes`、`nextNodeId`、`options`、`initialBoard`。
- 保留现有剧情节点和发布/草稿数据合同，旧脚本必须能在新界面继续编辑。
- 第一版覆盖现有全部能力：剧情、道具互动、对弈教学、初始棋盘、落子、技能、数目、认输。
- 不考虑移动端；但桌面布局要兼容较窄桌面窗口。

### Script library

- 左侧/独立区域使用脚本卡片库，不再只依赖单个下拉选择器。
- 脚本按用途分组：新手引导、道具互动、对弈教学、混合剧情教学。
- 支持复制脚本。
- 草稿/未发布脚本可删除。
- 已发布脚本可停用。
- 默认新手引导是系统脚本，不可删除。
- 新建脚本先选择用途：新手引导、道具互动、对弈教学、混合剧情教学。
- 触发条件使用专用表单。
- 道具互动触发条件从真实道具列表和角色列表下拉选择。

### Flow editor

- 编辑器使用自动流程图：主线自上而下，分支横向展开。
- 节点不可拖拽，不允许手动画线。
- 节点 ID、`type`、`nextNodeId` 默认隐藏，只在必要的高级/调试信息里体现。
- 节点显示为紧凑摘要卡：步骤类型、友好名称、关键内容摘要。
- 步骤名称可手动编辑；不填时自动生成。
- 步骤类型按分类选择：剧情步骤、对弈步骤、结算步骤。
- 新增步骤默认插入到当前选中节点后面。
- 剧情选项可以添加分支步骤。
- 剧情选项支持跳到某步骤或结束剧情；空目标仍表示关闭窗口，流程图上显示虚拟「结束剧情」节点。
- 删除主线中间步骤时，前一步自动接到后一步。
- 删除分支目标时，相关选项变成未选择目标并在问题面板提示修复。

### Step form

- 右侧只显示当前步骤专用表单，不保留旧的全量节点表单入口。
- 初始棋盘、玩家落点、NPC 落点、技能目标全部优先使用棋盘点选。
- 技能选择使用角色 + 技能二级选择，而不是裸 `skillId` 文本优先。
- 表单内提供轻量帮助文本。
- 提供完整说明弹窗。
- 错误提示靠近问题字段，且实时问题面板可点击定位到对应步骤。

### Preview and save

- 支持从开头预览和从当前步骤预览。
- 当前步骤预览要从起点静默重放到当前步骤，保证棋盘状态准确。
- 保留「保存草稿」，不做自动保存。
- 离开/切换脚本时提醒未保存。
- 保存成功、校验失败、点击节点、切换步骤、打开帮助等操作要有明确反馈。

### Visual design

- 为本模块建立独立、干净、专业的后台工具界面风格，不沿用旧后台黑绿色污染风格。
- 使用独立 class namespace，例如 `.admin-story-workbench-*`。
- 不复用会带来黑绿风格的旧 `.admin-onboarding-*` 样式，除非明确清理覆盖。
- 新 CSS 使用语义化 CSS 变量，避免组件中散落硬编码颜色。
- 背景使用温和浅色，主表面使用白色或近白色。
- 主品牌色使用柔和蓝色/蓝紫色，仅用于主要操作和选中态。
- 成功/发布使用低饱和绿色，危险操作使用红色并与主操作分离。
- 表单输入框必须为浅色底、深色文字、清晰边框。
- 卡片圆角约 8px，阴影轻，不做厚重漂浮。
- 使用一致的 4/8px spacing scale。
- 使用 lucide 图标或项目现有图标体系，不使用 emoji 当功能图标。
- 避免黑底绿字、绿边输入框、大面积深色面板、强渐变、斜切、游戏化样式、高饱和色泛滥、文字挤压和字段遮挡。

### Interaction and accessibility

- 动效只用于状态变化和空间连续性，控制在 150-250ms。
- 不做装饰性动效。
- 支持 `prefers-reduced-motion`。
- 所有按钮 hover/focus/disabled 状态清楚。
- 删除、停用、发布等关键操作需要确认或明确反馈。
- 弹窗、下拉、棋盘选择器层级要独立管理，不能被其他面板遮住。

## Technical Approach

- 以现有 `src/admin/AdminOnboardingStory.jsx` 作为功能入口，重构为剧情教学 workbench，而不是改运行时播放器或 `StoryScript` 模型。
- 复用现有 `/api/admin/story-scripts` 保存/发布 API；如删除/停用缺少管理接口，则在 `server/storyScripts.js` 和路由层补齐最小 API，并保持旧兼容路径不变。
- 复用 `TutorialSessionModal` 做预览；当前步骤预览在前端构造从起点到当前步骤的预览脚本或运行前置节点推演。
- 复用共享 `Board`、`gameModeById`、`createGameState`、`getPoint` 作为棋盘点选基础，避免维护第二套坐标系统。
- 使用新 CSS namespace `.admin-story-workbench-*` 和语义化变量构建浅色桌面工具界面。
- 更新 `AdminOnboardingStory.test.jsx`、样式合同测试或补充新的源码/CSS 合同测试，覆盖命名、布局、问题面板、流程图、棋盘点选和禁用旧样式污染。

## Decision (ADR-lite)

**Context**: 当前后台脚本编辑器已经能维护 StoryScript，但编辑体验仍是旧「新手引导」大表单，节点字段暴露过多，视觉风格也容易继承旧后台黑绿污染。

**Decision**: 保持底层 StoryScript 数据合同不变，只改后台编辑层：将脚本选择改为卡片库，将节点列表改为自动流程图，将全量节点表单改为当前步骤专用表单，并在同一模块中加入问题面板和预览。

**Consequences**: 数据兼容风险低，旧脚本可继续编辑；前端状态管理会明显变复杂，需要把 graph derive、validation、selection、dirty guard 和 preview helpers 拆成清晰的小函数。删除/停用如果现有 API 不支持，需要补齐最小管理能力，但不引入新 DSL 或自由画布。

## Out of Scope

- 不做移动端专门适配。
- 不改 `StoryScript` 数据结构或新 DSL。
- 不做自由画布、节点拖拽、手动画线。
- 不做撤销/重做。
- 不做条件分支。
- 不重做玩家侧剧情/教学播放器视觉。

## 2026-06-29 Addendum: 分支局面切换

- 一个 `StoryScript` 仍然只保留一个脚本级默认 `initialBoard`，不新增表结构、不引入新 DSL。
- 为同一脚本内的不同分支教学新增“设置局面/切换局面”步骤，作为普通 `nodes` 节点保存。
- “设置局面/切换局面”步骤携带自己的棋盘局面快照；运行到该步骤时替换当前教学棋盘状态，然后继续走 `nextNodeId`。
- 典型用例：新手引导中询问“会不会下围棋”，不会则进入入门教学局面，会则进入进阶教学局面，两条分支不共用同一个默认 `initialBoard`。
- 后台表单必须用棋盘点选维护该步骤的局面快照，并在流程图摘要卡上显示为局面步骤。
- 发布校验、运行时播放、后台从开头预览和“从当前步骤预览”的静默重放都必须应用该步骤，确保分支内棋盘状态准确。
- 验收补充：同一脚本可通过不同剧情选项进入不同“设置局面/切换局面”节点，并在后续落子、技能、数目、认输步骤中使用各自分支的棋盘状态。

## 2026-06-29 Addendum: 完整教学对弈 Screen

### 背景纠正

- 当前把对弈教学渲染为简化 `TutorialSessionModal` 棋盘弹窗的方向不符合产品目标，后续实现应废弃该方向。
- 对弈教学不是一个简化棋盘弹窗，也不应该把完整对弈界面挤进后台右侧窄预览。
- 对弈教学必须进入现有完整对弈界面形态，包含双方信息框、棋盘、操作区和现有对弈布局语境。

### 已确认产品决策

- 教学对弈应进入一个独立的本地教学对弈 screen，而不是 modal overlay。
- 该 screen 应复用现有完整 `RoomScreen` / `RoomBattleStage` / `Board` / 双方信息框 / 操作区的视觉与布局。
- 本地教学对弈不创建真实 socket 房间，不走匹配，不影响真实战绩、排行或回放。
- 脚本在遇到 `设置局面` 节点时启动教学对弈 screen。
- `设置局面` 节点同时承担两种语义：
  - 如果尚未在教学对弈 screen 内，进入完整教学对弈 screen，并用该节点配置初始化教学对局。
  - 如果已经在教学对弈 screen 内，替换当前棋盘局面，用于分支切换或章节切换。
- 在遇到第一个 `设置局面` 之前，普通剧情仍使用原剧情播放器。
- 一旦进入教学对弈 screen，后续 `story` 节点表示退出对弈并回到普通剧情窗口，从该 `story` 节点继续播放。
- 脚本结束或空目标结束时退出教学对弈 screen，回到进入前页面。

### 教学对弈中的剧情表现

- 对弈 screen 内的纯对话由 `npc-dialogue` 或 `player-choice` 承担，不使用 `story` 节点。
- NPC 对话显示在对弈界面左上安全区，带立绘和对应文本。
- 如果 `npc-dialogue` 或 `player-choice` 节点有 `options`，用户回复应在屏幕中间弹出选择窗口。
- 用户选择只用于剧情分支跳转，不代表落子、技能或任何游戏动作。
- 如果 `story` 节点没有 `options`，显示继续按钮推进到 `nextNodeId`。
- 普通非对弈剧情仍使用原 `StoryPlayerModal`。

### 设置局面节点配置

- `设置局面` 节点不仅配置棋盘快照，也配置进入这一段教学对弈的场景信息。
- `设置局面` 表单至少包含：
  - 棋盘局面：模式 + 棋子点选。
  - 玩家执棋：黑 / 白，默认黑。
  - 玩家角色：无 / 角色列表。
  - NPC 角色：角色列表。
  - NPC 显示名：默认使用角色名，可手动覆盖。
  - 教学提示 / 进入文案：可选，用于进入对弈 screen 后的第一句提示。
  - 下一步骤：继续使用现有 `nextNodeId`。
- 玩家侧不显示段位。
- 玩家侧可选择角色，也可以选择“无”。
- 当玩家角色为“无”时：
  - 玩家信息框不显示立绘。
  - 玩家技能为空，不显示技能按钮或技能入口。
  - 仍显示玩家用户名和执棋身份。
- NPC 侧使用脚本配置角色和显示名。
- 不要求 MVP 配置头像框、称号或其它装饰。

### 落子、技能和 NPC 行动

- 教学对弈不是自由对局，玩家落子节点必须强引导，只允许点脚本指定交叉点。
- 玩家技能节点必须强引导，只允许按脚本指定角色、技能和目标完成。
- 点错时在完整对弈界面内显示教学提示，不发送真实 socket action。
- NPC 落子 / NPC 技能由脚本推进，不需要真实 AI。
- NPC 行动可以通过“继续 / 播放”推进；是否自动播放可在后续实现阶段再细化。
- 数目、认输等结算步骤也在完整教学对弈 screen 内呈现。

### 后台预览

- 后台右侧预览区不应嵌入缩小版完整对弈界面。
- 右侧预览区保留摘要和“从开头预览 / 从当前步骤预览”入口。
- 点击预览后打开全屏预览 overlay 或切换到全屏预览模式，渲染完整教学对弈 screen。
- 如果预览路径尚未经过 `设置局面`，使用普通剧情播放器预览。
- 如果预览路径已经经过 `设置局面`，进入完整教学对弈预览，并通过静默重放恢复棋盘状态。

### 实施拆分建议

1. 先做本地教学对弈 screen 壳，复用完整对弈界面视觉。
2. 接入 `设置局面` 的进入 / 切换语义和双方场景配置。
3. 接入对弈 screen 内 `npc-dialogue` / `player-choice` 对话 overlay 和选项弹窗。
4. 接入玩家落子 / 技能强引导、NPC 行动、数目和认输。
5. 后台预览改为全屏预览入口。

### 验收补充

- 进入对弈教学后，截图应看起来像现有完整对弈界面，而不是简化棋盘弹窗。
- 对弈教学界面必须包含双方信息框。
- 玩家侧不显示段位。
- 玩家角色为“无”时不显示玩家立绘和技能入口。
- 对弈中的 `npc-dialogue` 纯对话节点能在左上显示 NPC 立绘和文本。
- 对弈中的用户回复选项能在中间弹窗选择，并正确跳转分支。
- `设置局面` 是进入教学对弈 screen 的启动点，也是中途切换棋盘局面的节点。

## 2026-06-29 Addendum: 对弈教学中的节点节奏、交互约束与加载过渡

### 对弈步骤节点能力

- 在“对弈步骤”分类下新增并支持 `npc-dialogue` 与 `player-choice` 两类节点。
- NPC 可以有单独对话不落子的节点，也可以在 NPC 落子 / 放技能节点上携带对话文本与用户回复选项。
- NPC 节点的用户回复选项可以为空；为空时按节点配置自动继续或显示继续按钮。
- 用户可以有单独选项对话节点，只显示居中的选项弹窗，不显示用户气泡。
- 用户选择回复不在界面上显示用户气泡，但必须写入对弈教学聊天记录，供后续回顾。
- 对弈教学聊天记录只读；普通聊天输入框置灰，不允许自由输入。

### NPC 气泡与选项显示

- NPC 气泡显示在对弈界面左上安全区，包含 NPC 立绘与文本。
- NPC 当前气泡在下一个 NPC 节点开始时消失或被新文本替换；进入用户节点时清除 NPC 气泡。
- NPC 气泡出现使用向右展开 / 滑入动效，消失使用向左收回 / 滑出动效；动效控制在 150-250ms，并支持 `prefers-reduced-motion`。
- 当 NPC 节点同时存在气泡和用户选项时，显示用户选项期间 NPC 气泡仍然可见。
- 用户选项弹窗允许关闭 / 跳过，但必须弹出确认；确认后等同普通剧情窗口中的跳过 / 关闭，结束整个脚本。

### 节点节奏与自动推进

- 取消让用户手动触发 NPC 操作的按钮。
- NPC 自动操作节点进入后，先显示 NPC 气泡，再等待 `actionStartDelaySeconds`，然后自动落子 / 放技能。
- NPC 自动落子 / 放技能演出完成且棋盘状态生效后，再等待 `replyDelaySeconds` 显示用户选项或继续推进。
- `actionStartDelaySeconds` 默认 1.5 秒；延迟字段为空表示使用默认值，填写时必须是非负数字。
- 纯 NPC 对话节点没有选项且没有自动继续时，在棋盘下方功能区显示“继续”按钮；该按钮替换原先所有对弈按钮。
- 对弈教学中的所有自由对弈按钮（认输、数目、跳过落子、自由技能、测试按钮等）都由当前教学节点接管，不直接暴露普通对局操作。

### 玩家操作引导

- 玩家落子节点只允许在脚本指定点落子；指定点显示金黄色圆环 / 光效提示。
- 玩家点击非指定落点时 toast 提示“请在提示区域落子”。
- 玩家按钮节点只显示并高亮脚本指定按钮；点击非指定按钮时 toast 提示“请点击提示按钮”。
- 玩家技能节点必须分两阶段：先点击指定技能按钮，再点击棋盘确认。
- 如果技能需要棋盘目标，则目标点显示金黄色提示，点击错误点提示“请在提示区域落子”。
- 如果技能不需要棋盘目标，也仍然进入第二阶段；此时提示“点击棋盘区域任意位置即可”，点击棋盘任意位置执行技能。
- NPC 自动操作或系统自动节点执行期间，用户点击棋盘或按钮不产生 toast，直接无反应。
- 玩家侧角色可以为“无”；无角色时玩家信息框尺寸保持与有角色一致，但不显示立绘内容，技能为空且不显示技能入口。

### 退出、返回普通剧情与加载页

- `story` 节点在教学对弈 screen 内表示退出对弈界面并回到普通剧情窗口，从该 `story` 节点继续播放。
- 不新增单独的“退出对弈”节点；进入普通剧情窗口即使用现有 `story` 节点语义。
- 退出对弈界面不保留棋盘状态；后续如果再次进入对弈教学，必须通过新的 `board-setup` / 设置局面节点重新初始化。
- 对弈界面右上“退出房间”语义改为“退出 / 跳过”，点击后弹出确认；确认后结束整个脚本，不触发真实房间离开或认输逻辑。
- 去掉教学对弈 screen 顶部额外的“新手引导 / 剧情教学”标题行，只保留完整对弈界面自身的头部结构。
- 从普通剧情进入 `board-setup` / 设置局面节点时先显示加载页，加载页展示本次进入对弈的 NPC 角色，固定台词为“正在激烈对局中...”，最少显示 3 秒。
- 教学中退出对弈界面时，无论是主动退出、跳过，还是进入普通剧情窗口，都必须先显示加载页；加载页台词为“正在收拾棋盘...”，最少显示 3 秒。
- 对弈 screen 内再次遇到 `board-setup` / 设置局面节点时，也显示同一进入对弈加载页并锁定输入，然后切换棋盘局面继续脚本。

### 后台校验补充

- `npc-dialogue` 至少需要 NPC 文本或用户选项，否则该节点在运行时不可见。
- `player-choice` 至少需要一个用户选项。
- `npc-move` 必须配置落点；可以没有文本。
- `npc-skill` 必须配置技能；如技能需要目标则必须配置落点。
- `player-move` 必须配置落点。
- `player-skill` 必须配置技能；目标点可为空，用于无目标技能的“点击棋盘任意位置确认”流程。
- 数目、认输等结算步骤需要 `actor` 区分玩家触发、NPC 自动触发或系统触发。
