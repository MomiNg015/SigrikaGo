# 身份区主立绘 80% 等比构图

## Goal

将履历与详细资料身份区的主立绘从头像框的 70% 放大到 80%，同时保持水平、垂直居中和原始宽高比，避免任何压扁、拉长或变窄。

## Requirements

- 自己履历与他人详细资料共享的身份区主立绘统一占 `.profile-portrait-mask` 宽高的 80%。
- 主立绘继续使用 `object-fit: contain` 和居中定位，重置场景服装缩放与位移。
- 桌面端与 360–412px 竖屏移动端使用同一 80% 合同。
- 保留身份区头像框现有边框、背景、圆角和裁切行为。
- 角色战绩立绘维持现有透明、无边框、80% 等比合同，不修改其他角色立绘场景。

## Confirmed Visual Refinement Decisions

- 普通操作按钮统一使用 Bright School 现有米色底、深褐描边和 3–4px 硬阴影，按下时缩短阴影形成实体反馈。
- 模式选项卡复用同一按钮形体，选中态使用主题粉色，避免继续使用当前偏终端式的扁平白色页签。
- 举报、加入黑名单等危险操作保留米色外壳，但以暗红文字、描边和悬停色维持危险语义。
- 档案卡片统一使用参考图的 `#fffaf0` 暖白纸面、`#3d2b25` 深褐描边和既有硬阴影层级，不再使用偏黄的 `#fff6dd` 作为卡片底色。
- 段位、积分、总对局、胜率四张统计卡统一使用 `#fffaf0` 卡面、深褐描边与硬阴影；粉色、蓝色、薄荷色只用于图标或小标签点缀，数值统一使用深褐色。
- 保留现有桌面与移动端信息排列关系，不以卡片化为由重排布局。
- 角色战绩区域使用一张主题大卡作为外层容器；每个角色行同时做成独立小卡，但仅使用更短、更轻的硬阴影和较细描边，形成明确的两级层次。
- 角色行卡片在移动端继续保持原生六列单行布局，不允许换行；角色名仍是唯一允许省略的内容，角色列固定占 48% 以避免橘色姓名区域被数值列过度压缩。
- “最近十盘”使用独立的中层米色宽卡，阴影弱于统计卡主层级、强于角色行小卡；标题与对局回放按钮继续水平对齐，胜负结果标记保留现有语义颜色。
- 顶部身份区整体做成主题大卡，使用 `#fffaf0` 卡面、深褐描边和主层级硬阴影；立绘、身份文字与操作按钮共享同一外层卡片，用户名、称号等文字不再额外嵌套小卡。
- 模式区域不使用可见托盘；布局容器必须保持透明、无边框、无阴影。三个模式选项使用彼此独立的等宽主题选项卡，复用其它窗口的米色硬阴影、粉色选中态和实体按压反馈，并在桌面与移动端保持单行。
- 角色战绩行小卡以 `#fffaf0` 为基底，只混入约 6%–8% 的角色主题色；深褐描边和短硬阴影保持统一，避免形成杂乱的彩色卡片墙。
- 窗口结构底层继续保持透明，不重新引入突兀的纯白背景；可见色块只属于明确的卡片、按钮、标签和状态元素。
- 角色战绩可见表头保持一整行六列并与数据列严格对齐，首列直接显示“角色战绩”，并和对局、胜、负、和、胜率在同一行下对齐；语义表头继续保留无障碍“角色”列名。标题栏自身必须透明、无边框、无阴影，不拆成六个独立标签。
- 桌面与移动端都将角色战绩表头置于大卡的非滚动层，表头自身无滚动范围或滚动栏；角色行列表作为独立滚动层，并通过同一组列宽与非滚动槽位补偿保持六列严格对齐，不使用会让透明表头与内容重叠的 `position: sticky`。
- 移动端 `.profile-record-panel` 不承担纵向滚动，上方统计与最近十盘保持固定；唯一纵向滚动条局限在角色战绩大卡的 `.profile-character-table-scroll` 内，并在 360×800 至少保留一整行角色记录高度。
- 只有按钮和模式选项卡提供悬停上浮与按下回落反馈；身份卡、统计卡、最近十盘卡、角色战绩大卡和角色行卡均保持静止，避免对只读信息产生可点击暗示。
- `prefers-reduced-motion: reduce` 下关闭按钮和选项卡的位移反馈。
- 成就和金币恢复既有粉色/黄金标签，不继承通用米色按钮；个性化恢复既有蓝色语义。成就与金币图标清除终端主题遗留的绿色光晕。
- 段位恢复问号说明，内容说明最近十盘的升降规则；资料层和提示层均高于模式选项卡，提示内容不能被页签遮挡。
- 对局回放恢复既有浅绿色主题按钮，不再继承通用米色按钮。
- 角色战绩透明立绘框尺寸放大：桌面端使用 68×56px，移动端使用 46×46px；图像继续以 80% `contain` 居中显示。
- 详细资料的点赞、加好友、加入黑名单、举报全部位于顶部身份区；加入黑名单排在举报之前并使用对应人物移除图标。除点赞数外，四个按钮不显示文字标题；举报使用浅血红色强调面。
- 履历与详细资料的关闭按钮复用其它 Bright School 窗口的标准 44×44px 白色按钮、3px 深色描边、14px 圆角和硬阴影，不再继承档案操作按钮的米色样式。
- 履历模式选项卡与观战窗口共用 `.window-mode-tabs` 控件合同；档案样式只保留透明布局容器和上下留白，不再独立重绘一套近似选项卡。
- 顶部用户名及铭牌从上一版 200% / 184% 精确缩小 30%，桌面与移动端缩放分别为 140% / 128.8%；铭牌宽高、内边距和字体必须共用同一 scale，保持 3.75:1 不变形。移动端身份卡使用立绘与身份同排、操作区独占第二排的紧凑构图，为角色战绩独立滚动区留出空间。
- 桌面端点赞按钮最小宽度为 72px，四个社交操作图标统一为 18×18px。
- 段位/积分说明框向统计卡下方展开；卡片在 hover/focus 时提升层级，移动端聚焦时依据提示框实际边界自动校正资料正文滚动，并覆盖误命中的房屋资料 fixed-tooltip 规则，确保桌面与移动端均不被页签、后续卡片或窗口边界裁切。

## Acceptance Criteria

- [x] 主立绘计算 `object-fit` 为 `contain`，中心偏差不超过 1px。
- [x] 桌面与竖屏稳定性视口无溢出、裁切或布局回退。
- [x] CSS 合同、构建、最终打包 CSS 与系统设计文档生成通过。
- [x] 自己履历与他人详细资料复用同一套 Bright School 米色硬阴影按钮、独立模式选项卡和卡片层级。
- [x] 身份区、四项统计、最近十盘、角色战绩外层和角色行小卡满足已确认的背景、描边与分级阴影合同。
- [x] 桌面/移动透明表头与独立滚动角色行无重叠且六列对齐；移动端只有角色战绩卡内滚动，单行六列且至少显示一整行。

- [x] 对局回放为既有浅绿色；社交身份区四个操作顺序、图标化内容和举报浅血红语义已锁定。
- [x] “角色战绩”与五项列标题同一行下对齐、标题行无滚动范围，桌面/移动角色立绘尺寸已增大并保持 80% 等比。
- [x] 标准关闭按钮、观战同款选项卡、缩小 30% 后的 1.4 / 1.288 用户名铭牌、72px 桌面点赞按钮与 18px 社交图标均由真实计算样式断言锁定。
- [x] 段位提示框在 1440–1920px 桌面及 360–412px 竖屏视口内完整位于档案内容区。

## Definition of Done

- 相关 CSS 最终所有者与移动端安全层同步。
- 静态合同和真实浏览器断言更新。
- `docs/system-design.md` 与相关分篇同步并重新生成 HTML。

## Technical Approach

共享身份/角色立绘选择器及移动端最终覆盖统一使用 80% `object-fit: contain`。Bright School 档案样式拆为卡面、操作按钮和模式选项卡的有界 owner；桌面与移动端共用带“角色战绩”首列的非滚动视觉表头，语义 `thead` 只做无障碍后备。选项卡复用 Watch 的共享 hook，关闭和语义操作通过最终 owner 排除/覆盖通用按钮赢家；竖屏将身份卡压缩为两行，并把唯一纵向 overflow owner 下沉到角色记录表体。最终档案 owner 放在主题 QA 尾部以覆盖旧 commerce/profile 规则，不修改接口、素材或数据合同。

## Out of Scope

- 不修改身份头像框的边框、背景或尺寸。
- 不修改角色战绩之外的手册、房间、商城或剧情立绘。
- 不修改角色素材文件或服装校准数据。
