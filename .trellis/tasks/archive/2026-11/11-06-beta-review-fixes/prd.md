# 内测前审查修复

## Goal
修复本聊天已复现的上线风险，并完成用户接受的局部体验优化；保留现有工作区改动，不进行大规模重构或部署。

## Accepted scope
- 服务端实时视图不向对手或观战者泄露未公开隐藏手位置，包括历史及衍生字段；本人及结束后的完整回放保持有效。
- 最终同步建房边界统一检查容量及维护状态，异步读取期间容量变化不能越过上限。
- 断线及恢复同步期间拒绝改变局面的操作，取消旧请求重试，避免恢复连接后补发过时动作。
- HTTP 超时及外部取消覆盖完整响应体读取，保留认证刷新及开发环境有限重试。
- 首页必需资源保留严格就绪；低频窗口代码及非首页资源后台预热，打开窗口沿用加载反馈。
- 邮箱分别显示未读和附件待领取状态。
- 设置 CSS 回到既有文件大小合同内，保持外观与动效。
- 补充有意义的回归，同步系统设计入口/相关分篇及 HTML。

## Evidence / constraints
- 隐藏手执行后，对手和观战视图的 history 仍有坐标；并发陪练在 MAX_ACTIVE_ROOMS=1 时创建两间房。
- fetch 的响应头完成后超时被清除；断线 game:action 被 Socket.IO 缓存。
- 当前基点 e8ec9bb4，已有数据库、容量工具、文档和设计产物 WIP，不覆盖或提交无关内容。
- 主机内存紧张；验证串行运行，保留 1024MiB 空闲保护，只管理本任务的进程。
- 后台仅桌面，玩家以桌面和手机竖屏验证。

## Decisions
- 需求已由上一轮审查和用户“按建议做修正”确认，无需重复询问。
- 使用现有协议及模块，最小化接口变化；不新增依赖。
- 不调整生产容量默认值，不宣称本机测量为目标云容量。
- 用户补充确认：同步本地角色署名与奖励图文到发布快照，排除本地测试公告，保留作者库。按项目流程隔离提交本轮修复，不吸收原有 WIP。
