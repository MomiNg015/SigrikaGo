# 拓展彩虹豆豆跳跳糖角色剧情

## Goal

按 `彩虹豆豆跳跳糖剧情.docx` 的定稿，为西格莉卡与达妮娅补齐成功/拒绝剧情，并让每次对这两名角色使用彩虹豆豆跳跳糖时各自有 35% 概率被拒绝。

## Requirements

* 西格莉卡与达妮娅各有 35% 拒绝概率；其余 65% 进入成功剧情。
* 成功时消耗 1 个道具并应用既有效果；拒绝时不消耗道具、不应用角色效果、不触发成功类成就。
* 西格莉卡成功后不再获得或掉落 30 金币；她仍进入暂时不能出战的糖果状态，并在剧情中明确“暂时不能找她下棋了”。
* 达妮娅成功后的表现是双眼和嘴巴发出三道彩虹射线，不描述为全身发彩虹光。
* 成功与拒绝剧情的台词、玩家选项和叙述文字以用户提供的 Word 文档为准。
* 叙述节点的 `speakerName` 与 `characterId` 均为空；剧情窗口角色区域保持空白，不显示“旁白”字样或旁白立绘。
* 后台已发布的两份糖果剧情默认快照同步包含成功与拒绝节点，玩家侧按本次随机结果进入对应起始节点。
* 拒绝结果的玩家提示不能声称“成功使用”；跳过提示不能声称道具效果已经生效。

## Acceptance Criteria

* [ ] 可注入随机值的服务端测试证明 `< 0.35` 进入拒绝、`>= 0.35` 进入成功。
* [ ] 拒绝西格莉卡或达妮娅时，道具数量、用户效果、金币与选角不发生变化。
* [ ] 接受西格莉卡时消耗道具并禁用出战，但金币不增加。
* [ ] 接受达妮娅时消耗道具并应用 `deniaRainbowGlow`，成功剧情描述三道彩虹射线。
* [ ] 只有达妮娅接受糖果时才触发既有糖果成就事件。
* [ ] 成功/拒绝响应均播放对应剧情；所有叙述节点的角色名与角色 ID 为空。
* [ ] 前端拒绝提示与跳过文案准确反映“未消耗、未生效”。
* [ ] 默认剧情种子、后台默认快照和系统设计文档保持同步。
* [ ] 相关测试、`npm run docs:system-design` 与仓库质量门通过。

## Definition of Done

* 服务端概率、结算、剧情选择和成就边界均有回归测试。
* 前端拒绝提示与剧情播放路径有回归测试。
* 默认快照测试验证两名角色的成功/拒绝节点与空叙述角色区域。
* `docs/system-design.md`、相关分篇和生成的 `docs/system-design.html` 已更新。

## Technical Approach

* 在道具结算边界注入可测试的随机源，先完成使用资格校验，再为受支持的糖果角色判定 `accepted` / `rejected`。
* 以稳定的成功/拒绝起始节点 ID 保存同一角色的两条剧情；玩家响应只覆盖本次返回脚本的 `startNodeId`，不把随机结果写回后台脚本。
* 响应携带明确的使用结果，供前端 toast、跳过文案与成就触发判断；拒绝路径返回未改变的用户和仓库快照。

## Decision (ADR-lite)

**Context**: 现有 `item-character-use` 每个道具/角色只允许一份已发布脚本，且道具效果会在读取剧情前立即落库。

**Decision**: 保持一份脚本内含成功/拒绝两组节点，由服务端在结算时随机选择返回的起始节点，并用响应结果决定是否消费和触发成就。

**Consequences**: 不新增数据库模型或第二份冲突脚本；后台仍能编辑同一脚本的全部节点。成功/拒绝起始节点 ID 成为彩虹豆豆跳跳糖脚本的运行约定，需要测试保护。

## Out of Scope

* 不为西格莉卡和达妮娅之外的角色新增糖果效果或剧情。
* 不新增通用可视化概率节点编辑器。
* 不改变其它道具的使用与剧情触发行为。
