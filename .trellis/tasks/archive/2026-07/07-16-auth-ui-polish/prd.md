# 优化登录注册界面的视觉、交互与安全提交

## Goal

在保留“明亮校园”纸张网格、贴纸按钮、角色压框和现有登录标题资产契约的前提下，优化登录/注册表单的视觉层级、输入效率、错误恢复与安全提交行为。界面默认保持安静克制，不把用户当成需要逐步教学的新手；仅在限制确实相关或输入确实出错时提供简短、可执行的信息。

## Requirements

### Visual direction

- 保留现有纸张网格、深棕描边、粉色主操作、登录专用吉祥物和 `.text-window-title` 标题钩子。
- 将界面收敛为清晰的“围棋部入部登记卡”，不引入玻璃拟态、额外说明面板、教程文案或装饰性步骤条。
- 登录/注册模式、表单标题和主操作保持明确的视觉层级；模式切换时标题区与模式按钮位置稳定，不让整张卡片明显上下跳动。
- 登录主按钮使用自然、直接的中文动作文案；如保留英文，只能作为非必要的小型装饰文案。
- 移动端以竖屏为主；在 390x844 和键盘压缩高度 390x600 下无横向溢出、顶部吉祥物不被不可恢复地裁切、所有字段与主按钮可滚动到达。
- 动效仅用于表达模式切换、按压、提交和结果反馈，优先使用 `transform`/`opacity`，并尊重 `prefers-reduced-motion`。

### Input and interaction

- 正常状态不新增长段帮助文案、规则清单、密码强度教学或重复解释。
- 用户名与新密码的特殊限制以标签旁的短信息表达；更具体的原因只在对应字段出错时出现。
- 不再静默截断用户名；保留用户输入，并在失焦或提交时给出简短字段错误。
- 登录与注册切换时保留用户名，清空密码与确认密码，避免跨模式复用敏感输入。
- 密码和确认密码提供可访问的显示/隐藏控制，控制尺寸至少 44x44px，切换时不丢失输入焦点。
- 登录/注册模式控件提供可访问的选中语义；键盘焦点顺序与视觉顺序一致。
- 表单字段补齐 `name`、必要的 `required`、`autocomplete`、`aria-invalid` 与 `aria-describedby` 契约。
- 客户端校验失败时聚焦第一个无效字段；字段错误只在字段下出现一次。表单级错误区域只承载服务器、网络、超时或限流错误。
- 已登录冲突不使用浏览器原生 `window.confirm`；使用项目内可访问确认层，文案简洁，明确“退出其他在线会话并继续”与“取消”。

### Safe submission

- 使用同步提交锁与可渲染提交状态，保证连续点击、Enter 连按或模式操作不会发出重复认证请求。
- 提交期间冻结相关控件，主按钮显示简短进行态并通过 `aria-busy`/live region 传达状态；失败后恢复编辑，成功后沿用现有认证跳转。
- 忽略或取消过期请求的返回结果，避免旧模式/旧输入的响应覆盖当前表单。
- 登录与注册使用独立的凭据限流；refresh/logout 不再与 20 次/10 分钟的凭据额度共用同一个限流桶。
- 仅在实际收到 429 时根据 `Retry-After` 给出一句简短重试提示，不常驻展示安全教育。
- 服务端会话替换必须原子化或按用户串行化，并发登录最终只能留下一个有效会话。
- 注册只把真实唯一键冲突映射为“用户名已存在”；其他异常交给统一错误处理。
- 不存在用户与错误密码保持同一公开错误，并通过 dummy hash 比较降低明显的响应时间差。
- 新注册密码采用更合理的长度上限，同时保持旧账号登录兼容，不能因新策略直接锁死已有 6-7 位密码账号。

## Acceptance Criteria

- [x] 正常登录态只显示品牌、模式、字段标签、输入框和主操作，不出现新增的教程式说明段落。
- [x] 注册限制使用短标签信息；详细规则仅在对应错误发生时出现，且每个错误只出现一次。
- [x] 粘贴超长用户名不会被静默修改；失焦或提交时显示简短错误。
- [x] 空注册提交后焦点移动到第一个无效字段，不保留在提交按钮。
- [x] 登录/注册模式具有可访问的选中状态；密码显示控制可用键盘操作并具有可访问名称。
- [x] 从登录切到注册或反向切换时用户名保留、所有密码字段清空。
- [x] 快速点击或按 Enter 10 次只产生一个在途认证请求。
- [x] 旧请求返回时不会覆盖已切换模式或已开始的新提交。
- [x] 两个并发登录会话替换完成后只有最新会话有效。
- [x] 登录/注册凭据限流与 refresh/logout 限流分离，429 能显示简短、可恢复的等待提示。
- [x] 旧账号的 6-7 位密码仍能登录；新注册执行更新后的安全密码规则。
- [x] 1440x900、390x844、390x600 下无横向滚动，主操作可到达，短高度下顶部装饰不永久裁切。
- [x] `prefers-reduced-motion` 下模式与提交反馈不依赖明显位移动画。
- [x] 前端、认证路由、限流、会话并发和视觉契约测试新增或更新并通过。
- [x] `npm run check` 通过。
- [x] 认证运行行为、会话安全、主题/移动端事实同步到 `docs/system-design.md` 与对应分篇，并重新生成 `docs/system-design.html`。

## Definition of Done

- 实现与测试只覆盖登录/注册界面及直接认证链路，不混入现有工作区的其他未提交内容。
- 前端行为、服务端安全边界、限流与会话竞争均有回归测试。
- 桌面与竖屏移动端完成真实渲染和键盘操作验证。
- 系统设计文档与生成 HTML 同步。
- 完整质量门禁通过，交付时明确列出本任务文件与仍属于其他工作的脏文件。

## Technical Approach

- 在 `AuthScreen` 内建立明确的表单状态机：idle -> validating -> submitting -> conflict confirmation / error / success；使用同步 ref 防止 React 状态更新前的重复提交窗口。
- 将本地字段校验、服务端错误和提交状态分层显示：字段错误就地呈现，服务器错误仅在统一表单状态区呈现。
- 将登录/注册模式控件改为带选中语义的紧凑分段控件；密码显示控制作为输入框内的语义按钮。
- 在 Bright School 的 auth owner CSS 中完成视觉与响应式调整，避免新增跨主题全局覆盖。
- 在认证安全层拆分 credential/session 限流；客户端 API 错误保留状态码、错误码与 `Retry-After`。
- 在登录会话存储层使用事务完成 revoke + create；认证路由收窄唯一键异常映射并执行 dummy compare。
- 新密码校验与登录兼容校验分离，避免升级注册策略时破坏旧账号。

## Decision (ADR-lite)

**Context**: 当前视觉方向已经与项目品牌一致，主要问题来自信息冗余风险、字段规则隐藏、错误重复、提交竞争和会话安全，而不是缺少一套全新视觉语言。

**Decision**: 采用“克制的入部登记卡”方案：保留现有品牌资产和基础构图，只强化视觉层级与状态反馈；默认不解释，按需报错；客户端和服务端同时防重复/竞争。

**Consequences**: 需要同时修改前端表单、auth owner CSS、API 错误模型、认证限流和会话存储，并更新系统设计。不会增加复杂 onboarding，也不会依赖新的 UI 或动画库。

## Out of Scope

- 邮箱、手机号、验证码、找回密码、SSO 或第三方登录。
- 默认 CAPTCHA；仅保留未来在异常流量下渐进启用的可能性。
- 密码强度仪表、逐条规则 checklist、常驻安全教育或新手教程。
- 首页、房间、后台管理和全局主题的视觉重构。
- 将认证页改造成多步骤注册流程。
- 清理或提交当前工作区中与本任务无关的既有修改。
