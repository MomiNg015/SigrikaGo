# 重绘扎希拉商店蜡笔手绘背景

## Goal

基于用户提供的扎希拉商店截图提炼场景要素，绘制一张能承载现有商品卡、扎希拉立绘、气泡和钱包 UI 的新商店背景。画面需要比当前纯色 CSS 背景更有场所识别度，同时保持粗朴、低细节的蜡笔手绘质感。

## Requirements

- 从参考图提炼帐篷布、紫蓝色空展柜、石质柜台、卷毯、流苏、几何织纹和橙金色花形灯等视觉要素。
- 不复制参考截图中的人物、名字、交互提示或其他游戏 UI。
- 桌面构图适配当前商店主体约 16:10 的横向画幅。
- 左侧约 68% 作为商品区，保留低细节、低对比的陈列台和清晰的可用空间。
- 右侧作为扎希拉立绘/接待区，保留足够安静的背景与轮廓分离度。
- 前景柜台、中央陈列墙和后方帐篷形成明确的前中后景层次。
- 使用粗蜡笔、油粉笔、纸张纤维和不完全填色；避免精细 3D、写实材质和过度抛光。
- 颜色以灰蓝、靛紫、旧玫红、暖沙色为主，少量橙金作为识别性点缀。
- 无文字、无人物、无水印、无边框、无 UI 控件。
- 生成结果以版本化源图和运行时 WebP 保存到 `public/assets/shop/`，不覆盖旧资产。
- 用户确认首稿后，将其接入扎希拉商店主体；桌面使用完整 16:10 构图，竖屏使用独立 9:16 背景，不机械裁切横图。
- 扎希拉 header 复用同一背景的帐篷顶部区域，并叠加半透明旧纸蜡笔层与紫色织物下沿，降低原纯色 header 的割裂感。
- 新 header 只在扎希拉页生效，不改变残星会商店的红金主题。

## Acceptance Criteria

- [x] 商品区、立绘区、前景柜台和后景帐篷可在缩略图尺度下快速辨认。
- [x] 左侧商品 UI 放置区域没有密集装饰或强光斑干扰。
- [x] 右下立绘区域没有会穿过人物脸部或躯干的高对比结构线。
- [x] 参考元素被重新组织为原创背景，不包含截图人物或 UI。
- [x] 画面明显呈现粗糙蜡笔/油粉笔手绘质感，细节密度低于参考截图。
- [x] 最终文件位于项目资产目录，且没有覆盖现有文件。
- [x] 桌面扎希拉商店主体完整使用新背景，商品和立绘仍清晰可读。
- [x] 竖屏使用独立 9:16 背景，上方 56% 商品区与下方接待区均按真实 UI 覆盖位置留白。
- [x] 扎希拉 header 与帐篷背景视觉连续，标题与控制按钮保持清晰。
- [x] 切换到残星会商店后不继承扎希拉 header 背景。
- [x] 新运行时 WebP 进入商店预加载资产合同。

## Definition of Done

- 生成并保存项目内可复用的无人物横版与独立竖版背景。
- 对桌面 1440x900、移动 375x812 与短屏 375x600 进行视觉检查，确认构图、覆盖位置、风格和禁用项。
- 将横竖 WebP、扎希拉专属 header 和预加载注册接入运行时，并由静态合同测试守护。

## Technical Approach

使用内置 ImageGen 的参考图生成模式。八张用户截图只作为元素、色彩与场景结构参考；依据当前 `.shop-product-stage`、`.shop-mascot-slot` 和移动端分区合同重新组织构图。用户确认首稿后，将 PNG 保留为源图并生成运行时 WebP；桌面使用 1586x992 横版，移动端使用 941x1672 独立竖版。header 通过扎希拉状态类复用桌面图顶部并覆盖低对比蜡笔纸层。

## Decision (ADR-lite)

**Context**: 当前 Bright School 扎希拉商店背景由 CSS 低频笔触构成，场所识别度不足；现有 UI 已有明确的商品区和立绘区占位。

**Decision**: 先产出独立版本化位图候选；用户确认后，以版本化 WebP 接入扎希拉页面并注册预加载。背景承担场景氛围和空间分区，交互内容继续由现有 DOM/CSS 层承载；header 仅增加页面状态类，不改变交互结构。

**Consequences**: 横竖两张图保持同一风格，但可以分别按真实 UI 结构安排元素与留白。两张运行时 WebP 都必须进入预加载、测试、质量规范与系统设计合同。

## Out of Scope

- 本轮不改商品卡、扎希拉立绘、气泡、钱包或标题文字/字体。
- 本轮不制作人物、文字标牌或可交互元素。
