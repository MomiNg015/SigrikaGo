# 精简和整理角色技能描述

## Goal

减少角色技能说明中重复、冗长的规则文字，把超频信息和可复用规则语义结构化展示；角色详情保持快速扫读，对局中仍能看到完整、上下文明确的技能说明。

## What I already know

* 角色详情中，基础技能和派生技能都要在技能名后显示超频标签，格式暂定为 `超频：X`。
* 对局中查看技能说明时，不展示同款标题标签，而是把超频内容转换为文字，放在说明最上面一行。
* 重复规则可以收敛为特性词；已明确的示例是把“该技能不消耗当前回合落子”收敛为 `【疾走】`，置于技能描述最前面。
* 特性词带下划线、可点击；点击后从触发位置展开悬浮说明，解释该特性词的含义。
* 现有基础技能和派生技能都已有独立的 `costType` / `costValue`，且后台允许编辑超频内容。因此超频展示应读取结构化字段，不能继续从描述字符串中解析。
* 固定超频由 `costType/costValue` 在发动时计入；仇远和千咲当前以 `costValue=0` 为基础值，再由各自技能结算逻辑按移除棋子数量动态增减超频。本需求仍把两者的标签显示为 `超频：0`，动态公式继续保留在正文。
* `freeTurn` 等规则字段虽然存在，但本需求只处理技能描述与展示，不用它们自动生成特性词，也不修改技能功能逻辑。
* 当前角色详情 `src/modals/house/HouseNestedDialogs.jsx` 与对局 `src/room/PlayerInfo.jsx` 都直接渲染原始 `description`。
* 对局已有从点击位置定位、自动上下翻转并限制在视口内的移动端提示层，可作为特性词悬浮说明的交互基线。
* 当前 `effectTags` 只出现在一个前端兜底角色里；本需求不扩展该规则字段，而是解析描述文本中人工写入的 `【特性词】`。

## Assumptions (temporary)

* 特性词的释义是集中定义、可复用的展示词典，而特性词是否出现、出现在哪里由该技能描述文本人工决定。
* 桌面端和移动端都以点击/键盘激活为主；悬停可以辅助预览，但不能成为唯一入口。
* 视觉继续沿用现有明亮校园主题和技能详情层级，不引入新的通用设计体系。
* 超频标签和特性词同时覆盖基础技能与派生技能。

## Open Questions

* 无；等待用户确认最终需求。

## Requirements (evolving)

* 建立可扩展的通用特性词体系，并审阅当前全部基础技能和派生技能；由 AI 整理候选词，但只有经用户逐项确认的词才会转换。
* 超频展示必须以结构化技能数据为唯一事实来源。
* 动态超频技能仍按结构化基础值显示标题标签；仇远、千咲显示 `超频：0`，实际按棋子增减的算法继续保留在正文中。对局首行转换的也是该基础超频值，不把它表述成最终结算值。
* 对局技能说明最上方直接显示独立一行 `超频：X`，不改写为完整句子；第二行再显示 `【特性词】` 和技能正文。
* 对局首行 `超频：X` 使用语义化红色文字，并在现有主题背景上保持足够对比度；不能只靠颜色传达含义，文字标签本身必须保留。
* 角色详情中技能名后的 `超频：X` 使用红色文字、低饱和浅红背景和细边框的小标签；对局首行仅使用红色文字，不增加标签底板。
* 特性词只由描述中人工写入的 `【词】` 标记触发，不根据 `freeTurn`、`passive`、`effectType` 等技能规则自动推导。
* `【】` 语法专用于特性词；现有长离技能开头的条件句要收敛为一个两字特性词，普通条件说明不再使用 `【】`。
* 长离的负面发动限制特性词确定为 `【禁先】`；长离同时具有 `【疾走】`，因此描述展示必须支持开头连续出现多个特性词。
* 多个特性词严格按描述文本中的书写顺序展示，程序不重新排序；文案约定限制词在前、增益词在后，长离写作 `【禁先】【疾走】`。
* 娜波摩技能描述开头的“被动技。”改为 `【被动】`，点击后解释被动技能无需玩家主动发动。
* 爱弥斯派生技能“远航星”开头的“派生技”改为 `【派生】`，点击后解释该技能需要由其他技能或对局状态生成。
* 特性词说明必须集中维护，同一词在所有角色和所有展示面含义一致。
* 特性词词典由后台管理并持久化，管理员可以新增词条、修改名称与释义；前端从服务端读取同一份词典用于角色详情和对局悬浮说明。
* 后台保存词条后立即刷新后台列表；后续新打开或刷新后的玩家页面读取最新词典。已经打开的角色详情和进行中的对局不接收实时推送，刷新或重新进入后再更新。
* 后台侧边栏新增独立的“特性词”主导航，词典管理不嵌入角色编辑器；页面提供词条列表、新增、编辑、引用查看和受保护删除。
* 基础技能和每个派生技能描述框旁提供“插入特性词”选择器；选中词条后在当前光标位置插入 `【词】`，并恢复描述框焦点。仍允许手动输入，已在同一描述中引用的词条不重复插入。
* 重命名特性词时，服务端必须在同一事务中精确替换所有基础技能描述和派生技能描述中的 `【旧名】`；删除仍被引用的词条时必须拒绝，并返回引用它的角色与技能列表。
* 保存技能描述时，所有 `【词】` 必须命中已存在的特性词词典，且同一描述中不得重复引用同一词条；未知或重复引用时阻止保存并给出明确错误。合法词条不要求位于开头或彼此连续。
* 特性词名称去除首尾空白后允许 1–8 个任意字符，但不得包含 `【` 或 `】`，并且名称必须唯一；首批 `疾走 / 禁先 / 被动 / 派生` 仍统一使用两字名称。
* 本次纳入词典的内容限于技能性质或发动限制；`隐藏手`、`喷涂棋子`、`禁入点` 等正文规则名词不纳入词典。但合法 `【特性词】` 可以出现在描述任意位置，也可以被普通文字分隔。
* 技能正文采用保守迁移：只删除已经由超频标签或确认特性词替代的重复句，并插入相应 `【词】`；其余核心规则文案不润色、不重写，由用户后续自行编辑。
* 特性词必须具备明确的点击态、键盘焦点态和触屏可操作区域。
* 悬浮说明从触发点建立空间联系，同时不得超出视口或遮住后无法关闭。
* 悬浮说明顶部显示 `【特性词】`，下方显示释义，并通过箭头或明确的空间方向指向触发位置；不提供独立关闭按钮。
* 特性词仅在点击、轻触、Enter 或 Space 激活时打开悬浮说明；再次激活同一词、激活其他词、点击外部或按 Escape 时关闭或切换。桌面悬停只提供视觉反馈，不自动打开说明。
* 移动端从技能说明层点击特性词时，原技能说明保持可见，词条说明作为更高层的小悬浮窗锚定在触发词附近；点击外部或按 Escape 时优先关闭最上层词条说明，不连带关闭底层技能说明。
* 每个 `【词】` 作为不可拆分的行内按钮自然参与换行，保留可见焦点；辅助技术读出词名、可点击状态和展开状态，悬浮说明通过语义关联到触发词。
* 玩家端词典加载失败或历史数据包含未知 `【词】` 时，完整描述仍以普通文字显示；页面、角色详情和对局不得因此报错或隐藏正文。
* 原始长描述中被结构化展示替代的重复文字应删除，避免同一信息重复出现。
* 一次性迁移只处理可精确识别的内置基础/派生技能片段：固定 `超频：X`、免落子原句、长离原条件括号、娜波摩“被动技”和远航星“派生技”；其余文字保持原样，无法识别的变体跳过而不是猜测改写。

* Tests added/updated for base skills, derived skills, dynamic overclock, keyboard/touch interaction and tooltip positioning.
* Lint, typecheck and relevant frontend/server tests pass.
* `docs/system-design.md` and the relevant `docs/system-design/` chapter record the structured skill-copy contract.

* Default/fallback/admin snapshot descriptions are migrated so structured facts are not duplicated in prose.

## Out of Scope (explicit, temporary)

* 不修改任何技能的实际规则、数值结算、使用次数或演出。
* 不新增或改变决定技能行为的数据字段，不让特性词反向驱动技能逻辑。
* 特性词词典可以新增独立的文案内容模型，但不得与技能结算、可用性或回合行为建立驱动关系。
* 不重做角色详情或对局玩家信息卡的整体视觉结构。
* 不改写未被超频标签或特性词替代的技能核心正文，不统一所有技能的语气、句式或标点风格。
* 不建立正文行内术语系统，不把规则名词批量转换为可点击词条。
* 不做特性词导入导出、多语言、别名或角色后台实时渲染预览。
* 不向已经打开的玩家页面实时推送词典变更。

## Confirmed Trait Glossary

* `疾走`：发动该技能不消耗当前回合落子。
* `禁先`：对手尚未在本局成功发动过主动技能时，具有该特性的技能无法发动。
* `被动`：无需玩家主动发动，满足其技能条件时自动生效。
* `派生`：该技能不是角色初始持有的常驻技能，需要由其他技能或对局状态生成后才能使用。

## Technical Approach

* 新增独立的特性词文案模型，使用稳定 ID 与唯一显示名称，词条不参与技能规则或结算。
* 提供玩家只读词典接口和管理员 CRUD 接口；管理员重命名在事务中同步替换基础技能描述及 `params.derivedSkills[]` 内的派生技能描述，删除前扫描并返回引用位置。
* 提供共享描述解析与渲染组件：按原文顺序拆分所有合法 `【词】`，未知词安全退化为普通文字；角色详情和对局复用同一组件与词典。
* 角色详情从现有 `costType/costValue` 生成技能名后的超频标签；对局从当前生效技能生成红色 `超频：X` 首行。
* 特性词说明使用视口级定位层，从触发点计算上下放置与水平钳制；移动端允许叠加在技能说明层上，Escape 与点外部按最上层优先关闭。
* 后台新增独立“特性词”导航页；角色基础/派生技能描述框加载词典选择器并在当前选区插入标记。
* 默认内容加入四个初始词条并执行幂等、精确匹配的一次性描述迁移；fallback、部署快照和数据库现有内置内容保持一致。

## Decision (ADR-lite)

**Context**：技能描述同时承担规则正文、固定超频和重复行为说明，导致多个展示面文案冗长且容易漂移；用户还需要在后台持续编辑描述与词典。

**Decision**：超频继续读取现有结构化字段，仅用于展示；特性词采用描述内 `【词】` 引用和独立后台词典，名称变更事务化级联到描述，但词条绝不驱动技能功能。

**Consequences**：文案可独立演进且角色详情/对局复用同一释义；代价是重命名需要跨基础技能和派生 JSON 做原子更新，并需要对未知历史词条提供安全降级。
