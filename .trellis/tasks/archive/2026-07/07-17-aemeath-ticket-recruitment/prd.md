# 爱弥斯纪念券招募获取方式

## Goal

将爱弥斯从初始角色改为一条具有叙事演出的专属获取链路：新用户注册后收到“飞行雪绒歌友会”的纪念券邮件，领取道具后在招募界面触发专属 999 分钟倒计时与爱弥斯像素小人演出，最终必定招募到爱弥斯。

## What I already know

* 当前 `User.ownedCharacters` 默认包含 `sigrika,denia,aemeath`，公开资产投影也会把 `AVAILABLE_CHARACTER_IDS` 中的角色强制视为已拥有，因此“移出初始角色”需要同时处理数据库默认值与资产投影规则。
* 注册当前在 `server/authRoutes.js` 中直接创建用户并立即返回登录响应；邮箱已有单用户邮件、发件人、道具附件、领取入仓和未读/可领取角标能力，可以复用现有模型与领取事务。
* 招募已有共享道具目录、仓库库存、一次仅一个进行中任务、开始时决定结果、服务端 `readyAt`、客户端倒计时、领取结果和开发环境快进到 5 秒的完整链路。
* 现有普通招募时长为全局 5 分钟；专属纪念券需要按道具覆盖时长、固定候选与固定成功结果，并增加客户端专属演出状态。
* 玩家端以竖屏移动端为主要适配目标；后台管理界面无需考虑移动端。

## Placeholder Asset Contract

* 爱弥斯小人首版复用本机已安装的 `Pink Cyber Angel` 桌宠 WebP 精灵图集作为临时素材，不把它视为最终美术。
* 精灵演出从图集选择 `running-right` 行组成飞入循环，抵达倒计时上方后切换 `waving` 行完成一次招手并停留；仍保留独立动态 WebP 资源槽，后期可以不改时间线和状态机直接替换。

## Implementation Dependency

* 实施时若仍缺少 `ELEVENLABS_API_KEY`，专属音效生成需要先补齐环境依赖。

## Requirements

* 新注册普通用户不再初始拥有爱弥斯。
* 新获取链路只对功能上线后注册的普通账号生效；所有存量账号继续保留已经拥有的爱弥斯，不回收角色，也不补发纪念券邮件。
* 新用户注册成功后获得一封发件人为“飞行雪绒歌友会”的邮件。
* 邮件标题必须为“飞行雪绒演唱会纪念奖品”。
* 邮件正文必须为：“感谢您参加我们前天举办的飞行雪绒演唱会活动。这是这次活动您抽到的奖品，请收下！希望以后也和我们一起支持飞行雪绒哦~”。
* 邮件附件为道具“飞行雪绒纪念券”×1。
* 玩家邮箱详情中的道具附件必须显示物品图标/图片、玩家可见中文名称和数量，不得把 `attachmentItemId` 等内部英文 ID 当作附件名称显示。
* 玩家端不出售纪念券，商城不可见、不可购买；新用户欢迎邮件是常规玩家获取渠道。后台管理员仍可在邮件附件中手动补发纪念券，用于客服恢复、测试或未来活动。
* “飞行雪绒纪念券”的仓库说明文案严格为：“从飞行雪绒歌友会那里收到的特殊的奖品。上面的儿童画是怎么一回事呢？”不在该描述后追加用途说明；“仅可在招募中使用”由仓库的用途标签与禁用使用状态表达。
* 邮件不会自动打开；主界面邮箱入口按现有规则显示未读/可领取角标。
* 新用户关闭、完成或跳过新手引导后，弹出一次纯提示 Toast，文案严格为“你有收到新的邮件！”。Toast 不可点击、不包含操作按钮，必须晚于新手引导退出，不能被引导弹窗遮挡或同时出现。
* 领取附件后，道具进入仓库并可见；仓库中不可直接使用，只能在招募界面使用。
* 玩家拥有纪念券时，招募底部道具选择行在现有两种普通道具按钮之间额外插入纪念券按钮；按钮使用冰蓝、粉、紫、金黄、薄荷绿缓慢横向流动的全息渐变，并叠加轻微扫光，文字和数量位于明亮、稳定、高对比度的内层，不得呈现为黑色或深色块。没有纪念券时完全不渲染该按钮、不保留空位。
* 若玩家已经拥有爱弥斯但仍持有纪念券，中央纪念券按钮继续显示但不可启动招募，并复用普通招募无候选对象的标准提示：“好像已经没有可以用该道具招募的角色了”。服务端即使收到请求也必须拒绝且不消耗纪念券。
* 使用纪念券开始招募后，倒计时初始显示为 999 分钟，并暂时锁定用户操作。
* 从纪念券扣除并成功创建任务开始，到光芒渐隐完成为止，锁定整个应用的用户交互：不可关闭招募弹窗、按 Escape、点击遮罩、操作招募控件或点击底层主界面。
* 倒计时与整段动画并行且全程持续运作，不因暗场、飞入、发光、全屏光芒或渐隐暂停。
* 演出使用均衡时间线：`0–3.2s` 从 `999:00` 正常递减、锁屏并持续渐暗；`3.2–5.2s` 小人从左侧界外向右飞入，沿每次一致的固定编排不规则上下起伏轨迹逐渐减速；`5.2–5.8s` 在倒计时正上方悬停、招手并发光；`5.8–6.25s` 光芒必须从小人停驻/原地跳动的位置扩散并覆盖整个界面，不能改从视口中心凭空出现。
* 暗场以深色半透明遮罩压低原界面；爱弥斯悬停光晕和全屏光芒采用冷白主光，边缘混合冰蓝、淡粉与浅紫，峰值接近白色。
* 在 `6.25s` 全屏光芒峰值时，最上层光芒遮罩必须达到完全不透明，先完整盖住爱弥斯小人和倒计时；随后只在遮罩之下、同一换幕点立即移除像素小人，并把倒计时从当时的 998 分钟段切换到 `00:05` 后继续递减。用户不能看见小人消失或数字大幅跳变，只能在 `6.25–7.05s` 光芒渐隐时逐步看到新倒计时；渐隐结束后界面恢复并解除交互锁，此时倒计时约剩 4 秒。
* 新创建演出的 11.25 秒玩家展示期限从客户端收到开始响应时计算，避免移动端网络/服务端响应耗时提前吃掉 5 秒尾段；展示倒计时归零时必须在同一渲染节拍直接进入“瞧瞧有没有新部员！”阶段，不得先显示 `00:00` 再等待一次网络刷新。服务端原始 `readyAt` 仍是领取权限的最终校验，且开始请求早于客户端展示期限，因此不能提前领取。
* 爱弥斯专属演出不因 `prefers-reduced-motion` 而缩短、跳过或改为静态版本；所有用户均播放完整轨迹和完整时间线。
* 光芒使用单次连续扩散与渐隐，不使用快速反复闪烁或频闪。
* 专属演出进入暗场时用 350ms 将当前 BGM 平滑压低到玩家原设定音量的 15%；飞入阶段与全屏光芒阶段各使用独立专属音效槽；光芒渐隐结束时用 500ms 恢复原音量，刷新、断线、切后台、组件卸载等任一中断路径也必须恢复，不能留下永久低音量状态。
* 首版生成两段可替换的专属非循环音效：约 2 秒的轻盈像素飞行掠过声，以及约 1 秒的冰晶舞台闪光声。音频不得包含人声、音乐旋律或快速重复冲击，并使用稳定资源路径接入。
* 领取爱弥斯结果时继续沿用现有招募成功音效。
* 若专属演出因刷新、断线或页面切到后台而中断，玩家回来后不重播、不补播演出，也不继续等待原倒计时；该任务直接进入现有“瞧瞧有没有新部员！”阶段，由用户手动点击后才领取并展示爱弥斯。
* 纪念券招募必定产出爱弥斯，不进入普通随机候选、失败率或未回应返券逻辑。
* 爱弥斯结果页文案严格为：“爱弥斯，回应粉丝的期待，闪亮登台！嗯？是想让我加入围棋部吗？哼哼哼，也好，就让你们见识一下我的实力吧！”
* 同一玩家仍只能存在一个进行中的招募任务。
* 共享招募道具定义增加最小专属招募元数据，包括固定结果角色、专属展示时长和演出 ID；服务端复用同一招募任务/库存/领取骨架，客户端按演出 ID 路由到爱弥斯演出。
* 本次只实现爱弥斯的专属演出，不建设可视化编排器或完整通用演出 DSL。
* 首版为“飞行雪绒纪念券”图标与爱弥斯小人使用临时占位图，不在本任务内制作最终美术。
* 纪念券和爱弥斯小人都必须通过稳定、独立的图片资源槽渲染；当前桌宠精灵图集与后期动态 WebP 使用可切换的素材模式，替换正式动态 WebP 时无需修改招募状态机、布局或演出时间线。

## Acceptance Criteria

* [ ] 新用户注册响应及重新登录后的资产均不包含爱弥斯，其他初始角色符合现有产品约定。
* [ ] 部署升级不会删除、隐藏或重置任何存量账号已经拥有或正在使用的爱弥斯，也不会向存量账号补发纪念券邮件。
* [ ] 每个符合条件的新账号恰好收到一封标题为“飞行雪绒演唱会纪念奖品”、指定发件人、正文和纪念券 ×1 的邮件，重复登录不会重复发放；邮箱详情以券图标/图片、中文名称和数量展示附件，不显示内部英文 ID。
* [ ] 新手引导仍在显示时不出现新邮件 Toast；通过关闭、完成或跳过任一路径退出后出现一次“你有收到新的邮件！”，该 Toast 不可点击、无按钮，邮箱角标可见且邮箱不会被强制打开。
* [ ] 纪念券领取具有事务幂等性，重复点击不会重复增加库存。
* [ ] 玩家商城及其搜索/分类中不出现纪念券；后台邮箱附件选择仍可找到并发放该道具，领取后进入同一库存与招募链路。
* [ ] 仓库正确展示纪念券数量、图标和“仅可在招募中使用”的禁用状态。
* [ ] 仓库中的纪念券描述逐字显示“从飞行雪绒歌友会那里收到的特殊的奖品。上面的儿童画是怎么一回事呢？”，用途提示与描述分离。
* [ ] 只有库存数量大于 0 时，招募道具行中央才显示五彩动态纪念券按钮；桌面与竖屏移动端均不溢出。
* [ ] 已拥有爱弥斯且仍持券时，纪念券可见但无法启动，界面复用“好像已经没有可以用该道具招募的角色了”；并发或绕过客户端直接请求也不会创建任务或扣券。
* [ ] 动态五彩背景提供 `prefers-reduced-motion` 静态降级，且不会降低按钮文字、数量与焦点状态的可读性。
* [ ] 开始纪念券招募会原子扣除 1 张券、创建固定爱弥斯结果任务，并以 999 分钟状态进入专属演出。
* [ ] 演出按 `0–3.2s` 从倒计时出现起持续渐暗、`3.2–5.2s` 飞入、`5.2–5.8s` 悬停招手发光、`5.8–6.25s` 全屏光芒、`6.25–7.05s` 渐隐解锁执行；从任务创建成功到渐隐结束，关闭按钮、Escape、遮罩、招募控件与底层界面均不可操作，也无法重复提交。
* [ ] 倒计时在动画全程每秒更新：从 `999:00` 连续递减，在 `6.25s` 光芒峰值切换为 `00:05` 后继续递减，渐隐期间不冻结、不重置；移动端弱网下仍在演出结束时保留约 4 秒，并在展示期限归零的同一节拍进入 ready，不停留在 `00:00` 等待网络刷新。
* [ ] 光芒从爱弥斯小人停驻中心开始扩散，而不是从视口中心出现；峰值时最上层遮罩完全覆盖整个视口，爱弥斯小人卸载与倒计时跳变均发生在不透明遮罩之下，任何可见帧都不会暴露消失过程或从 998 分钟段跳到 5 秒的数字变化。
* [ ] 小人使用 `Pink Cyber Angel` 图集中的右飞行动作流畅进场，抵达后切换招手动作；从左侧界外完整进入，沿不规则上下起伏路径移动并准确停在不同桌面/竖屏尺寸的倒计时正上方，不被弹窗或视口裁切。
* [ ] 固定飞行路径每次播放一致，使用 `transform` / `opacity` 等合成友好属性实现，不依赖运行时随机数。
* [ ] 开启 `prefers-reduced-motion` 时仍播放同一完整专属演出；演出不存在高频闪烁，仅有一次连续光芒扩散与渐隐。

* [ ] BGM 在暗场开始后 350ms 内降至原设定的 15%，正常渐隐结束后 500ms 内恢复；恢复值来自演出前实际播放音量，不覆盖玩家设置。
* [ ] 两段专属音效时长、起止点和峰值分别对齐 `3.2–5.2s` 飞行阶段与 `5.8–6.25s` 光芒扩散/峰值，不循环、不含人声、不产生刺耳频闪式重复冲击。

* [ ] 领取结果后的结果卡逐字显示“爱弥斯，回应粉丝的期待，闪亮登台！嗯？是想让我加入围棋部吗？哼哼哼，也好，就让你们见识一下我的实力吧！”。
* [ ] 普通招募道具的 5 分钟、概率、保底、失败返券及开发快进能力不受影响。
* [ ] 新增专属券时可以通过共享道具元数据复用固定结果与专属时长骨架，无需复制普通招募事务逻辑；未知演出 ID 有安全降级。
* [ ] 刷新、断线或切后台打断专属演出后，任务直接进入“瞧瞧有没有新部员！”阶段，不重播演出、不继续 999 分钟或 5 秒倒计时；只有用户点击后才领取并展示固定爱弥斯结果。
* [ ] 相关后端、前端、移动端、可访问性与回归测试通过。
* [ ] 临时纪念券与爱弥斯小人占位图在本地预览中尺寸、透明边界和动画锚点正常；后续用正式 WebP 或动态 WebP 替换后仍可沿用同一布局和演出控制。
* [ ] 同步更新 `docs/system-design.md`、相关分篇，并运行 `npm run docs:system-design`。

## Technical Notes

* 注册入口：`server/authRoutes.js`。
* 初始资产与兼容投影：`prisma/schema.prisma`、`server/userAssets.js`。
* 邮箱领取链路：`server/mailbox.js`、`server/mailboxRoutes.js`、`MailboxMessage`。
* 招募领域：`src/shared/recruitment.js`、`server/recruitment.js`、`server/recruitmentRoutes.js`。
* 玩家招募界面：`src/modals/RecruitmentModal.jsx`、`src/modals/recruitment/useRecruitmentCatalog.js`、`src/styles/commerce/recruitment/`、`src/styles/mobile-adaptive/phone-recruitment.css`。
* 当前开发环境已有通用“快进到 5 秒”接口；正式专属演出不能依赖开发开关，且倒计时压缩必须由服务端授权并持久化。
* 该需求改变注册运行行为、资产体系、邮件附件、招募逻辑与主题样式，实施时必须同步系统设计文档。
* 当前 `server/shop.js` 会把 `RECRUITMENT_ITEMS` 中每个道具自动创建为启用、可购买商品；纪念券需要显式的商店可用性元数据，不能只把它加入共享目录后依赖默认映射。
* 新手引导正常完成、关闭/跳过和教学对局回流目前经过不同回调；新邮件 Toast 需要统一的退出事件与服务端一次性确认，不能只挂在 `onComplete`。
* 当前 BGM ducking 只根据语音播放计数使用固定衰减；专属演出需要可释放的命名 duck 请求、15% 目标倍数及自定义 350ms/500ms 斜坡，并兼容 Web Audio 与 HTMLAudio fallback。

## Technical Approach

* 注册使用单一服务端事务创建新用户及其专属欢迎 `MailboxMessage`，成功后再进入现有登录响应；邮件唯一性通过与用户的一对一欢迎奖励标识或等价唯一约束保证，而非登录时重复补发。
* 新增数据迁移先把爱弥斯固化进所有上线前账号的真实资产，再将新用户默认与强制可用角色集合改为只含现有其他初始角色，保证存量账号不掉角色、新账号不再继承爱弥斯。
* 专属任务开始时即在服务端固定结果为爱弥斯，并把领取校验 `readyAt` 设为请求开始后约 11.25 秒；客户端收到新任务时另建同长度的玩家展示期限，前 6.25 秒显示从 999 分钟递减的戏剧化计时，峰值后切换为本地展示期限剩余 5 秒，并在归零时直接进入 ready。服务端期限开始得更早，领取接口仍以服务端 `readyAt` 校验，因此弱网不会缩短演出尾段，也不会放宽领取权限。
* 客户端仅把“本组件刚刚成功启动的任务”视为可播放首演；重新挂载发现未完成的专属任务、页面隐藏或网络中断时，请求服务端立即把任务置为 ready，并进入“瞧瞧有没有新部员！”阶段。
* 专属演出使用独立的全视口交互遮罩和语义阶段状态机；动画只消费服务端给出的演出 ID/时间参数，固定结果与库存事务仍留在现有招募服务。

## Decision Log

### 存量账号处理

* **Decision**：仅更新上线后新注册的普通账号进入纪念券获取链路；存量账号保留爱弥斯且不补发邮件。
* **Rationale**：避免回收已获得角色、破坏当前选择或重复发放对已拥有角色无意义的专属券。

### 新邮件提示时机

* **Decision**：欢迎邮件不自动打开；邮箱显示现有角标，并在新用户关闭、完成或跳过新手引导后弹出一次“你有收到新的邮件！” Toast。
* **Rationale**：既明确告知奖励到达，又避免新手引导与邮箱弹窗争抢前台焦点。

### 邮件标题

* **Decision**：使用“飞行雪绒演唱会纪念奖品”。
* **Rationale**：直接对应演唱会活动和纪念券附件，便于新用户理解邮件用途。

### 专属演出交互锁

* **Decision**：演出期间锁定整个应用界面，直到全屏光芒渐隐完成后统一解锁。
* **Rationale**：保证 999 分钟到 5 秒的剧情转折完整呈现，并防止关闭弹窗、重复提交或穿透操作造成状态错乱。

### 演出中断恢复

* **Decision**：刷新、断线或切后台均视为演出中断；返回后直接进入现有“瞧瞧有没有新部员！”阶段，不再补演出，仍需用户点击揭晓。
* **Rationale**：避免重复锁屏与演出状态错位，让中断后的玩家可以立即继续领取固定结果。

### 新美术资源与后期替换

* **Decision**：首版只接入临时占位图，不生成正式美术；纪念券与爱弥斯小人均使用独立图片资源槽，后期可直接换成 WebP，爱弥斯小人允许动态 WebP。
* **Rationale**：先完成可靠的业务与演出骨架，并将最终素材与业务状态机解耦，避免正式美术尚未确定时阻塞功能实现。

### 专属招募扩展边界

* **Decision**：本次实现爱弥斯专属体验，同时在共享道具定义中保留固定结果、专属展示时长和演出 ID 等最小数据驱动扩展点。
* **Rationale**：避免把特殊业务散落硬编码到前后端，又不为尚未出现的其他角色提前建设完整演出框架。

### 爱弥斯入场方向

* **Decision**：从左侧界外向右飞入，沿不规则上下起伏路径减速，停在倒计时正上方。
* **Rationale**：保留明确的横向进场阅读方向，同时用非机械起伏体现飞行感。

### 不规则轨迹

* **Decision**：使用一条固定编排、每次一致的不规则起伏路径，不运行时随机。
* **Rationale**：确保停靠锚点、移动端边界和视觉节奏稳定，同时保留非机械飞行感并便于回归测试。

### 演出时间线与倒计时

* **Decision**：采用约 7.05 秒的均衡演出时间线；从 `999:00` 出现的第一帧起到小人进场持续渐暗。倒计时全程持续运行，在 6.25 秒光芒峰值瞬间切为 5 秒后继续递减，渐隐不暂停，演出结束后仍等待服务端倒计时自然归零才进入 ready。
* **Rationale**：提前铺垫小人登场并用连续运行的数字保持“招募正在进行”的时间感；演出播放完毕不等于招募计时结束，避免提前跳到结果入口。

### 爱弥斯像素小人动作素材

* **Decision**：首版复用已安装 `Pink Cyber Angel` 的 8×9 WebP 图集，飞入阶段播放 `running-right` 八帧循环，抵达后播放 `waving` 四帧单次动作并停在末帧；同时保留动态 WebP 回退渲染路径。
* **Rationale**：现有图集已包含一致造型、透明边界与完整动作帧，可在不生成新美术的情况下让演出从静态贴图升级为连续动作，并给后期正式动图留出直接替换通道。

### 减少动态效果设置

* **Decision**：爱弥斯专属演出忽略 `prefers-reduced-motion` 的缩减请求，始终播放完整轨迹与时间线；但禁止高频频闪。
* **Rationale**：该演出是本获取流程的核心叙事内容，产品选择保持所有用户体验一致，同时以单次连续光芒替代反复闪烁控制风险。

### 光芒配色与换幕遮罩

* **Decision**：使用冷白主光与冰蓝、淡粉、浅紫边缘；光芒峰值形成全视口完全不透明的白色换幕遮罩，在遮罩下原子式隐藏小人并把倒计时切换为 5 秒。
* **Rationale**：色彩呼应飞行雪绒与爱弥斯，同时用视觉遮挡隐藏角色卸载和倒计时大幅跳变，避免用户看到突兀的 DOM/状态切换。

### 已拥有爱弥斯时的纪念券

* **Decision**：仍显示纪念券按钮，但不可启动；复用普通招募标准提示“好像已经没有可以用该道具招募的角色了”，服务端拒绝且不扣券。
* **Rationale**：不让异常来源的道具凭空消失，也避免重复演出、无效消耗或重复角色奖励。

### 纪念券按钮视觉

* **Decision**：使用冰蓝、粉、紫、金黄、薄荷绿缓慢横向流动的全息渐变，叠加轻微扫光，并用高对比度内层承载文字和数量。
* **Rationale**：满足动态五彩要求，同时保持按钮信息、选中态和焦点态持续可读，避免色块跳变或粒子闪烁喧宾夺主。

### 纪念券仓库说明

* **Decision**：使用“从飞行雪绒歌友会那里收到的特殊的奖品。上面的儿童画是怎么一回事呢？”。
* **Rationale**：保留奖品来源和儿童画悬念；使用限制由独立 UI 状态表达，不破坏道具叙事口吻。

### 爱弥斯招募成功文案

* **Decision**：使用“爱弥斯，回应粉丝的期待，闪亮登台！嗯？是想让我加入围棋部吗？哼哼哼，也好，就让你们见识一下我的实力吧！”。
* **Rationale**：以舞台报幕承接飞行雪绒粉丝语境，再自然转入爱弥斯本人接受围棋部邀请的台词。

### 专属演出声音结构

* **Decision**：演出期间压低当前 BGM，为飞行和全屏光芒预留独立专属音效；结束或中断时恢复 BGM，领取结果继续使用现有成功音效。
* **Rationale**：让视觉高潮拥有清晰的听觉层次，同时复用现有音频设置和结果反馈，避免演出结束后污染全局播放状态。

### 专属音效来源

* **Decision**：通过 `sound-effects` 技能生成约 2 秒飞行掠过声和约 1 秒冰晶舞台闪光声，使用稳定资源路径并允许后期替换。
* **Rationale**：专属音效能与演出节拍精确匹配，且独立资源槽不会把临时素材耦合进状态机。
* **Dependency**：当前环境未配置 `ELEVENLABS_API_KEY`；实施时必须先验证依赖，缺失时明确报告并保留已完成的音效槽/混音逻辑，不得伪造生成结果。

### BGM ducking

* **Decision**：暗场开始时用 350ms 将 BGM 压低到原音量 15%，光芒渐隐结束时用 500ms 恢复；异常中断也必须恢复。
* **Rationale**：接近静音的背景让专属飞行与闪光音效形成舞台焦点，同时用渐变避免硬切造成听觉突兀。

### 纪念券发放渠道

* **Decision**：玩家端只通过新用户欢迎邮件常规获取，不进入商店；后台管理员保留手动邮件补发能力。
* **Rationale**：维持活动奖品的专属性，同时保留客服恢复、测试和未来运营所需的安全补发通道。

### 新邮件 Toast 交互

* **Decision**：Toast 仅显示“你有收到新的邮件！”，不可点击且不提供按钮。
* **Rationale**：保持现有 Toast 模型和简洁提示，邮箱入口继续由清晰的未读/可领取角标承担。
