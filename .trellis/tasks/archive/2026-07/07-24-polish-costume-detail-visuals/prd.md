# 修正服装详情标签价格与配色

## Goal

修正残星会服装详情中的标签可读性、价格与购买按钮重叠，以及浅色组件规则与深红背景不协调的问题，让详情信息在桌面和竖屏移动端都清晰、稳定。

## What I already know

- 当前分支为 `codex/frontend-chores`，任务开始时工作区干净。
- 截图中的标签文字几乎不可见，原因是服装标签与通用 `.costume-detail-copy span` 颜色规则发生覆盖。
- 价格当前位于购买按钮内部，窄宽状态下按钮文字被拆成逐字竖排，并与价格重叠。
- 服装数据包含 `characterSlug`，内置角色显示名可从 `src/shared/characters.js` 的 `CHARACTERS` 映射。
- 服装详情使用共享扎希拉结构，但服装专属修饰类应负责深红背景上的颜色和操作区布局。

## Requirements

- 标签内容改为“{角色显示名}服装”；无法解析角色名时回退为“角色服装”。
- 标签使用深色文字配暖金背景，保证在深红详情背景上清晰可读。
- 操作区改为两行：第一行左对齐显示“售价”和“{金额} 金币”，第二行显示完整宽度购买按钮。
- 价格不再作为购买按钮的子元素；按钮文字保持横排且居中。
- 说明区、操作区、标签和按钮使用统一的暖金、酒红与米白层级，避免扎希拉粉色/白色组件规则污染。
- 已拥有、角色未解锁、不可购买、购买中等按钮语义保持不变。
- 桌面与竖屏移动端均无文字重叠、横向溢出或触控目标缩小。
- 后台服装编辑必须使用角色管理接口返回的规范 `id` 作为 `characterSlug` 提交，不得把角色显示名提交给服装接口。
- 后台收到不存在的角色目标时显示中文错误“服装所属角色不存在”。

- [x] 价格独占第一行并左对齐，购买按钮独占第二行。
- [x] 购买按钮文字不逐字换行，价格不与按钮重叠。
- [x] 说明区和操作区在深红详情背景上具有一致的暖金边框、酒红底色和米白文字。
- [x] 购买成功/失败与购买后装扮流程不发生回归。

## Technical Approach

- 在 `CostumeDetailDialog.jsx` 中从共享角色目录解析角色显示名，并将价格拆为独立的语义行。
- 在服装详情 owner CSS 中定义两行操作区与按钮横排约束。
- 在 Bright School 残星会主题文件中使用更精确的服装修饰选择器覆盖共享扎希拉详情颜色。
- 后台服装编辑器从 `character.id` 读取目标标识，并为旧数据形状保留 `character.slug` 回退。
- 不修改玩家服装接口、购买结算或装扮流程。

## Decision (ADR-lite)

**Context**: 服装详情需要复用扎希拉的布局骨架，但不能复用其浅色内容层，也不能把价格塞进购买按钮；后台角色管理接口以 `id` 暴露规范角色标识，服装编辑器必须遵守同一契约。

**Decision**: 保留共享 DOM 骨架，只在服装语义节点上增加角色标签和两行操作结构；颜色由服装 owner 主题规则统一控制。后台服装编辑器从 `character.id` 读取目标标识，并仅为旧形状保留 `slug` 回退。

**Consequences**: 两家详情仍共享响应式布局，但信息密度和配色由各自 owner 管理，后续不再依赖脆弱的通用 `span` 覆盖；后台保存不会再把角色显示名误作 `characterSlug`。

## Out of Scope

- 不修改商店商品列表、看板娘、购买接口或装扮确认流程。
- 不改扎希拉商品详情的视觉样式。
- 不新增角色或服装数据字段。
