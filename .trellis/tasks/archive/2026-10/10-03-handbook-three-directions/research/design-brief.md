# Grounded handbook brief

The real house window has character/decoration bookmarks. Character cards open details and an independent flag changes deployment; detail contains actual skill/derived-skill/overclock, acquisition, voice description, music preview/selection and wardrobe. Current mobile character cards are 88px high with 72px art, hidden names and 30px deployment controls. Those proportions are unsuitable for full standard illustrations.

Captured the real current HomeOnboarding fixture and HouseModal detail on the existing development server; no live account changes. Product Design's saved context is absent. The in-app Browser execution tool is unavailable, so captured via the available Chrome tools. Screenshots were opened directly and supplied to each Image Gen call, together with real Sigrika, Denia and Aemeath smile WebPs. Existing DESIGN.md palette, integration plan and offline student-card prototype were read. Research agent independently checked component behavior and catalog copy.

## Three directions

- Horizontal student-card roster (recommended): clear head/chest crop, consistent name and distinct flag, two or three desktop columns, two mobile columns. Fast scanning; accommodates both standard art and legacy chibi. Details can stay separate and larger.
- Open member dossier: narrow member index, generous full/knee-up artwork and ruled-paper skill reading column. Makes skill reading and individual character presence central; fewer roster members visible. Mobile keeps selection strip and stacks portrait/skill reading.
- Vertical portrait album: spacious head-to-waist photos, names and flags on separate caption footers. Strongest cast presentation; more scrolling. Mobile uses two columns and retains names plus 44px actions.

For all directions keep role/decoration access, explicit current-deployment vs inspection selection, voice/music/wardrobe access and grayscale unavailable members. Never invent levels, affinity, rating, stats or progression. Never cover a face with controls. List expression remains stable; explicit detail expression changes may use the existing nine-expression sets. Actual implementation must reuse exact images and catalog copy, retain costumes/candy/corruption precedence and hidden intelligence, and treat any generated incidental text or generic secondary faces as visual placeholders only.

Images are review artifacts, not implemented UI. Three independent generation calls use the same actual sources and a single desktop screen each. Visible order in the conversation owns numeric option mapping.
