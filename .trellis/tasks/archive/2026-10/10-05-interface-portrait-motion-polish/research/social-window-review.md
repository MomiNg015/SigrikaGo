# Social window review and bounded repairs

## Evidence and production context

Reviewed actual FriendsModal, FriendsOverlays, WatchModal, LeaderboardModal, MailboxModal, HouseReplayDialog and MessageBoardModal with the full styles entry. Temporary probes live under `.tmp/interface-polish/social-review/`; no external data was changed. The fixture uses the same `useModalDismissal` fallback as App. AppOverlays mounts Friends and Watch directly. Therefore the original bare-component Escape failure was not a production dismissal failure: the App fallback already closed those windows. FriendsOverlays renders after the entire main backdrop as a sibling; its confirm, duel and profile sheets are outside the entering `.friends-modal`. No additional portal was needed. Confirm and duel bounds/ancestry were verified 65ms after opening on 320/390/1440.

## Verified defects and final behavior

- Friends main, confirmation and duel sheets now use the existing ModalDialog contract. Closing a nested sheet returns to the originating gear after its former inline action has been removed. If the friend was deleted and that gear no longer exists, focus returns to the main close button. Escape dismisses the active nested sheet; the App fallback remains intact.
- Pending Friends removal previously allowed two synchronous DELETE calls and an unhandled rejection. A synchronous ref guard now allows one request, disables only confirmation, and catches failure through the existing notice callback. The target remains available for retry; cancel/close stay available. Exported ConfirmPanel gains optional `confirmDisabled=false`. UserProfileCard's own blacklist confirmation uses separate controls already driven by `blacklistPending`, so no shared caller flag was missing.
- On 320/390, the final Friends action panel was 12px tall while its buttons were 44px; max scrolling still clipped them. The scoped mobile owner reserves 56px. At widths up to 360, the old row gave a plain name only 26px at 320; a two-row card moves status below the portrait/name. All three legal plain examples (`星炬同学`, `fx2eee94`, `WWWWWWWW`) are fully visible at 320/360, with the wide ASCII example using two lines. Rows are 94px and the gear remains 44px. 390/desktop retain their prior layout. Equipped nameplates retain their existing sizing branch. Ordinary list ellipsis at 390 remains intentional; detailed profiles already expose full names.
- Watch now starts loading when a token is present, so the initially disabled refresh is skipped and close receives focus. Mobile three-row cards previously had a 44px minimum while their children occupied 25+22+14px, plus gaps/padding/border. A scoped 89px minimum contains all fields and prevents adjacent row overlap. Native table scrolling and joining payload remain unchanged.
- Five-digit ranked counters reduced identity width to 0px at 320 and 44px at 390. Both ordinary ranked records and capture scores now sit below identity, preserving counter fonts, rank badges and desktop columns. Ordinary/pinned identity widths are 126/134px at 320 and 176/184px at 390. Ranked cards are at least109px and capture cards93px; all visible fields fit. Existing record text stays on one line.
- Mailbox body long uninterrupted URL text produced 1747px internal horizontal overflow on 320. The shared information-center prose now uses `overflow-wrap:anywhere`. Native reader scrolling, attachment shelf, mobile back focus and busy claim/delete behavior all remain functional. Announcement prose shares the same improvement.
- Feedback's old form had no dialog role, accessible icon-close name or initial focus, and two synchronous submits issued two POSTs. It now uses ModalDialog `as="form"`, title linkage and meaningful close/textarea labels. A ref guard prevents repeated callbacks before React commits disabled state. Its 400-character budget, trimmed API payload, retained content on error and success callbacks are preserved.
- Replay list dense/empty/error states retain native scrolling, last-row reach and Escape/opener return; semantic row controls remain in the existing markup. This probe did not separately test keyboard row activation. No actionable replay layout defect was found.

## Suggested system-design wording

Social and feedback sheets use the shared dialog focus contract, including nested Escape and return to their originating controls. Friends removal and feedback submit use synchronous single-flight guards, preserve failed input/targets for retry, and keep dismissal available. Narrow Friends cards and ranked/capture cards reserve readable identity space without shrinking counters; watch cards contain all three mobile rows; shared information-center prose wraps uninterrupted content within its native reader.
