## Method

The isolated port-5300 fixture imports full `src/styles.css`, actual production components/hooks, `ToastStack`, and production `useModalDismissal`. API requests are intercepted by pathname beginning `/api/`, held, then fulfilled as rejection or success. No database writes or audio/gameplay contract changes occur. The fixture uses real native range changes, native button activation, keyboard Enter/Tab/Shift+Tab/Escape, and coarse-pointer touch coordinates. Authentication removes fixture background controls from navigation while mounted, matching the standalone login screen. ## Authorized repairs

`useWarehouseInventory` synchronously serializes one inventory consumption request with a ref, before any await or React state update. Native disabled state covers all inventory use controls and target choices while that request is active; the target section exposes aria-busy. Its close remains enabled. Rejection releases the guard, allows retry, and uses the existing notice. Success keeps existing inventory/user/effect/story/wallet callback handling unchanged.

Shared `ModalDialog` records the last focused DOM descendant through focus capture, forwarding an existing supplied callback. A layout effect after each commit recovers to the dialog shell only when that prior control becomes native disabled/disconnected and the active element is BODY or that same now-disabled control. Chromium can retain the disabled control during the React layout phase before blurring it; the same-control branch is necessary and was proved by real browser rerun. Another active field, external deliberately moved focus, and a currently active nested portal remain untouched. Tab from the recovered shell selects its first enabled control; Shift+Tab selects its last. This uses no timeout, document-wide capture listener, dialog stack, or exit delay. Existing background-focus/BGM lifecycle remains present.

Warehouse target keeps its existing section classes and geometry through `ModalDialog`, adds a named close/title, and receives the same focus containment and restoration. Its overlay is portaled with the established `.app-shell ?? document.body` pattern and preserves the SSR inline branch. Before the portal, an actual initial target result mounted while warehouse entry translation/scale is active produces a clipped fixed backdrop: first desktop rect approximately (183,78,1069,252) against 1440×900, phone390 approximately (28,65,345,408), phone360 approximately (27,65,315,408). The existing generic warehouse target layer 12 and Bright School layer 80 become the established ordinary nested layer 180, above the parent modal's 160; the intermediate portal-only probe caught real pointer selection falling through to the outer backdrop before this prerequisite was repaired. `nested-backdrop` has no other JSX consumer. No new stacking family, palette, selector, motion timing, or important declaration is introduced.
