# Character portrait integration research

Read-only code research, 2026-10-05. Existing unrelated working-tree changes must be retained.

## Available art and shared owner

- Nine humanoid characters already have transparent 832 × 1216 runtime illustrations: `public/assets/characters/handbook-sprites/{sigrika,denia,aemeath,lynae,mornye,chisa,changli,qiuyuan,nabomo}.webp`. No new generated art is required for these surfaces. `manifest.json` records original PNG source, alpha verification and compression; retain original pixels. Some exports use quality-95 because lossless was larger, so do not claim all files are lossless.
- Baconbits has no humanoid full-body sprite; retain the established mascot portrait. Custom/admin characters and equipped costumes have no guaranteed full-body alternatives and should keep their existing source and framing.
- Sigrika, Denia and Aemeath additionally have full-body story expressions and derived avatar images under `public/assets/characters/story-sprites/`. Their owner, `characterStorySprites.js`, is for explicitly authored appearance/expression selections. Using it for routine player identity would introduce competing appearance semantics and does not cover six other characters.
- `src/shared/handbookPortraits.js:resolveHandbookPortrait` already selects the nine standard illustrations only when the shared resolved source is the canonical or legacy built-in default (or empty). It preserves custom URLs, equipped costumes, Denia candy and Sigrika corruption. It returns `src`, `isStandard`, `width`, `height`, `visibleTop`, per-character `focal`, `headWidth`, `cropWidth`, and original costume `style` for fallback art.
- Reuse this resolver. If integrating battle snapshots, extend its options to forward `costumeSnapshot` (and any explicit `equippedCostumes`) into `characterPortraitImageProps`. Its current implementation accepts only `{ itemEffects, user }`, so directly calling it without extension would lose replay/match costume precedence. The standard-art gate must examine the actual winning costume, including a snapshot whose URL equals the built-in default, rather than only `user.equippedCostumes`.

## Existing precedence to preserve

`src/shared/characterPortraits.js:resolveCharacterPortraitPresentation` chooses costume as `costumeSnapshot ?? equippedCostumes[id] ?? user.equippedCostumes[id]`; Sigrika corruption overrides it; active Denia rainbow chooses costume candy art or animated default candy art; ordinary costume source then wins over `character.portraitUrl`, then `character.portrait`. `src/shared/costumes.js:costumePortraitFrameStyle` preserves bounded scale/translation metadata. Do not rewrite the global square portrait catalog or replace costumes with a default outfit.

## Framing recommendation

Use a small shared presentational component around `resolveHandbookPortrait`, accepting the same identity/effect/costume options plus a bust crop variant and alt text. An overflow-hidden mask and an inner proportional art wrapper can use the existing pupil `focal` and `headWidth` landmarks to make faces readable at small sizes while retaining chest/shoulders. Keep CSS custom properties on the wrapper rather than fighting legacy direct-img `scale` and `translate` resets. Non-standard art uses existing contain/framing, never stretches. Avoid full-body contain in a 164 × 152 dossier mask or 56–68 × 88 phone battle slot: it yields a tiny head.

Keep image errors bounded and recover to the old effective portrait without changing identity/appearance. Selected home and participant battle sprite URLs should join existing relevant preload lists; do not preload every story expression or all owned full-size assets into initial site-entry critical loading. Relevant owners are `src/shared/preloadAssets.js` (login / battle) and `src/shared/assetRegistry.js` (home shell).
