# Batch-one security decisions

- Public username/password registration stays available. The user's personal identity and pending SMS eligibility are not prerequisites for this batch.
- Use a self-hosted, one-attempt PNG challenge layered with credential limits, registration quotas and account/IP login backoff. This adds no external provider account or per-message cost, but is only a modest obstacle to automation/OCR, not managed risk scoring.
- OWASP treats CAPTCHA as defense in depth and recommends layered throttling rather than relying on one IP-only control or account-wide lockout: [Authentication Cheat Sheet](https://cheatsheetseries.owasp.org/cheatsheets/Authentication_Cheat_Sheet.html), [Credential Stuffing Prevention Cheat Sheet](https://cheatsheetseries.owasp.org/cheatsheets/Credential_Stuffing_Prevention_Cheat_Sheet.html).
- Reuse sharp, move it into runtime dependencies, and render raster pixels with the shipped LXGW font. Do not return SVG text or depend on cloud system fonts. APIs checked against [sharp constructor](https://sharp.pixelplumbing.com/api-constructor/) and [output](https://sharp.pixelplumbing.com/api-output/).
- Preserve the existing same-host Nginx deployment; trust loopback proxies only. Distributed instances need shared protection state and a separately verified proxy topology.
- Runtime and development npm audit findings were fixed with compatible lockfile updates plus sharp 0.35.5 / Vitest 4.1.12. No force upgrade. All-dependency audit after installation reports zero known findings; target-host certification is still separate.
- Existing WIP was inventoried and snapshotted to an external temporary directory before editing. Shared docs, CSS inventory and style-entry tests must be committed as task-only deltas. Do not include unrelated UI/theme work.
- Design-hook color warnings in styleContract.test.js are existing positive/negative string assertions about unrelated theme owners, not new rendered colors. This batch adds only the auth-challenge import assertion, so these warnings are contextual false positives; no design or suppression settings are changed.
- Release checks also exposed stale stability selectors: the watch list no longer has mode tabs, profile tabs call the last category 其它, and the result dialog has both return and leave buttons. Update semantic selectors and selected-tab assertions; retain layout, keyboard, data, last-row visibility and replay coverage.
- The retained mobile overflow assertion then found a real 36px table overflow in social details. Fix only the existing 260px minimum-width rule (to 0); preserve the current WIP theme and its column proportions. This is a release-check repair, not a profile redesign.
- Windows keeps the development Prisma DLL loaded. The root aggregate release command fails at client generation with EPERM. Migration and backup checks were run using unchanged verifier scripts and schema in a small isolated code/client copy; their disposable databases and generated engine do not touch the running development service or its database. Remaining build/config/stability/capacity gates run normally against the current working tree.
- Run the final broad check alone: simultaneous cold browser/capacity work caused a Vite startup readiness timeout in e2eIsolation.test.js. The separate HTTP-only proxy fixture had a reproducible scanning/watch timeout and was fixed by disabling unnecessary discovery/watch work, retaining its five-second assertion budget.
- A separate legacy leaderboard migration fixture crossed the generic five-second test limit while replaying every migration with real SQLite disk writes. Set only that integration test to an explicit 15-second budget, retaining all data/order/idempotence assertions. The migration fixture and Vite stdin-lifetime fixture then both passed when run without competing suites.
- A later full run passed 461 files but one server-restart worker exited without delivering its result. The restart test passed in isolation. Review found that this child-owning fixture still installed process-global shutdown hooks, contrary to the existing isolation contract; pass manageSignals=false and track each owned server PID so cleanup cannot delete a database still held by a live child. Do not claim the isolated passing test alone establishes a clean full run.
- The next full unit run passed all 462 files / 3,384 tests. The subsequent snapshot gate found existing authoring changes: an enabled test announcement and nine illustrator labels changed to nai5. Preserve both the local content and committed snapshot. Fix CI reproducibility with an isolated snapshot seed/export check, while retaining the read-only authoring comparison as an explicit release-candidate stage. This avoids accidentally publishing a test announcement or requiring a mutable developer database for CI.
