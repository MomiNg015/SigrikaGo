# 准时宝陪练与吃子挑战赛入口整合

## 当前阶段
实现与验证已完成（2026-10-27）；验证证据见 validation.md。

## 目标
将沙包陪练与吃子挑战赛统一到准时宝窗口，简化选择流程，并让吃子挑战赛拥有独立排行榜入口。

## 用户已明确的要求
- 星炬对弈模式中移除独立的“吃子挑战赛”卡片，入口移入准时宝陪练窗口。
- 精简准时宝窗口，以“沙包陪练”和“吃子挑战赛”两张模式卡片选择玩法。
- 沙包陪练卡片右侧为难度循环按钮：从左至右为纯色图标、等级文字；绿色初级 → 黄色中级 → 红色高级 → 绿色初级循环。
- 等级按钮的颜色由左侧纯色图标表达，右侧显示等级文字；按钮必须保留适当内边距，不能用单独色块或整块彩色背景代替“纯色图标 + 文字”的布局（用户再次强调）。
- 吃子挑战赛卡片右侧为排行榜图标按钮，打开吃子挑战赛独立排行榜；主页面排行榜移除吃子赛选项卡。
- 底部开始按钮文案固定为“START！”，只有模式和角色均已选择才能进入。
- 沙包陪练时，下方西格莉卡立绘与对话维持现状。
- 吃子挑战赛时使用西格莉卡惊讶表情，对话为“随机猜先。在100手内尽可能多地提掉准时宝的棋子吧！吃得越多分数越高！”
- 移动端以竖屏为主，沿用现有窗口与主题体系。

## 已确认的交互决策
- 窗口恢复上次选择的模式和角色；两项均有效时，可直接点击 `START！` 开始（用户选择 C）。
- 首次使用、没有历史记录时，模式和角色都不预选，需要用户手动选择（用户选择 A）。
- 选择记忆沿用当前浏览器 localStorage、按账号隔离的方式，刷新后仍保留；不增加跨设备同步。
- 两种模式共用一个角色选择，切换模式时保留当前角色，不分别记忆（用户选择 A）。
- 点击沙包陪练的难度按钮，循环到下一等级，并同时选中沙包陪练模式；点击吃子挑战赛的排行榜按钮，只打开榜单，不改变当前模式（用户选择 A）。
- 沙包陪练难度首次显示绿色“初级”；之后按账号在当前浏览器记住上次等级，切换模式、关闭窗口或刷新均保留（用户选择 A）。难度有默认值不代表模式已选中，首次模式仍为空。
- 角色选择入口保留在顶部右侧；下方依次为两张纵向模式卡、`START！`、西格莉卡立绘与对话区（用户选择 A）。两张模式卡去掉原有编号和难度描述，仅保留模式名称及右侧按钮。
- 未选择模式时保留西格莉卡默认立绘，对话使用用户指定文案：“今天想找准时宝做什么呢？”。选中模式后切换为对应表情与对话。
- 模式或有效角色尚未选齐时，`START！` 置灰并禁用；两项均有效后亮起并允许开始，不通过点击禁用按钮触发 toast（用户选择 A）。
- 独立排行榜沿用现有吃子赛榜单，保留前三名展示、纪录角色、昵称、段位、提子数和“我的排名”，移除模式选项卡（用户选择 A）。
- 排行榜作为上层窗口叠在准时宝窗口上；关闭后返回原窗口，模式、角色和难度选择保持不变。打开排行榜不要求先选模式或角色。

## 沿用现有行为与实现约束
- 两种模式均沿用随机猜先和现有陪练开始／加载流程。
- 沙包陪练使用记住的难度；吃子挑战赛固定使用现有高级难度，与沙包陪练等级按钮无关。进入吃子赛不覆盖沙包陪练已保存的等级。
- 保持吃子挑战赛现有 100 手限制、计分、成绩有效性与排名规则，以及两种模式现有可用角色范围。
- 模式卡为单选；点击已选中的卡片保持选中。右侧按钮单独处理事件，避免一次点击触发两次操作。
- 记住的角色若已不可用，则作为未选择处理并禁用 START；不自动替换成首页角色或其他角色。
- 本地记忆读取失败、数据损坏或无效时安全回退；写入失败不妨碍当前窗口继续选择和开始。
- 排行榜沿用现有加载、错误和空榜状态；关闭最上层窗口或按 Escape 只退出最上层，焦点返回触发入口，不连带关闭下层窗口。
- 精简后仍保留模式选中状态、按钮焦点样式、文字与图标可访问名称；难度通过文字及颜色共同表达。
- 等级按钮内图标与文字水平排列、垂直居中、不换行；图文间距以 6–8px、上下内边距约 8px、左右内边距约 12px 为初始样式，结合实际渲染调整。三个等级保持相同按钮尺寸，手机触控区域高度至少 44px，避免切换等级造成布局抖动。
- 手机竖屏下右侧按钮可点击，长对话完整显示；短屏可滚动，START、关闭按钮及角色入口可达。
- 只同步受入口迁移直接影响的引导、选择入口与文案，不扩展修改其他对弈模式。

- [x] 顶部右侧角色入口保留；模式卡无原有编号和难度描述；开始按钮准确显示 `START！`。

- [x] 切换模式保留角色；选中吃子赛不改写沙包难度；三种模式状态分别显示约定立绘和完整对话。

- [x] 存储异常、失效角色、空榜、请求失败与窗口嵌套关闭不会导致错误启动、选择串号或误关下层窗口。
- [x] 桌面与手机竖屏完成可视及交互验证，尤其核对长对话、右侧小按钮和嵌套弹窗。

## 实现与验证安排
1. 统一准时宝窗口的选择状态与本地记忆，重排模式卡并接入两种开始参数。
2. 复用现有排行榜数据和展示组件，新增吃子赛独立窗口入口，移除主页对应选项卡。
3. 接入现有惊讶素材，调整模式文案与主题／手机样式；补充选择、记忆、按钮事件及榜单回归用例。
4. 运行相关测试和项目要求的质量检查；同步受影响的系统设计入口／分篇并运行 `npm run docs:system-design`。

## 边界
- 不改玩法规则、排名结算、人机算法与后端鉴权，不增加新难度、跨设备记忆或新角色素材。
- 不重做排行榜视觉体系，不改动其他模式的角色记忆和首页展示角色。
- 现有无关设计样稿、系统设计待提交内容和其他工作区改动保持原状；实现时仅合入本任务需要的文档变更。

## 当前实现调研
- 角色选择已通过 `sigrika-match-characters:${user.id}` 保存在当前浏览器 localStorage，按账号隔离。现有陪练与吃子挑战分别使用 practice／capture 选择槽。
- 当前陪练难度在窗口内默认 beginner（界面称入门），并未随角色存储持久化。
- 现有排行榜已支持吃子赛数据与展示：请求 `/api/leaderboard` 并以 `CAPTURE_CHALLENGE_MODE` 作为 mode 参数，展示前三名、纪录角色、用户名、段位、提子数及我的排名。独立窗口可以复用榜单展示与接口。
- 西格莉卡已有惊讶表情资源 `public/assets/characters/story-sprites/sigrika/surprised.webp`，通过 `storySpriteUrl("sigrika", "surprised")` 解析；现有陪练默认立绘与表情资源同属 Q 版体系，无需新增素材。
- 现有吃子赛入口传入 `difficulty: "advanced"`、`challenge: CAPTURE_CHALLENGE_MODE` 和 `playerColor: "random"`；服务端校验吃子赛必须使用高级难度。共享规则常量 `CAPTURE_CHALLENGE_MOVE_LIMIT` 为 100。
- 主要影响文件：`src/home/HomeScreen.jsx`、`src/home/PracticeDifficultyDialog.jsx`、相关选择状态模块、`src/modals/LeaderboardModal.jsx`、排行榜展示组件、陪练窗口的基础／主题／手机样式及相关测试。接口及素材解析优先复用现有代码。
