# 成就系统与个性化装备 PRD

## 背景

玩家需要一个长期目标系统，用来展示游戏内可达成的成就、发放成就奖励，并让部分成就奖励转化为可展示的个性化装扮。后台需要能够维护成就与成就奖励资产，前台需要在“履历”中进入成就列表和个性化装备界面。

## 目标

- 在“履历”窗口主标题右侧新增“成就”按钮，打开成就窗口。
- 在“履历”中新增“个性化”入口，装备或卸下称号、徽章、用户名背景。
- 成就窗口支持“未达成 / 已达成 / 全部”三类筛选。
- 成就列表展示成就名、成就内容、成就奖励、达成时间；未达成时间留空。
- 未达成成就使用灰色背景，已达成成就使用浅黄色背景。
- 玩家达成成就时，逐条显示醒目的成就 toast。
- 后台新增“成就管理”，支持成就与成就奖励资产的增删改查；删除采用软删除/下架。
- 成就界面、个性化界面必须分别适配桌面端和移动端，并符合当前游戏 Bright School / 纸张 scrapbook 界面风格。

## 非目标

- 不公开展示其他玩家的完整成就列表。
- 不允许后台用自由表达式配置任意成就条件。
- 不把商店或扭蛋可获得的普通资源作为成就奖励。
- 不新增新的视觉品牌或独立设计体系。

## 用户体验

### 履历入口

- 履历标题区右侧新增“成就”和“个性化”两个紧凑按钮。
- 桌面端按钮与现有履历标题、金币胶囊、关闭按钮协调排列，不互相遮挡。
- 移动端按钮允许换行到标题下方或标题操作行，触控区域不小于 44px。

### 成就窗口

- 使用当前弹窗风格：奶油纸面、浅色边框、8px 基础圆角；Bright School 下保持纸张描边和 scrapbook 阴影。
- 顶部为三段式 tab：“未达成 / 已达成 / 全部”。
- 桌面端以四列表格展示：成就名、成就内容、成就奖励、达成时间。
- 移动端以单列卡片流展示：卡片顶部显示成就名和状态，下方显示内容、奖励、达成时间。
- 长文本必须换行，不允许横向滚动。
- 奖励可以显示文本或图片；图片需要稳定尺寸，避免加载跳动。

### 个性化窗口

- 只管理称号、徽章、用户名背景三类可装备成就奖励。
- 桌面端为三列装备槽：称号、徽章、用户名背景。
- 移动端为纵向分段卡片或 accordion，每段包含当前装备预览、可选列表、装备/卸下按钮。
- 用户名背景是横向长条图片，小屏按容器宽度缩放，不遮挡用户名。
- 称号显示在用户名上方；徽章显示在用户名或头像前侧。

### 全站身份展示

- 抽象共享用户身份展示组件，统一渲染称号、徽章、用户名背景。
- 覆盖履历、公开资料、排行榜、好友/社交列表、房间玩家信息、观战列表等用户身份出现位置。
- 他人公开资料只展示已达成数量和百分比，不展示完整成就列表。

### Toast

- 成就达成使用新的 `achievement` tone，比普通成功 toast 更醒目。
- 多个成就同时达成时逐条提示。
- toast 继续使用顶部居中队列，不抢焦点，并支持 `prefers-reduced-motion`。

## 后台管理

- `AdminShell` 新增“成就管理”tab。
- tab 内包含两个子视图：
  - “成就列表”：维护成就名称、内容、条件类型、条件参数、奖励资产、排序、启用/下架状态。
  - “奖励资产”：维护货币、称号、徽章、用户名背景，以及 `source=achievement` 的限定角色、装饰、道具、音乐引用。
- 徽章、用户名背景图片通过后台上传，并复用现有图片安全校验思路。
- 后台桌面端使用表格 + 右侧抽屉表单。
- 后台移动端表格折叠为卡片列表，抽屉改为全屏表单 sheet。
- 表单必须有可见 label、字段级错误、保存中禁用状态。

## 数据与规则

- 新增 `Achievement`：成就名、成就内容、条件类型、条件参数、奖励资产、排序、启用/软删除状态。
- 新增 `UserAchievement`：用户是否达成、达成时间、奖励是否已发放。
- 新增 `AchievementRewardAsset`：奖励类型、名称、文本说明、图片、目标资源引用、来源。
- 新增 `UserAchievementEquipment`：用户当前装备的称号、徽章、用户名背景。
- 新增 `AchievementCounter`：记录上线后才能稳定统计的行为计数。
- 每条成就奖励一个资产。
- 奖励支持：
  - 货币。
  - 称号、徽章、用户名背景。
  - `source=achievement` 的角色、装饰、道具、音乐。
- 角色进入部员手册，装饰进入装饰系统，道具进入仓库，音乐进入角色详情 BGM 选择，货币直接入账。
- 达成成就和发放奖励必须幂等；重复判定不能重复发放奖励。

## 成就判定

- 采用混合判定：
  - 可从现有数据推导的目标支持回溯补发。
  - 无法完整恢复历史的行为从上线后开始计数。
- 第一版内置目标类型：
  - 累计对局数。
  - 累计胜场数。
  - 指定模式对局数。
  - 指定模式胜场数。
  - 段位达到。
  - 积分达到。
  - 拥有角色/装饰/音乐/道具数量。
  - 好友数量。
  - 累计登录天数。
  - 累计购买次数。
  - 累计抽卡次数。
  - 指定角色对局数。
  - 指定角色胜场数。
  - 指定角色胜率；必须配置最低对局数。
  - 触发事件。
- 触发事件使用内置事件下拉，不允许后台手填任意事件 id。
- 首批触发事件至少包含：给达妮娅使用彩虹豆豆跳跳糖触发彩虹眼。

## 接口范围

- 玩家接口：
  - 读取成就列表。
  - 读取可装备奖励。
  - 更新个性化装备。
- 后台接口：
  - 成就列表/创建/编辑/软删除。
  - 奖励资产列表/创建/编辑/软删除。
  - 图片上传。
- 业务入口在登录、对局结算、商城购买、抽卡、道具使用、好友变化等节点调用成就判定。
- 新达成成就随响应或 socket 事件返回前端。
- 启动 schema guard 兼容旧 SQLite。

## 验收标准

- 玩家能从履历打开成就窗口，并按三种 tab 查看成就。
- 玩家能从履历打开个性化窗口，并装备/卸下称号、徽章、用户名背景。
- 桌面端与移动端成就/个性化窗口均可读、可点、无横向溢出。
- 达成成就时逐条显示醒目 toast。
- 后台能创建、编辑、下架成就和奖励资产。
- 成就判定和奖励发放幂等。
- 他人公开资料只展示成就达成数量/百分比。
- 系统设计文档同步更新，并生成 `docs/system-design.html`。

## 验证计划

- 后端：
  - schema guard 幂等创建成就相关表。
  - 成就判定覆盖累计对局、胜场、指定角色胜率、段位/积分、收藏数量、登录天数、触发事件。
  - 重复判定不会重复发奖。
  - 后台 CRUD 校验软删除、来源限制、图片上传、触发事件合法性。
  - 公开资料不泄露完整成就列表。
- 前端：
  - 履历渲染“成就”和“个性化”按钮。
  - 成就窗口桌面表格和移动卡片流正确。
  - 个性化窗口桌面三列和移动纵向布局正确。
  - 装备变更后共享身份展示同步更新。
  - 成就 toast 使用 `achievement` tone。
  - 后台成就管理双视图可渲染和保存。
- 命令：
  - `npm test`
  - `npm run build`
  - `npm run docs:system-design`
