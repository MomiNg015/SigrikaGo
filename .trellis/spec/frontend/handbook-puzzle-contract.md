# Member Handbook Diagonal Portrait Strips

## Scope and signatures

`HouseCharacterGrid` owns the ordinary handbook strips; `LegacyHouseCharacterGrid` owns the existing corrupted presentation. `resolveHandbookPortrait(character, { itemEffects, user })` returns the effective source, costume style, dimensions and a fixed crop focal point. This is a handbook presentation adapter over `characterPortraitImageProps`, not a replacement for the shared portrait catalog. The former polygon-puzzle contract is superseded by the user's ordered strip requirement; the filename remains a historical reference.

`handbookStripPage(characters, page)` preserves input order, clamps the page and returns `{ pages, currentPage, roster }` with at most ten characters. `handbookStripArtStyle(portrait, size, { mobile, expanded, count, index = 0 })` preserves the portrait aspect ratio and keeps desktop width, height and vertical placement independent of preview state. Built-in `headWidth` and pupil `focal` landmarks align the eye line and frame the larger desktop bust. Its head target is `min(width / count * 1.35, height * .38)`, with handbook-only `desktopScale` visual corrections (Qiuyuan 1.1, Nabomo .91). Preview changes the horizontal anchor from 50% to 20% only. Mobile framing alternates its portrait side by absolute catalog index (`currentPage * HANDBOOK_STRIP_PAGE_SIZE + index`) and keeps a headwear-safe expanded bust. Custom/costume sources retain their shared resolver framing; the owned mascot uses its existing alpha bounds. The pure-import `handbook-puzzle.css` entry delegates to bounded `handbook-strip-labels.css` and `handbook-strip-frame.css` owners in that order; motion inventory points to these concrete owners.

## Rendering contracts

- Normal built-in portraits use nine lossless 832x1216 transparent WebP images under `/assets/characters/handbook-sprites/`. Baconbits uses the existing portrait. Equipped costumes, Denia candy, Sigrika corruption and custom URLs retain shared resolver priority and framing. Unknown aspect ratios use `contain`, never stretch.
- Preserve the received catalog order, including backend `sortOrder`; do not maintain a separate portrait order or reorder by ownership. More than ten characters paginate. Empty slots are not interactive.
- Desktop uses one left-to-right row; narrow viewports use one top-to-bottom column with slanted internal paper seams. Keep original artwork upright and proportional, with thin neutral gaps and muted paper/character-color backgrounds. Unowned ordinary strips use alpha-mask gray silhouettes and a question mark. Unowned Baconbits is the explicit exception: no image, silhouette, mask, question mark or real-name metadata; use the achromatic missing-data presentation labelled `暂无情报`. Do not add colored borders or radial shine.
- Fine-pointer hover expands the current strip's width on desktop or height on narrow viewports. Keyboard focus previews the same composition. Desktop image dimensions and eye line remain fixed while the portrait moves horizontally and the lower-right name appears. Mobile portraits alternate left/right starting with the first catalog entry on the left; their larger horizontal names occupy the opposite side in both states. Mobile preserves usable neighboring row heights and allows natural board growth inside the existing handbook scroller. It does not rotate/lift the slice. Reduced motion preserves the final expanded layout and disables animation.
- Names have no badge fill or text background. Scope their typography to the strip owner: the requested WuWa Lahai-Roi asset has only 65 Latin/number/punctuation mappings and no CJK. Preserve its global Latin/numeric restriction and use the existing `Sigrika Window Title` / LXGW Marker Gothic face for Chinese fallback. Do not claim that assigning the Latin family makes Chinese characters render in Lahai-Roi; verify the actual font cmap and computed fallback.
- `.handbook-modal > .handbook-puzzle-panel` owns `min-height: 0` and vertical scrolling in the final theme layer. The mobile board is taller than its panel; do not allow the board to paint beyond the paper window. The project's global reduced-motion contract may compute a 1ms important duration even when the local owner sets `transition: none`; assert numeric effective durations at most 1ms, rather than exact string `0s`.
- Native clipped buttons own real hit areas. Verify first/last slices and neighbors rather than relying on bounding-box clicks. Bright School important button states must be explicitly overridden by the final bounded strip owner, including hover/focus/active backgrounds and transforms. Keep costume/image transforms inside an art wrapper so direct button-child resets cannot override them.
- Every strip activation opens its matching detail directly: mouse click, touch tap, keyboard and programmatic `element.click()`. Do not render a separate detail button or make touch stop at a preview. `HomeOnboarding.activateTarget` uses `element.click()` on `[data-home-guide="sigrika-card"]` and requires the detail dialog for the next step.
- Hover preview works in both viewport orientations and clears on piece/board leave. Keyboard preview has separate focused identity, so leaving mouse hover restores a legitimate keyboard preview. Touch does not expand resting geometry. If a hybrid user touches an already-expanded target, keep its hit geometry through pointerdown/blur/pointerup and any implicit touch leave until the native click has landed; defer non-activating release cleanup to the next task. Cancel and scrolling clear contact state. Never shrink an expanded target between touch release and native click: lower-half taps would hit the following row.
- Before opening any detail, focus the stable primary strip, clear preview and mark a one-time restoration suppression. Modal close/Escape returns focus to that trigger without re-expanding a narrow row. Activation/touch also disarms hover: browser-generated enter/zero-movement events and touch-compatible mouse events must not re-expand the row after overlay removal. A new genuine mouse movement or keyboard interaction can preview again. The same restoration suppression applies to synthetic guide activation. Remove dead secondary-action CSS, and clean release timers on unmount.
- Details never select a sortie character. Mode selection is deferred by user request. The account's existing selected character remains authoritative. Keep effect cancellation controls separate from portrait activation and preserve page/orientation/roster reset behavior.
- Unowned Baconbits opens an anonymous `ModalDialog`; it must not expose name, skill, wardrobe or voice. Other existing detail content remains available under the existing ownership rules.

## Detail carrier

Keep the existing skill, CV, description, music and wardrobe controls. Portal the detail overlay to `.app-shell` outside the handbook's scroll clipping. The full-body figure owns a fixed display frame independent of copy height, with visible paper overflow and viewport containment. Only the copy scrolls. Mobile keeps an upper figure reservation and reachable wardrobe/close buttons. Keep wardrobe layers above the detail overlay. `ModalDialog` owns Escape, keyboard containment and focus restoration.

## Validation

Behavior tests cover input order, ownership-independent placement, constant larger desktop preview image dimensions and landmark alignment with intentional visual-size corrections, opposite mobile anchors, direct touch/programmatic activation, touch cancellation/hit stability, collapsed restoration, effect-button isolation and extra/missing roster handling. House tests cover portrait precedence, anonymous details, absence of unknown mascot art, no sortie selection, original detail actions and corrupted isolation. Browser-check 1440x1024, 1440x768, 390x844 and 360x640: ten strip hit targets, no horizontal overflow, first/last expansion and scroll ends, hover/focus/reduced-motion, background-free names, proportionate art, full-body details, wardrobe and focus return. Include real touch cancellation and a lower-half tap on a hovered narrow target. Run the real home-onboarding fixture on desktop and mobile when the programmatic activation path changes. Use `tests/e2e/fixtures/handbook-puzzle.html` to exercise production components without account writes; its URL is retained for compatibility.

Wrong: change the global 900x900 portrait catalog or clip the detail image inside the handbook.

Correct: use the local presentation adapter and portal the independent detail carrier.
