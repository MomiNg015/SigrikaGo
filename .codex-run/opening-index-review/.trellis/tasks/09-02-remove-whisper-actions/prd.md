# 移除密谈按钮并均分操作区

## 目标

移除当前尚未提供功能的“密谈”操作，并让同一操作区内保留的按钮在水平方向等宽、均匀分布。

## 范围

- 好友列表展开操作区：移除“密谈”，保留“详细信息”“对局申请”“解除好友”。
- 黑名单列表展开操作区：保留现有两个操作，并使用相同的等宽水平布局。
- 房间成员浮动操作区：移除“密谈”，保留“详细信息”“加好友/解除好友”“加入黑名单/从黑名单解除”。
- 保持所有既有操作逻辑、禁用条件和反馈不变。
- 同步相关测试与系统设计文档。

## 验收标准

- 上述两个玩家入口不再渲染“密谈”按钮。
- 好友操作区的三个按钮、黑名单操作区的两个按钮均在各自行内等宽分布。
- 房间成员浮动操作区的三个按钮在一行内等宽分布。
- 竖屏移动端不产生横向滚动，按钮仍满足既有触控高度约束。
- 相关组件测试、样式合同测试和系统设计文档生成通过。

## 不在范围内

- 开发私聊或密谈功能。
- 改动好友、黑名单或对局申请的服务端接口。
- 重做社交列表或房间成员弹层的视觉风格。

## 追加：统一道具使用对象排序

- 仓库中需要选择角色的道具，其角色顺序必须与部员手册一致。
- 两处界面共同以角色目录的 `sortOrder` / 共享展示顺序为准，不以用户资产字段的存储顺序为准。
- 只调整展示顺序，不改变拥有状态、道具适用条件、禁用状态或卡片视觉。
