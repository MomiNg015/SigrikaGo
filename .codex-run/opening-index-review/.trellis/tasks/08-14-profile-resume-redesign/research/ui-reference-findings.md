# 界面参考结论

## 外部案例

- Blue Archive 账号档案：借鉴“身份信息先于统计数据”的阅读顺序，以及角色形象和用户名牌共同构成唯一视觉锚点的做法。
- HoYoLAB Battle Chronicle：借鉴模式切换后的连续数据阅读、摘要与详细记录分层，不复制其品牌装饰。
- OP.GG 玩家摘要：借鉴紧凑、可扫读的战绩摘要和历史结果表达，不采用其产品色彩或桌面网页外壳。

## 项目内约束

- Bright School 的纸张底色、粉蓝薄荷强调色、标题字体、短硬影与名牌动画是既有品牌合同。
- 数据区应减少独立卡片数量，通过栅格、留白和横向分隔线建立层级。
- 桌面近全屏不是简单放大旧弹窗：身份页眉、页签、摘要/最近结果和角色成绩应形成清晰纵向节奏。
- 手机竖屏必须重排为单列；表格行转换为上下两层，但保留真实表头和单元格语义。

## 采用原则

- 只采用信息架构和密度经验。
- 不复制品牌图形、徽章、字体、配色或虚构内容。
- 生成探针只用于布局判断，不进入仓库资产。
