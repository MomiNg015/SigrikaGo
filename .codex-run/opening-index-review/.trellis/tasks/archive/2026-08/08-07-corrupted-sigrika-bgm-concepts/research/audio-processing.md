# 黑化 BGM 离线处理研究

## 仓库约束

* 当前曲目使用 OGG，既有资源同时存在 `single-loop` 与 `intro-loop` 两种播放方式。
* 黑化覆盖层目前主动暂停音乐；正式接入需要将黑化状态传入现有曲目解析，而不是在视觉组件里启动另一套独立播放器。
* 西格莉卡主题由约 25.9 秒 intro 与约 73.0 秒 loop 组成；主页默认主题为约 38.4 秒 single-loop。
* 移动端是竖屏主要运行环境，因此优先离线生成资源，避免持续 Web Audio DSP 带来的耗电、延迟和平台差异。

## 本机能力

* FFmpeg 版本：2026-05-25 git full build。
* `rubberband`：可分离控制 tempo 与 pitch，适合做降调但不必同比拖慢。
* `lowpass`、`aecho`、`aphaser`、`tremolo`、`vibrato`：可用于暗化空间、轻微漂移与不安感。
* `acrusher`、`asoftclip`：可用于受控的数据损坏与失真；应保持低混合比例，避免破坏旋律。
* `loudnorm`：可用于最终响度校准，但试听阶段宜先保留动态，再做峰值保护。

## 三档可行方案

### A. 轻度诡异

* 约降 1.5 个半音，tempo 约 0.97。
* 温和低通、短暗回声、极轻微音高漂移。
* 优点：旋律最清晰；缺点：黑化冲击可能不足。

### B. 叙事黑化（推荐）

* 约降 3 个半音，tempo 约 0.92–0.94。
* 暗色低通、受控长尾空间、轻微 wow/flutter 与少量数据失真层。
* 优点：仍能认出原曲，同时明显感觉“熟悉内容被污染”；缺点：需要谨慎处理循环尾音。

### C. 重度故障

* 约降 5 个半音，tempo 约 0.86–0.89。
* 更强相位漂移、bit-crush、断裂式门控与低频压迫。
* 优点：黑化感最强；缺点：长期循环容易疲劳，可能掩盖棋盘操作反馈音。

## 循环处理策略

* 试听版可从 loop 的有代表性片段生成，无需先解决完整接缝。
* 正式 loop 不应直接对单段加长尾混响后导出，否则尾音会在循环点被截断。
* 推荐把 loop 重复三次后整体处理，再截取中间一次；必要时对首尾做短等功率交叉淡化，以保留处理器的连续状态。
* intro 与 loop 使用相同的核心音高、速度和音色参数，空间尾音需在 intro→loop 交界进行实际试听验证。

## 建议

第一轮按用户选择同时制作两组：以 `sigrika_loop.ogg` 为西格莉卡组母体、以 `main_bgm.ogg` 为主页组母体，各生成三档约 30 秒试听。用户选定方向后，再分别制作正式 intro/loop，并决定黑化主页与决战的最终分配。
