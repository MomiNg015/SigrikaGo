# 修复新手剧情播放节奏与立绘切换

## Goal

修正新手剧情中一处错误的用户台词节点，并让剧情文本、NPC 对弈气泡和角色立绘切换保持可读、及时、稳定；普通剧情窗口支持点击窗口内任意区域立即完成当前句的打字动画。

## Requirements

- 将 `（目瞪口呆地看着西格莉卡把自己地脸颊拍扁了）` 从独立剧情文本改为用户固定单选回复，选择后继续原后续节点并写入剧情记录。
- 有完整语义、需要阅读的 NPC 台词使用手动继续；仅短感叹、即时动作及无需阅读的过渡保留自动推进。
- NPC 对弈气泡切换到新节点时立即替换说话人、姓名、配色、文本和立绘，不允许为了旧气泡退场动画而继续显示上一角色。
- 普通剧情播放器预加载当前脚本使用的立绘；同角色连续台词不反复卸载图片，不同角色切换时使用角色与资源地址作为身份。
- 点击普通剧情窗口内部任意区域时，如果当前句仍在打字，则立即显示完整文本；原有继续、选项、关闭、快进和跳过确认行为保持不变。
- 草稿、发布版、本地开发数据库和部署默认快照保持一致。
- 按项目要求同步 `docs/system-design.md`，并运行 `npm run docs:system-design`。

## Acceptance Criteria

- [x] 指定“目瞪口呆”文本不再作为 `story` 文本节点出现，而是作为单选按钮出现。
- [x] 完整 NPC 句子不会在打字完成后 0.35–0.5 秒内自动消失。
- [x] 西格莉卡与达妮娅连续切换时，气泡内容和立绘在同一次节点更新中同步替换。
- [x] 同一角色连续剧情节点不会因节点 ID 变化重复创建立绘元素。
- [x] 点击立绘区、文本区、窗口留白或操作区均可立即完成打字；点击窗口外仍进入跳过确认。
- [x] 桌面与竖屏移动端沿用同一交互逻辑，无新增移动端布局回归。
- [x] 针对性测试和 `npm run check` 全部通过。

## Definition of Done

- 代码、剧情数据、数据库、测试和系统设计文档同步。
- 不新增节点类型、数据库字段或依赖。
- 不启动额外后台开发服务；视觉验收交由用户完成。

## Technical Approach

- 数据层：把目标文本作为单选项挂到前一条西格莉卡 `story` 节点并删除原文本节点，避免普通剧情误入对弈运行时；将需要阅读的自动 NPC 节点改成互斥的手动推进字段。
- 普通剧情：把完成打字的点击处理提升到主剧情面板；立绘 key 从“节点+角色+URL”收敛为“角色+URL”，并在脚本变化时预加载去重后的角色立绘。
- 对弈剧情：移除旧 NPC 气泡延迟替换分支，新节点立即覆盖气泡；保留首次出现、关闭和 reduced-motion 兼容。
- 回归：快照锁定目标回复与节奏字段，组件测试锁定全窗口点击、稳定立绘身份、预加载和即时 NPC 角色替换。

## Decision (ADR-lite)

**Context**：旧实现把 NPC 气泡退场动画优先于内容正确性，并用节点 ID 强制重建普通剧情立绘；部分自动推进节点只给完成文本极短停留时间。

**Decision**：内容与角色同步优先。新 NPC 节点立即替换旧气泡；同角色立绘跨节点复用；可读台词改为手动确认，自动推进只服务短反应和动作。

**Consequences**：角色切换不再保留旧气泡完整退场过程，但不会出现“新台词配旧角色”；剧情节奏更依赖玩家确认，阅读不会被计时截断。

## Out of Scope

- 不重做剧情窗口视觉样式或棋盘布局。
- 不改变普通对局聊天、角色资源格式或后台编辑器结构。
- 不增加全局“打字速度”设置。
