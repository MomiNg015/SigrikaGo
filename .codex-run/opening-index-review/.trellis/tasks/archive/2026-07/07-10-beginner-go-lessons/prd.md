# 零基础完整第一课：从气到星炬围棋

## Goal

把 `onboarding.default` 的“其实我完全不会下围棋...”分支重构为一条约 12–15 分钟、四章连续完成的第一课。在不新增节点类型或教学运行时的前提下，让零基础玩家建立从普通围棋规则到星炬围棋资源取舍的完整认知链。

## Requirements

* 保留现有长篇规则讲解、达妮娅打断与另外两个水平分支，只整体替换 `node-4-4-2` 后的 `beginner-*` 支线并接回 `node-4-5`。
* 第一章覆盖气、打吃、逃跑、连接棋块共享气、一次提取两子、禁入点例外、劫和劫材。
* 第二章覆盖直接连接、分断、真假断点、真眼、假眼、两眼活棋与无处逃的死棋。
* 第三章覆盖金角银边草肚皮、布局、中盘、官子、申请数目、死子/中立点确认与中国数子规则。
* 第四章使用西格莉卡的星辉符文真实演示除子与超频，解释提子、除子、超频、技能次数、标准模式与星烁模式的差异，并要求玩家判断技能的全局价值。
* 只有动作记忆环节要求落子；概念判断使用静态局面和 `player-choice`。答错由达妮娅提示后回到原题，不设置失败结局。
* NPC 讲解手动继续；局面切换、正确落子、NPC 技能和 NPC 落子自动推进。
* 复用现有 `story`、`board-setup`、`npc-dialogue`、`player-move`、`npc-move`、`player-choice`、`npc-skill` 和 `counting-start`，不新增节点类型、API、数据表或数子运行时。
* 通过 `server/storyScripts.js` 的发布服务同步本地草稿和已发布数据，使用真实管理员身份留下审计记录；随后运行 `npm run admin:snapshot` 持久化默认部署数据。
* 同步 `docs/system-design.md` 与生成的 `docs/system-design.html`。

## Board Fixtures

### A. 气、逃跑与提子

* 黑棋：`3,3`、`8,8`、`10,8`、`9,7`、`8,9`、`10,9`。
* 白棋：`2,3`、`3,2`、`4,3`、`9,8`、`9,9`。
* 黑棋先在 `3,4` 延伸救棋，再在 `9,10` 一次提走两颗相连白棋。

### B. 禁入点与劫

* 左侧白棋 `1,2`、`3,2`、`2,1`、`2,3` 围住 `2,2`；黑棋直接落入为禁自杀。
* 右侧白棋 `6,6`、`5,7`、`7,7`、`6,8`，黑棋 `5,6`、`7,6`、`6,5`；黑棋在 `6,7` 提劫后产生 `ko = "6,6"`。

### C. 连接与分断

* 黑棋 `3,3`、`5,3`、`8,8`、`9,9`，白棋 `8,9`、`9,8`。
* 黑棋在 `4,3` 直接连接左侧两子；右侧斜向黑棋仍被白棋切断。

### D. 真眼、假眼与两眼活棋

* 左侧同一块黑棋形成两个分开的真眼，眼位为 `2,2`、`4,2`。
* 右侧被白棋包围的黑棋只有 `8,2` 一个真眼；`11,1` 的上方斜角由白棋控制，是假眼。
* 该局面只用于静态判断，不依赖规则引擎自动计算死活。

### E. 布局

* 13 路空棋盘；黑 `3,3`、白 `9,9`、黑 `9,3` 依次落子。

### F. 中盘

* 复用现有 `story-16.boardSetup` 的 32 子复杂中盘快照，只做形势判断题。

### G. 官子与终局

* 初始黑棋九颗：`2,1`、`3,1`、`1,2`、`4,2`、`1,3`、`4,3`、`2,4`、`5,6`、`6,6`；在 `3,4` 收官后为十子四空。
* 白棋十颗：`8,7`、`9,7`、`10,7`、`7,8`、`11,8`、`7,9`、`11,9`、`8,10`、`9,10`、`10,10`，围六空。
* 真实结算必须为 `白胜3又3/4子`。

### H. 西格莉卡技能

* 黑棋 `6,5`、`6,6`；白棋 `6,4`、`5,5`、`7,5`、`5,6`、`7,6`。
* 白方西格莉卡在 `6,7` 使用星辉符文，技能清理两颗黑棋，产生 `skillRemovals.white = 2`、`skillCosts.white = 3`；技能不消耗落子，白棋随后仍在 `9,9` 正常落子。

## Acceptance Criteria

* [x] 草稿与已发布节点完全相同，节点 ID 唯一，所有跳转目标存在，所有错误选项都能回到原题。
* [x] `node-3` 的另外两个水平分支仍分别进入 `story-46` 和 `story-15`。
* [x] 逃跑、双子提取、禁入点和劫状态均由真实教程规则验证。
* [x] 连接目标落子成功；连接/分断和双眼/假眼答案与静态图形一致。
* [x] 布局三手、复用的中盘快照、官子目标和数目按钮按顺序可达。
* [x] 终局为黑十子四空、白十子六空，真实结果为 `白胜3又3/4子`。
* [x] 星辉符文真实产生白方除子 2、超频 3，且技能后白方仍可在 `9,9` 落子。
* [x] 对话准确说明普通提子不重复计分、除子每枚 `+1目`、超频每点 `-2目`、星烁黑贴白二又四分之三子，以及技能应按全局收益判断。
* [x] 相关定向测试、`npm run docs:system-design` 和 `npm run check` 通过。

## Definition of Done

* 本地 `onboarding.default` 经正式服务发布并留下审计记录。
* `server/adminDefaultSnapshot.js` 包含完整四章草稿/发布节点。
* `server/adminDefaultSnapshot.test.js` 覆盖节点图、代表局面、真实计分与技能计数。
* `docs/system-design.md` 与 `docs/system-design.html` 同步。
* 工作区中的无关 CSS、主题和图片提示词改动未被覆盖或纳入本任务。

## Out of Scope

* 征子、枷吃、倒扑、复杂死活题、定式变化和详细官子计算。
* 新增课程进度表、中途退出/续学、完整标死子或中立点教学运行时。
* 修改剧情播放器、后台编辑器、棋盘 UI 或其它水平分支。

## Follow-up: Existing Branch Pacing

在不修改任何对白、选项文案、棋盘、落点、技能、节点类型或跳转目标的前提下，统一调整“略懂一些”和“我超强的哦!”两条现有分支进入的共享剧情对弈节奏：

* `story-16` 与 `story-51` 的棋盘加载完成后只保留约 1 秒观察时间，不再额外等待 2–4 秒。
* NPC 落子和技能在对白出现后短暂停顿再执行；动作结算后保留约 0.3–0.8 秒观察结果，不叠加 2–3 秒空等。
* 连续的短反应对白自动推进，但在打字结束后至少保留 1–1.2 秒阅读时间；完整规则说明继续由玩家手动确认。
* `story-61`、`story-62` 从手动/自动同时开启修正为纯手动，避免长说明自行跳过。
* 连续两层玩家选项使用 0.2 秒左右的选择后过渡，避免遮罩与按钮瞬间替换。
* 通过正式剧情发布服务同步草稿和发布版，重新导出默认快照；回归测试锁定节奏字段并验证非节奏内容未在转换中变化。
