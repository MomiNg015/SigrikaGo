## Anti-Patterns Verdict

当前版本有中度 AI 模板感。主要信号是 `RECENT FORM`、`CHARACTER RECORDS` 这类小号大写英文眉题，加上“我的学院档案/学院成员档案”的重复元标签，以及横向铺满的身份 hero、四项指标和表格组合。它不像 Bright School 里经过人工编辑的档案页，更像把通用 dashboard 结构换成了校园色板。

自动 detector 对三个 JSX 文件返回零问题，这是明显的假阴性：它没有识别 CSS 级联冲突、失败后的数据错配和隐藏在嵌套弹窗后的错误消息。

## Overall Impression

信息结构方向是对的，但落地没有形成一个可信的“学院档案”。最大机会不是继续加装饰，而是收窄阅读宽度、建立明确的身份/战绩主次，并清除旧 CSS owner 对新 DOM 的干扰。

## What's Working

- “星炬、标准、五子棋”的顺序和自有/社交操作区分已经正确落地。
- 角色战绩改为语义表格，桌面列头与移动端两层行的方向合理。
- ModalDialog 统一了焦点、Escape 和嵌套弹窗边界；重复模式请求也已被阻止。

## Priority Issues

### [P1] 自己的履历在模式加载失败后显示错误模式数据

`ResumeModal` 在点击新模式时立即更新 `mode`，但请求失败只写入 `profileError`，没有恢复旧模式；`lastProfile` 仍是旧模式。结果是新页签高亮、旧战绩继续显示，而且点击当前页签无法重试。

### [P1] 移动端页眉 CSS 与当前 DOM 结构脱节

旧规则仍期待 `resume-title-actions` 和页眉直属的 `resume-close-button`，实际关闭按钮已嵌套在 `resume-header-actions`。两行网格因此留下空的 close/links 区域，并把成就、金币和关闭压进不足一半宽度。

### [P1] 手机端存在双滚动和立绘缩小冲突

他人资料外层 modal 与内部 `profile-resume-view` 同时 `overflow: auto`，形成双滚动；旧 `phone.css` 又把 hero 图片强制到 78x70，而最终 wrapper 是 132x112，导致立绘在空框里显得过小。

### [P1] 举报错误恢复不可见，危险语义也不足

举报失败写入父档案的状态区，但举报子弹窗仍覆盖在上方，用户看不到失败原因。主举报按钮使用普通粉色纸片，与点赞、加好友同等视觉权重，没有形成独立危险语义。

### [P1] 视觉层级过平且过宽

桌面固定放大到 1440px，但身份、摘要和角色表都沿全宽拉伸，首列和数值间距过大，空白不是留白而是松散。英文眉题和重复档案标签进一步增加模板感；自己的履历与他人资料页眉也没有使用同一视觉 owner。

### [P1] 存在 WCAG AA 文本对比度缺口

空角色战绩和“关系操作”使用约 62% ink 与白色混合，实算对比度约 4.05:1，低于普通小字号文本所需的 4.5:1。

### [P2] 页签只有角色，没有完整 tab 交互

页签缺少 `aria-controls`、对应 `tabpanel` 和左右方向键导航。鼠标能用，键盘用户只能逐个 Tab 穿过三个按钮。

### [P2] 重复 CSS owner 并未真正清干净

生产 DOM 已不再使用 `profile-resume-stats`、`profile-character-row`、`resume-title-actions` 等类，但它们仍分布在多份 CSS 中；其中旧 phone owner 已经实际覆盖了新 hero 图片尺寸。

### [P2] 其他状态与性能缺口

他人资料模式切换没有明确加载文案；黑名单缺少确认或撤销；角色表一次加载所有角色立绘，没有 lazy loading；用户在请求期间快速切换到另一份资料时，旧请求仍可能覆盖新用户状态。

## Persona Red Flags

- **Sam（键盘/低视力用户）**：页签不支持方向键，两个 12–16px 辅助文本低于 AA 对比度；举报失败没有在当前对话框内被宣告。
- **Riley（压力测试用户）**：模式接口失败会看到页签与数据不一致；资料对象在请求中途切换时缺少 stale-response 防护。
- **Casey（单手手机用户）**：页眉动作被压缩到半列，外层和内层都能滚动，立绘又被旧规则缩小，首屏身份区域既占高度又缺乏视觉收益。

## Minor Observations

- `aria-label="点赞 5次"` 与可见文案“点赞 5”表达不完全一致。
- 绝对定位的桌面状态条会覆盖摘要区，而不是稳定占位。
- 空状态只说明“暂无”，没有告诉用户如何产生战绩或如何重试。

## Questions to Consider

- 近全屏是否真的需要 1440px 内容宽度，还是窗口近全屏、正文控制在约 1080–1180px 更像档案？
- Bright School 的个性应该来自名牌、立绘和纸张结构，为什么还需要通用 dashboard 的英文眉题？
- 发生模式失败时，界面应该继续停留在旧页签，还是显示新页签的独立错误占位？两者都比当前“新页签配旧数据”可信。
